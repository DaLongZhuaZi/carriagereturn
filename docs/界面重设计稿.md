## 1. 设计语言：深底、暖纸、哑光金属

一句话：**屏幕就是一台机器，不是三个拼起来的盒子。**

- 画面只有一位主角：纸。背景是深暖炭色，纸面是全屏最亮的部分，视线先落纸，再落键盘，最后才是顶栏。
- 克制：每屏只用一套色彩（机身色 + 纸色 + 墨色），不引入彩色装饰；状态只用文字说明，不靠颜色单独表意。
- 质感：机身哑光金属、纸面暖米白带纤维纹理、键帽照片实拍；阴影只用一层短实阴影（纸压在字车上、按键高亮时），不做常驻装饰阴影。
- 网格：8vp 基线；左右边距 20vp；圆角收敛为三档——纸 12vp、卡片 8vp、键帽 10vp；字号只用四档——标题 20vp、纸面正文 17vp、界面正文 15vp、说明 12vp。
- 色板（风格板已锁定，直接用，不许另取色）：
  - 背景深炭 `#171310`（上下渐变至 `#241c16`，不许纯黑）
  - 纸暖米白 `#eee4ce`，纸高光 `#e4d8c5`
  - 机身主 `#312b24`，机身中调 `#574d43`，机身最深 `#15120e`
  - 键帽奶油 `#dbccb3`，金属高光 `#beb4a8`
  - 墨色三档：黑 `#1a1a1a`、蓝 `#24407c`、红 `#a33327`
  - 其余三台机器各用自家锁定色（1930s `#3d3732` / 1950s `#c8b9a6` / 1960s `#928b82`），不许串色。
- 字体分工（界面字体一律系统默认，不打包）：
  - 纸面英文：Courier Prime（默认）、Special Elite（做旧档）
  - 纸面中文：Noto Serif SC（默认宋体）、LXGW WenKai（楷体档）
  - 标题页落款与便签：手写体档（见 §7 字体落位表）
  - 界面文案：系统默认字体，不许用打字机体做界面标题（界面标题用打字机体是上一版显乱的原因之一）

## 2. 主屏：打字机（唯一主角是纸，机器、纸、键盘纵向连成一台）

参考尺寸 390×844（竖屏锁定）。其余尺寸不许用统一缩放系数硬套，见 §2.5 自适应几何（2026-11-04 视频定稿，取代“按比例缩放”一句）。

### 2.1 纵向构成（自上而下，不许打乱顺序、不许加段）

| 区 | 高度 | 内容与钉死点 |
|---|---|---|
| 顶栏 | 56vp | 左：文档库图标（线形文件夹，24vp）；中：文档标题（系统字体 15vp，居中，默认“未命名”）；右：汉堡菜单图标（24vp）。顶栏底色透明，不加分割线。 |
| 纸面区 | 弹性（390×844 下 461vp，不低于 220vp） | 纸面区是纸张活动的区域，不是纸本身；纸本身按 §2.2 生长规则从 96vp 起长，下缘锚定在字车条。纸纹见 §2.2；打击行永远停在纸片底部固定位置，不随行数下移。 |
| 字车条 | 55vp | 照片字车条（各机 `assets/images/animation/<机型>/carriage-strip.png`，满宽；带：1920s 45%–59%、1930s 51%–65%、1950s 47%–61%、1960s 44%–58%，均已逐条验图）；图层顺序：字车条在上、纸面在下，**纸面从字车条后方（下方图层）向上穿出，纸的下缘被字车条压住 8vp**（纸面底部 8vp 被字车条遮住）——纸和机器是连着的，不是两个分离的盒子。原稿“纸的上缘被压”一句作废：按本表顺序纸面在字车条上方，被压的只能是纸的下缘。字车导件（2026-11-04 用户定，取代“中央固定导件”）：照片里的中央金属件只是机器部件；打击点由代码在字车条上叠画的一根竖向导件指示，导件 x 随光标走——x = 纸面文本区左缘（左右边距 28vp）+ 当前行已落字总宽度（按当前字体实测字宽累加，英文等宽、中文全角），初始在左缘；每落一字导件向右移一字宽（弹簧动画，与杆到位同帧）；换行时导件回到左缘。字车条动效（2026-11-04 两轮后定稿，取代“小行程平移”）：上一版最大行程仅约 64vp、照片宽 = 舞台宽、左移后右侧留深底空位，用户 14:28 MatePad 截图实证未达成效果——截图里纸面已满行 a、字车条左右旋钮仍与纸面左右缘对齐、中央金属件仍在中部，即偏移量为 0，不是“动了但看不出来”，是 MatePad 上的包未含 48c4c9b、或偏移被重置/未生效（见 §7.4 诊断条）。本版改用**平移宽图**：字车条照片宽 = 舞台宽 + 最大行程（不是舞台宽），高 = 照片宽 / 7.14，容器宽 = 舞台宽、clip true；行首照片 x = 0（左旋钮可见、右旋钮在舞台右缘之外被裁），每落一字照片向左平移一格，行末照片 x = −最大行程（左旋钮在左缘之外被裁、右旋钮移到舞台内），全程字车条始终填满舞台宽、右侧永不留空位；最大行程 = min(舞台宽 × 0.35, 180vp)（手机 390vp 宽时约 136vp、每字约 3–4vp；MatePad 舞台约 473vp 时约 165vp、每字约 4–5vp；再大则字车条高增幅过大），每字行程 = 最大行程 / 每行字数，每步 70ms 弹簧快步；空格前进、删除/覆盖删除退格（不超 0）；换行与行满自动换行时照片一次性向右跳回 0（250ms 弹簧，与拨杆摆动 + 叮声 + 导件回左缘同步），偏移量必须钳制在 [−最大行程, 0]，超出行程必须触发换行、不许让照片继续左移出空白。满行 1:1 平移（约 300vp）仍不做；导件右移（文档坐标）与字车左移（机器坐标）方向相反仍是本批 UI 折中（见 §7.3 第 7 步后注记），物理 1:1（打击点固定、纸左移）仍是另一套重写、不在本批混用。字车条容器背景仍为与主屏相同的深底渐变，仅作照片被裁后的底色，不许出现照片宽 = 舞台宽的旧实现。 |
| 字体条 | 38vp | 当前字体名，用该字体本身渲染，上下细线分隔；换字体时字体条与键帽叠字同步换。 |
| 键盘 | 238vp（照片键区 186vp + 功能行 52vp） | 见 §2.3；键盘顶缘与字体条底缘之间不留空隙，键盘就是机器的底座。 |
| 页码轨 | 贴纸面右缘 | 半透明深色小 pill：上箭头、当前页码、加页号（`+`）；不占顶栏，不遮正文（纸面右留 44vp 安全区）。 |

纵向合计：56 + 4（纸面区上边距）+ 纸面 + 55（字车条，-8vp 与纸面重叠）+ 38 + 238 = 844（纸面取剩余，390×844 下 461vp）。

### 2.2 纸面（四种纸，纹理与格线全部钉死）

- 纸纹文件：信纸 `assets/images/papers/paper-letter.jpg`（默认）、稿纸 `paper-manuscript.jpg`、明信片 `paper-postcard.jpg`、便签 `paper-memo.jpg`。程序化 `*-procedural.jpg` 与 CC0 `cc0-paper001-color.jpg` 仍为备用，不许作主用（用户已否决程序化噪点图）。
- 边距：左右 28vp、顶 24vp、底 20vp；纸面圆角 12vp；纸面阴影：下缘被字车条压住处一层短实阴影（纸压在字车上的厚度感）。左右 28vp 是硬指标：指文本区内边距，用 padding 属性直接实现，不许用 onAreaChange 量纸片真实宽度反算 padding（28vp 是绝对 vp 值，不随纸宽变化而变；量宽反算只会引入异步首帧错位与布局回路，属于改 PaperStage 布局方式，不在本批做）。
- 纸张生长与走纸（2026-11-04 用户定，取代固定满幅纸面；截图里纸面固定满幅、引导文案在纸面区顶部是旧实现，必须按本条改）：
  - 纸片下缘锚定：纸片下缘固定在字车条上缘下方 8vp 处（被字车条压住 8vp），换行与走纸时下缘不动；纸片向上生长或上移，纸面区上部空出的部分是深底渐变背景（`#171310→#241c16`），不是纸。
  - 初始高度：新纸初始高 96vp（顶边距 24vp + 页眉区约 20vp + 1 行 28/30vp + 底边距 20vp，取整），即新纸只占纸面区下部靠近键盘的一小段，页眉双细线与页码在纸片顶部（初始时页眉位置也低，随纸片生长一起上移）；引导文案随第一行走，位置在纸片底部，不在纸面区顶部。
  - 生长：每换行（换行键或行满自动换行），纸片高增加一行高（英文 28vp、中文 30vp，按当前行高），顶缘向上推；纸片内已落字随纸片一起上移，打击行始终停在纸片底部固定位置（底边距 20vp 上方），与字车条中央竖向导件对齐。
  - 满幅后走纸：纸片高达到纸面区满高 461vp 后停止生长；此后每换行纸片高不变，内容整体弹簧上移一行（creep，§7.3 第 5 步），打击行仍在底部固定位置，顶部最早的行被纸面区上缘裁掉（纸片不缩短）。
  - 换页：页码轨加页时新纸回到初始 96vp，页码 +1，旧页存档不丢；换纸/换字体时纸片高按新行高重算，已落字保留旧呈现、新落字用新呈现；换机不改纸片高（纸是文档的，不是机器的）。
  - 动画：生长与走纸均为弹簧动画，不许跳变；换行时拨杆摆动 + 叮声 + 纸片生长/走纸 + 字车回位四者同步（§7.3 第 7 步）。
- 格线与页眉（全部代码画，不许 baked 进图）：
  - 信纸：无横线；页眉双细线 + 右上角页码（系统字体 12vp，灰色）。
  - 稿纸：红格 + 横线 + 页眉（红格线 `#c8a49a` 细线，横线间距 28vp）。
  - 明信片：图案区在纸面上半部（图片自带图案），下半部留白写字。
  - 便签：无格线，纸面略小（左右边距 36vp），营造便签感。
- 落字：英文 Courier Prime 17vp、行高 28vp；中文 Noto Serif SC 17vp、行高 30vp；墨色随色带（黑/蓝/红）；段首不空格，换行即新行。
- 光标：纸面不显示光标（逻辑光标仍在模型里跟随 offset）；打击点由字车条上叠画的竖向导件指示，导件 x 随光标走（见 §2.1 字车条行），不是固定中央；预编辑串浅色 + 下划线，不发音不落墨。
- 引导文案（定稿，直接用，不许再写占位句）：
  - 首次使用引导（只显示一次，纸面上方小字，系统字体 13vp，灰色）：“这是一台打字机。敲下去，字就落在纸上。”
  - 常驻引导（每张新纸一行，输入后消失）：“开始打字吧。”

### 2.3 键盘（照片键区 + 代码功能行，不许用系统键盘皮肤，不许代码画键帽）

- 照片键区（一台一母版，2026-11-04 定）：各机一张母版 `assets/images/machines/<机型>-keyarea.jpg`（2048×2048，正俯视整台键区入画，不断面）；代码按比例裁切，不许再按比例分别生成（实测：指定来源图后模型忽略比例措辞恒出正方形，原 12 张分比例计划作废；“spans the full width”类措辞会把键推到边缘致截断，安全措辞是四边安全区 + `no key cropped`）。手机带 `*-keyband-phone.jpg`（2048×975，2.1:1，390vp 宽时高 186vp，满宽铺底）、折叠带 `*-keyband-fold.jpg`（2048×853，2.4:1）；**1930s 折叠带复用手机带**（5 排键区高 931px，2.4 带 853px 容纳不下，裁到 2.4 必切顶排或空格条）。旧 `*-keyboard.jpg` 裁切带（v4 的 2400×931 键带）作废，主屏不再用它。键帽字母全部空白原图，字母由代码按当前字体叠在帽心（字号约 14vp，颜色按帽色走：1920s 奶油帽深色 `#312b24`、1930s 深色帽浅色 `#dbccb3`、1950s 奶油帽深色 `#312b24`、1960s 灰帽深色 `#312b24`）；换字体时键帽叠字同步换字体。
- 整机键区（2026-11-03 用户定）：照片的 4 行 + 空格条全按真机排布用上，不许只取字母三行；顶行是数字行（数字常驻，`123` 切换键取消）；行内多出的帽按暂定排布标功能，用户一句话可改任一帽。暂定排布（均已写入各机 keymap，`extra` 表示留空不叠字）：1920s（43 帽：顶行 1–0、-；QWERTY 行 10 帽；ASDF 行 A–;'；底行左 ⇧ + ZXCVBNM + ,、.、/，右大帽暂定 `/`）；1930s（58 帽：顶行 1–0、-；QWERTY 行 + 1 留空；ASDF 行左 ⇧ + A–;'；底行 Z–/ + 1 留空；第 5 排 11 帽全部留空，待用户定用途；空格条两侧大圆帽为 ⇧）；1950s（49 帽：顶行 1–0、-、=；QWERTY 行左留空 + Q–P + `[`、`]`；ASDF 行左 ⇧ + A–;'；底行左 ⇧ + Z–/ + 1 留空）；1960s（52 帽：顶行 1–0、-、=、? + 宽帽留空；QWERTY 行左留空 + Q–P + 1 留空、宽右 Backspace；ASDF 行左 ⇧ + A–;'、宽右 Return；底行左右 ⇧ + Z–/）。
- 键位图：每台一张键位坐标表（母版像素坐标 + 帽功能 + 空格条 bbox，见 `assets/images/machines/<机型>-keymap.json`）；1920s 43 帽（11/10/11/11）、1930s 58 帽（11/11/12/11/11 + 2 ⇧）、1950s 49 帽（12/13/12/12）、1960s 52 帽（14/13/13/12）；触摸命中按键位坐标表判定，不许套统一网格（行距与帽距逐行不等，1930s/1950s 有透视与错行）。
- 功能行（代码画金属键质感，照片键区下方，52vp 高）：深色金属渐变 + 顶部高光线，换行键为浅色金属渐变；中/EN（中英切换）、删除（双模式，见 §7.3 第 8 步）、换行（深色“换行”二字）；不许再加 Shift/123/空格（已在照片键区里；1960s 宽帽 Shift/Backspace/Return 与功能行删除/换行功能重复时，照片帽与功能行均可用）。
- 按键反馈（同一 Down 回调内，顺序钉死）：帽上高亮（照片帽按不下去，不做缩放）→ 播音 → 震动；缺任何一环按 bug 计；滑入只发声不上屏（防误落字，沿用阶段 1 结论）。
- 换机：照片键区 + 键位图 + 音效包同步换（200ms 淡入淡出，不闪白、不丢文档位置）；换字体只换叠字字体，不换照片。

### 2.4 换装过渡与三态

- 换机/换纸/换色带/换字体：纸面与键盘 200ms 淡入淡出，不许闪白、不许整页重建、不许丢光标与文档位置；换机同时换音效包与照片键区（含键位图），换字体只换叠字字体。
- 折叠屏三态（沿用既定规则，布局参数只换不重建）：
  - 半开桌台：上半屏纸、下半屏键盘，铰链即分界，任何内容不跨铰链。
  - 展开：宽纸 + 全尺寸键盘，文档库与收藏走双栏。
  - 外屏：快速便签 + 文档列表单栏，不做完整打字机布局。

### 2.5 自适应几何（2026-11-04 视频定稿：不许写死、不许按设备逐个调，下列规则在所有设备上同一套代码生效）

视频证据（01:57 录屏，1600×2560 设备）：顶栏标题随打字变成“1234”；键盘下排字母向下漂移、越往下越偏，底排与空格条被裁掉；纸片在纸面区里显得极小、上方大片深底空着；字杆层偶尔以一根竖条出现在屏幕左缘。根因不是某台设备特殊，是现实现在同时用了两套互相打架的尺寸：`Index` 用 `scale = min(w/390, h/844)` 缩放固定高度（顶栏/字车/字体/键区/功能行），而纸片高、行高、字号、边距不缩放；照片组件同时被给定固定高和图片宽高比（`height = 186vp` + `ImageFit.Fill` 满宽满高），图片与叠字又各用一套缩放，误差随行号累积、底排先被裁。这就是“写死 390×844”必然的结果，换一台设备只会换一套错位，逐台调是死路。

- **杀掉 uiScale（铁律）**：删除 `scale = min(w/390, h/844)` 及一切 `高度/字号/边距 × scale`。稿子里 56、55、38、186、52、461、96、28 这些数字只是 390 宽时的参考值，不是代码常量；代码里只许出现两类数：① 与图片无关的固定 vp（顶栏 56、字体条 38、功能行 52、字号 17、行高 28/30、边距 28/24/20），② 由图片宽高比算出来的数（见下）。字体、行高、边距在任何设备上都是绝对 vp，绝不随屏幕缩放——字在平板上变大 1.5 倍不是“适配”，是错。
- **舞台定宽、高度全屏（唯一全局规则，§2.6 平板逻辑下修订）**：§2.5 初版的舞台宽 `min(屏幕宽, 屏幕高 × 390/844)` 只解决了“不拉伸、不错位”，但在平板上它等同于把手机版居中缩小（见 §2.6 截图实证：内容宽只占窗口约 74%、上方大片深底、功能行贴底被裁）。宽高比封顶在平板上作废，改按 §2.6 的排版上限封顶（776vp，见下），其余 §2.5 规则（比例叠字、宽高比派生高度、标题、字杆比例）在各尺寸分级内全部保留。**舞台必须是容器**：顶栏、纸面区、字车条、字体条、键区、功能行、字杆层全部放在宽 = stageWidth、水平居中的舞台容器里，不许直接放在宽 100% 的屏幕列里——否则宽屏上键区宽、行宽、导件 x 全按屏幕宽算，舞台定宽等于没定（第 3/4 步实测：`screenWidthVp` 直接传给键区与行宽，就是这个漏）。
- **照片高度只由宽高比派生，绝不同时给定固定高**：键区高 = stageWidth / 带宽高比（手机带 2048/975 = 2.101，折叠带 2048/853 = 2.401，1930s 折叠带复用手机带；390 宽时 390/2.101 = 186vp，这就是 186 的来源，不是常量）；字车条高 = stageWidth / 7.14（2048/287，390 宽时 55vp，同理）。实现用 `aspectRatio` 或对舞台容器量一次宽后算高，不许 `width 100% + height 固定值 + Fill` 三件套同时出现——固定高与宽高比打架时，ArkUI 必然裁掉或拉伸其中一边，视频里底排被裁就是这个。纸面区高 = 舞台高 −（顶栏 + 字车条高 + 字体条 + 键区高 + 功能行），是算出来的，不是 461vp 固定值（461 只是 390×844 时的算出值）。
- **叠字与触摸只用比例，绝不用母版像素、绝不许单缩放**：keymap 在加载时一次换算成比例：`xRatio = (母版 x − 带 x0) / 带宽`，`yRatio = (母版 y − 带 y0) / 带高`（带 x0/y0/宽/高见各机 keymap 的 band 字段；1920s 手机带 y0 = 704、高 = 975，行 y 836/1020/1178/1352 对应 yRatio 0.135/0.324/0.486/0.665）。叠字 X = xRatio × stageWidth，Y = yRatio × 键区高；触摸同理：触点比例 = 触点坐标 / (stageWidth, 键区高)，与 keymap 比例 bbox 比对，容差用比例（约 0.02）不是 vp。**第 3/4 步实测纠正（`KeymapModel.parse` 现状是错的）**：现在代码用单一 `scale = widthVp / 带宽` 同时算 cx 与 cy（`cy = (行 y − 带 y0) × scale`），这只有在键区高恰好 = 舞台宽 × 带高/带宽时才对；宽屏上键区高是 `186 × min(宽比, 高比)`，高比先到顶，cy 就被系统性地放大——宽高比 0.625 的设备上放大倍数约 1.35，行 y 越大偏得越多，视频里下排漂移、底排被裁就是这一个公式。修法：`cx = xRatio × widthVp`，`cy = yRatio × heightVp`，且 `heightVp` 必须按上一条由宽高比派生（此时两式等价，单缩放才成立）；若高度暂时对不上，比例式仍能让叠字对上 Fill 拉伸后的照片，单缩放式则不能。另：`dumpLayout` 只能证明叠字与命中用了同一套错误坐标，绝不能证明叠字对上了照片——对照片只能用真机截图核对（见 §7.4），第 3/4 步“dumpLayout 证实落帽心”一句作废。
- **纹理与照片分开处理**：纸纹是纯纹理、无可对齐的特征，用 `Cover` 铺满纸片是允许的（裁掉纹理看不出来）；键区、字车条、字杆层、拨杆层是有可对齐特征的照片，绝不许用 `Cover`，且绝不许在固定高容器里用 `Fill`（Fill 在宽高比对不上的那一刻就是拉伸）。若某天容器宽高比与图片宽高比对不上，说明高度算错了，修高度，不许用 Fill/Cover 掩盖。
- **纸面文字是流式排布，绝不用绝对 Y**：纸片内各行就是一个正常 Column（padding 28/24/20、行高 28/30），纸片高 = 页眉区 + 行数 × 行高 + 底边距，算出来的；满纸面区后 creep。纸片下缘锚定字车条上缘下方 8vp 不变。纸面区上方的大片深底不是 bug，是生长规则本身（新纸只有 96vp，纸面区是纸活动的区域）——但纸片高、行高、字号在所有设备上必须是同一 vp 值，不能出现“大屏上纸片反而更小”的倒挂。
- **顶栏标题只认文档名，绝不认首行**：视频里顶栏随打字变“1234”，是因为标题取了 `DocModel.title()`（首行非空文本作标题）。顶栏标题只许绑定文档名状态（默认“未命名”，改名/保存时才变），打字时绝不更新。`title()` 的首行回退只许用于文档库列表的占位显示，且须另经用户批准才可用于自动命名——不经批准不得在打字时改顶栏。**第 3/4 步实测纠正**：现在 `Index.syncRows()` 里每落一字就重算 `docTitle = docModel.title(...)`，这行必须删掉，`docTitle` 只在新建/打开/改名时赋值一次。
- **行宽与导件 x 只认舞台宽**：`charsPerLine` 的可用宽 = stageWidth − 2 × 边距，导件 x = 边距 + 当前行已落字总宽（相对舞台左缘），绝不许用屏幕宽——宽屏上用屏幕宽算行宽，行会在纸的右缘之外才换行，导件也会偏出纸面。
- **计数异常定因（2026-11-04 桌面端复核，纠正上条）**：第 3/4 步提交信息称“连打 20 键得到 23 字无丢字”，桌面端复核定因为测试前已点 A/S/D 三键、未清数据（测试污染，非代码多发）；清数据后连测 3 轮均为 20 键 = 20 字。结论：代码无多发 bug，今后计数测试必须先清数据、再报轮次。
- **页码轨锚定纸片，不锚定纸面区**：页码轨容器的高 = 当前纸片高、顶缘 = 纸片顶缘，不许用纸面区满高（否则在纸片还小时页码轨会飘在深底空区里）。
- **字杆/拨杆层只用比例支点与比例尺寸，且尺寸不许绑纸面区高**：层图显示宽 = stageWidth × 层宽比例，支点 = (支点 x 比例, 支点 y 比例) × 显示尺寸。1920s 竖直杆支点 (1024,1776) 只许换算一次为比例 (0.5, 0.867)，代码里绝不许再出现 1024/1776 这类母版像素；其余各机的支点同理换算后写进层素材说明。**第 3/4 步实测纠正**：现在代码用 `层尺寸 = 纸面区高 × 0.9`、支点落在纸面区底缘（字车条上缘），杆长 = 0.752 × 层尺寸（竖直杆 alpha bbox y 236–1889、支点 1776，杆长占图高 0.752），击打时杆尖落在纸面区约 1/3 高处、静止 −64° 时杆尖向左摆出约 0.68 × 纸面区高——纸面区越大摆得越远，宽屏上直接摆出屏幕左缘，就是视频里左缘竖条。修法：层尺寸由 stageWidth 派生（杆尖在击打角 0° 时必须落在打击行、即纸片底部上方、字车导件处），支点锚定在字车条下缘后方（被字车条照片遮住的篮子位置），**静止态杆必须隐藏（透明度 0 或被字车条/键盘裁掉），不许以 −64° 的可见竖条横在纸面区里**；若重锚后截图仍不能证明杆尖落在打击行，字杆层先隐藏、只保击打时序（音、震、落字同帧），不许带着错位的杆子报过。
- **与 §2.2 边距澄清的区别（不许混淆）**：边距 28vp 不许用 onAreaChange 量宽反算，是因为边距是绝对 vp；照片高度必须用宽与宽高比算，是因为高度本身就是宽的函数。量宽算高是本节要求的，量宽算 padding 是 §2.2 禁止的，两者不冲突。

### 2.6 平板逻辑（2026-11-04 MatePad Mini 截图定稿：不用暴力缩放，用尺寸分级 + 排版规则填满屏幕）

截图实证（MatePad Mini 窗口模式）：叠字已对上帽心（§2.5 比例规则生效，无错位），但内容宽只占窗口约 74%、上方约 57% 是深底空区、功能行贴在窗口底缘被裁。这不是错位，是“一个手机版式、一个缩放系数、套所有尺寸”的必然结果：宽高比封顶把平板版压成手机版居中，纸面区弹性又把高屏的剩余全变成深底。逐台调数字、换个缩放系数都是同一条死路，区别只在于是按宽缩放还是按高缩放。

新逻辑：**没有全局缩放系数。尺寸分级决定版式，版式内的每个组件仍按 §2.5 的比例/宽高比规则算，字号按排版目标算，纸按纸的规则填。**

- **分级只认窗口宽（vp），不认机型、不认屏幕尺寸**：手机级：窗口宽 < 600vp；平板级：窗口宽 ≥ 600vp。MatePad Mini 窗口宽在 640–800vp 之间，属平板级。分级阈值 600vp 是 ArkUI 常见的宽屏断点，不是为某台设备写的数。
- **量窗口，不量屏幕**：现在 `Index.measureLayout` 用 `display.getDefaultDisplaySync()`（全屏尺寸），MatePad 窗口模式（顶部窗口条 + 右侧悬浮坞）下窗口尺寸 ≠ 屏幕尺寸，功能行按屏幕高算必然贴底被裁。改成根容器 `onAreaChange` 量到的实际窗口宽高，再减顶部/底部/右侧安全区 inset，得到可用宽高；§2.5/§2.6 的一切尺寸都从这个可用尺寸算，不许再用 display 尺寸。窗口模式、悬浮坞、分屏下自动生效，不用为每种窗口写分支。
- **平板级：全宽，不封顶到手机宽**：纸、字车条、键区宽一律 = 可用宽，不留 §2.5 初版的居中边距。键区高、字车条高仍按宽高比派生（全宽 640vp 时键区高 640/2.101 = 305vp、字车条高 640/7.14 = 90vp，天然比手机版大，不是拉伸——图片宽高比未变、像素未超原生分辨率，见下）。
- **字号按排版目标算，不按屏幕缩放**：目标每行 50 字（英文等宽 0.6em、中文全角 1em），字号 = (可用宽 − 2 × 边距 28vp) / (50 × 0.6)，钳制在 17–24vp 之间；行高按字号比例算（英文行高/字号 = 28/17，中文 = 30/17）。手机 390vp 宽算出 11vp，被下限钳回 17vp（手机版不变）；平板 640vp 宽算出约 19.5vp、800vp 宽算出约 24vp（上限），每行约 50 字，不会出现 80 字一行。字号是排版选择，不是缩放系数。
- **宽上限只认排版上限，不认手机宽高比**：可用宽超过 776vp 时舞台宽封顶 776vp、水平居中。776vp = 上限字号 24vp × 目标 50 字 × 0.6 + 2 × 边距 28vp，是“字再大、行再长就没法读”的排版上限，不是 390/844 的手机宽高比。MatePad 640–800vp 宽基本全宽（800vp 时仅留约 12vp 一侧边距），不再出现 26% 的居中边距。
- **平板级纸的初始状态：满页纸，不是 96vp 生长**：平板纸面区高约 480–740vp，从 96vp 生长要 12–17 行才能填满，期间大半屏都是深底——这就是截图里的空区。平板级新纸初始高 = 纸面区满高（满页纸，§2.2 的 creep 机制从第一行起生效），页眉在纸片顶部、打击行在纸片底部、中间空处是纸纹（现有纸纹资源，`Cover` 允许，见 §2.5），不是深底。手机级保持 96vp 生长不变（生长是手机版的进纸动画，用户已定）；平板级用满页纸是尺寸分级的初始状态差异，不是把生长规则废掉——creep、换页、换纸/换字体重算全部沿用 §2.2。代价如实说：平板级失去进纸生长动画，换来满屏利用；若用户要平板级也保留生长动画，备选是纸面区上方不再留深底、改用上一页纸面叠放（需另定稿，不在本批顺手做）。
- **现有资源不超原生分辨率，不模糊**：键带 2048px、字车条 2048px、纸纹 2048px；平板宽 640–800vp、密度 2–2.5 时所需像素 1280–2000px，均未超 2048px，全宽显示不产生上采样模糊。 guard：若某天可用宽 × 密度 > 2048px，照片组件宽封顶 2048/密度 vp、居中——这是原生像素上限，不是设计缩放。
- **不做的事（避免走回头路）**：不把机器 front 图（`*-front.jpg`）当平板页眉铺在纸面上方——front 图自带键盘与纸面，铺上去会与下方的键区、字车条重复成两台机器；不把收藏页/文档库硬塞成平板侧栏——竖屏平板剩余宽不足以放一个可用的侧栏，侧栏只在横屏宽屏下才成立，竖屏锁定下不做；不为 MatePad 单独写分支——分级、排版目标、像素上限三条规则在所有平板上同一套代码。

### 2.7 素材分层与机器坐标系（2026-11-04 用户定：本质是素材不够，不是代码缩放不够）

- 结论先说：_w0–_w3（1600×2560，14:42–14:43）证明平移代码本身在动——_w0 空纸时中央金属件在 641、代码导件在 169；_w2 满行 a 后中央金属件移到 388（左移约 25% 屏宽）、代码导件移到 812（右移），字车条确实按平移宽图走了。但效果仍不对，因为**两根导件在反向交叉**：代码导件随光标从左缘走到右缘，照片里的中央金属件随字车从中部走到左部，行中两者交错、行末两者分居两端，眼睛看到的是两台互不相干的机器，不是“一台打字机在打字”。再调行程、再换缩放系数都修不好这个——它是素材结构问题。
- 根因有三条，都是素材层面：
  1. **字车条是一张烤死的整图**：现 `*-carriage-strip.png`（2048×287）把滚筒纹理、左右旋钮、中央金属件、压纸卷全部烤进同一张图，旋钮就在图的两端、中央件就在图的正中。平移它，旋钮必然一端出屏、中央件必然远离打击点；图宽只有 2048px、图外没有任何可揭示的连续纹理，平移行程一到头就没内容了。这张图生来是静态正面照，不是为移动设计的。
  2. **纸、字车、键盘、字杆来自四张不同照片**：纸纹是 2048 方图、字车是 front 图的裁带、键区是 keyarea 母版的裁带、字杆是另一张抠图，四者拍摄距离、角度、比例各不相同，没有共同的机器坐标。代码只好给每张图各算各的宽高比（纸按行数、字车按 7.14、键区按 2.101、字杆按舞台宽），在 390×844 参考尺寸上凑齐了，换一台设备、换一个窗口，相对位置（纸下缘对字车上缘、字杆尖对打击行、键帽对叠字）就各自漂移——§2.5/§2.6 修的是“不错位”，修不了“不是一台机器”。
  3. **没有锚点登记**：现有锚点只有键帽中心（keymap）、字杆支点（1920s 比例 0.5/0.867）、字车裁带百分比，没有打击点在字车图里的位置、旋钮中心在字车图里的位置、纸左右缘在字车图里的位置、纸下缘对字车上缘的搭接量在纸图里的位置。没有这些锚点，代码放素材只能靠猜边距（−8vp 压纸之类），换设备必猜错。
- 新素材规格（先出素材、再改代码，不许再用代码补丁掩盖素材缺口）：
  - **机器坐标系**：每台机器定一个抽象机器框（宽 1000 单位，高按机器正面比例定），所有素材、所有锚点都登记在这个框里，不许再出现“这张图用母版像素、那张图用百分比、另一张图用 vp”三种口径混用。设备上只做一次换算：`scale = 舞台宽 / 机器框宽`，所有图层的位置与尺寸 = 机器坐标 × scale，换设备只换 scale、相对位置一律不变；平板分级（§2.6）只影响纸面排版（字号、行数、满页与否），不影响机器几何。
  - **字车拆四层（同框、同尺寸、透明底，靠框对齐不靠代码偏移）**：① 滚筒纹理层：可横向连续、无旋钮、无中央件、无压纸卷，宽 = 机器框宽 + 2 × 最大行程，平移永不跑出内容；② 左右旋钮层：左右各一张独立 sprite，锚点 = 旋钮中心（机器坐标），随字车层整体平移，不烤进滚筒图；③ 中央金属件层：独立 sprite，锚点 = 底部中心，随字车层整体平移——它是机器件，不是光标；④ 压纸卷/纸夹层：独立 sprite，随字车层整体平移。拆完之后，字车层整体平移时四层同进同退，中央件与旋钮的相对位置永远不变。
  - **导件只留一根，且固定在打击点**：拆层之后，代码里那根随光标右移的细线必须改名——它不是字车导件，它是纸面光标（文档坐标），画在纸面上、不画在字车条上。字车条上的打击点指示 = 字杆尖 + 机器框里的打击点锚点（固定，不随光标、不随字车走）；纸面光标与打击点指示是两个东西，不许再用一根线既当光标又当打击点、又让它在字车条上左右走。物理模型（打击点固定、纸与字车同向左移）是拆层之后的下一步，不在本批代码里混进——先把素材拆干净、锚点登记完，物理模型才有可落的图层；没拆层就谈物理模型，等于在烤死的图上再贴一层。
  - **纸素材**：纸纹不再是 2048 方图裁成纸片——要一张整页纸（左右缘、页眉、页脚在机器框里的位置登记清楚），纸的横向偏移与字车横向偏移用同一个机器坐标（纸在字车上，两者同进同退），纸的纵向生长仍按 §2.2。键区素材：键帽直径也要登记进机器框，叠字字号 = 键帽直径 × 比例（不是固定 14vp），否则大设备上叠字相对帽子越来越小、小设备上越来越大——这是同一类“素材无锚点”问题。
  - **生成/重制路径（需要重新优化与新生成，两者都要，不是只改代码）**：① 重新优化现有素材——用 AI 补全滚筒连续纹理（横向延展，不是重画一根新滚筒）、抠掉中央件与旋钮并分别出透明层、纸改整页重裁、键区母版只重登记锚点不重画；② 新生成缺失素材——其余三台字杆层目前缺失（只有 1920s 有），按同一机器框从各自 front 图抠取或生成；滚筒纹理超出 2048px 的部分、抠取失败的旋钮 sprite，按同风格新生成；现有照片若是透视角度、无法抠出平视图层，则按同机型、同色板（1920s 机身 #312b24、键帽 #dbccb3 等）新生成一张平视正面图再拆层。每步都要验图（alpha bbox + 真机截图核对锚点），不许凭 prompt 一次性出整机图蒙过去——整机新图必然带来新的透视、新的比例、未知的锚点，等于把今天的问题重演一遍。

## 7. 打字功能规格（“根本没实现”的部分，本节就是实现标准）

上一版的问题不是缺动画，是打字链本身没闭合。本节逐环钉死，缺一环即未实现。

### 7.1 唯一事实源

- 文档模型是唯一事实源：行数组 + 每行落字时的机器/纸张/色带/字体元数据 + 光标（行，列 offset）+ 页码；纸面、键盘、导出、存储全部读它，不许各自维护一份文本。
- 存储：JSON + 纯文本 .txt 成对保存、成对删除；每次停顿（防抖 500ms）落盘一次；打开即恢复文档、光标、纸张滚动位置。

### 7.2 输入双通道（英文自绘键 + 中文系统输入法，互斥，不许混）

- 英文：照片键区（§2.3）；容器级 onTouch + `Map<触点id, 键>` 多点状态，命中按键位坐标表判定；Down 高亮、Up/Cancel 回弹；滑入只发声不上屏（防误落字，沿用阶段 1 结论）。
- 中文：系统输入法 attach（attach 前订阅 setPreviewText，finishTextPreview 成对；insertText 整词拆单字 30–50ms 间隔逐字落字；deleteLeft/deleteRight/moveCursor 接管；updateCursor/changeSelection 同步光标）；预编辑串只显示（浅色 + 下划线），不发音不落墨不进模型；折叠切换不 detach/re-attach。
- 切换：底行中/EN 键切换；英文键弹起纸面不留系统键盘残影；系统键盘弹起时纸面避让（OFFSET_WITH_CARET 或 RESIZE_WITH_CARET，保当前行可见）。

### 7.3 击打链（顺序钉死，同一 Down 回调内完成前三步）

1. 手指按下：帽上高亮（照片帽不动 transform、不缩放，只叠高亮层）；代码功能行键缩放 0.92（springCurve(0,1,200,18)），只动 transform/透明度。
2. 同一回调内播音：SoundPool 当刻触发，12 变体轮询防机关枪感；空格、铃、回车各走专属音。
3. 同一回调内震动：15–30ms，usage 'touch'，fire-and-forget；系统触感关闭时静默跳过。
4. 字杆摆动：竖直杆层（`typebar-vertical.png`）绕支点（比例 0.5, 0.867，母版像素 (1024,1776) 换算，代码里只许用比例，见 §2.5）从收起态摆到竖直击打态再回落；击打行程快、回程稍慢；**字母出现在纸面的时刻必须与杆到位同帧**（落字挂在杆到位回调链上，不许键按了字先出、杆后到）。
5. 光标前进一格：只光标前进，纸面不整体抖动；每落一字字车导件向右移一字宽（与杆到位同帧，弹簧动画）；换行时：纸片未满幅则纸片向上生长一行（顶缘上推，打击行不动），已满幅则内容弹簧上移一行（creep），不许跳变（生长规则见 §2.2）。
6. 行末预告铃：距右边界约 8 字响一声（声 + 纸面轻提示，不许弹窗）。
7. 换行（换行键）：拨杆摆动（`lever-single.png`）+ 叮声（`carriage-reset-01.ogg`）+ 纸片生长或走纸（按 §2.2 生长规则，未满幅生长、已满幅走纸）+ 字车回位，四者同步；字车回位 = 导件回到纸面左缘 + 字车条照片从累计左移量一次性向右跳回 0（250ms 弹簧，行程即本行累计量、本版最大行程见 §2.1 平移宽图、不许再用 12vp bump），字车层（`carriage-layer.png`）随换行回位移动。行满自动换行时同样走本条回位动画，不许让字车条停在行末位置开始下一行。
- 导件与字车条方向相反是本批 UI 折中，如实记（不许谎称物理 1:1）：导件是纸面光标指示（文档坐标，随文字从左向右走，为可读性）；字车条是机器前进指示（机器坐标，随字车从右向左走，为机器感）。物理 1:1 要求打击点固定、纸与字车一起左移、已落字随纸左移，会把行首推出屏幕左缘——那是另一套重写纸面模型的方案（打击点固定、纸面左移、导件固定），不在本批做，不许把两套模型混在一起（本批导件仍向右走、字车仍按缩放行程左移）。
8. 删除双模式：现代删除（字消失、光标回退、行重排）；XXX 覆盖（光标回退一格，在错字上打 X，错字保留 X 痕，光标停留）。删除键本身同样走第 1–3 步。

### 7.4 验收标准（每项真机可验，不许口头报过）

- 自适应几何（§2.5，三个宽高比各验一遍，不许只在自家手机上验过就报过）：参考手机 390×844、高屏手机（约 412×915）、宽屏平板/折叠内屏（约 800×1280 或折叠内屏尺寸）。每台截图核：① 键区底排与空格条完整可见、无裁切；② 叠字帽心误差 ≤3vp，且顶行、中行、底行误差不随行号增大（误差随行号增大 = X、Y 各用一套缩放的铁证，立即按 §2.5 重算）；③ 纸面文字全部落在纸纹矩形内，不许落在深底上；④ 打字时顶栏标题不变（仍为文档名）；⑤ 字车导件 x 与光标列对齐、换行回左缘；⑥ 字杆层不许以竖条出现在屏幕边缘。六项中任一项不过，几何重构未过，不许以“这台设备特殊”结案。
- 平板逻辑（§2.6，MatePad Mini 同款窗口模式必验）：平板级截图核：① 纸、字车条、键区宽 = 可用宽（>776vp 时封顶 776vp 居中），不许出现约 26% 的居中边距；② 新纸初始高 = 纸面区满高（满页纸），上方不许出现大片深底空区；③ 字号在 17–24vp 之间、每行约 50 字；④ 功能行在底部安全区之上、完整可见不被窗口底缘裁掉；⑤ 窗口模式、分屏下尺寸随窗口变，不许用全屏 display 尺寸。
- 字车条动效（§2.1/§7.3，行首、行中、行末、换行四段截图核，核中央金属件 x 不是“感觉动了”）：行首照片 x = 0、行中约 −最大行程/2、行末约 −最大行程（手机约 −136vp、MatePad 舞台约 −165vp），中央金属件 x 同步左移相同量（截图里量中央金属件相对纸面左缘的距离，四段必须单调左移、行末比行首左移约一个最大行程），导件同步在左缘、中部、近右缘；换行时照片一次性向右跳回 0、导件回左缘、拨杆摆动 + 叮声同步；打字全程照片 x 恒 0、或换行只有 12vp bump、或行末照片仍与纸面左右缘对齐，均按未过计。
- 字车条未生效诊断（2026-11-04 14:28 截图后增）：先确认 MatePad 上的包是否含 48c4c9b 之后的平移宽图提交（HAP 安装时间、hilog 里 recalcTravel 的 max/perChar/cpl、commitChar 后 carriageOffsetVp 日志），再在同一台设备上慢速连打（每秒 1 键、避开字杆队列丢键）10/20/40 字各截一张、量中央金属件 x；若三张中央金属件 x 不动，先查 @Prop 是否拿到新值、guide 与 carriage 两次 animateTo 是否互相取消、carriageOffset 是否被换行/重进/文档重载重置为 0，再谈行程大小——不许只改行程数就报过。另：48c4c9b 已知问题（0.3s 间隔连点 43 次实得 41 字、行满未触发）必须在同批复核：连点丢键与行满不触发都会让字车测试失真，行满不触发时偏移必须钳制、不能继续左移出空白。
- 杆到位与落字同帧：10× 慢放构建逐帧核对（真机 screenCap 约 710ms/帧，抓不到 70ms 级动画，慢放是既定取证法）；正常速度由 animateTo.onFinish 回调链保证顺序。
- 中文：第三方输入法（搜狗/讯飞）逐项测：setPreviewText 有无、预编辑显示、光标与选区同步、删除语义、回车键行为、键盘高度与避让。
- 换装：换机/换纸/换色带/换字体后，已落字保留旧呈现、新落字用新呈现、光标与文档位置不丢。
- 导出：图片/PDF/纯文本三格式各出一份真机产物，分享面板正常拉起，PDF 自定义字体嵌入按真机结果报（不行则退回图片贴页方式，不许硬编）。
