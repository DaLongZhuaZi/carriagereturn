# 回车核心打字体验调研报告

> 调研员交付（2026-11-03）。调研方式：公开网络检索（华为开发者文档、官方指南、公开评测与商店描述），未登录、未购买、未做任何逆向。以下 API 名均以检索到的官方文档为准，个别细节标注“需真机验证”。

## 总体推荐架构（一句话）

**自绘 QWERTY 键盘（英文）＋ 系统输入法 attach（中文）双通道；纸面主体用 Text 行组件虚拟化渲染，Canvas 只做落字特效与导出；导出走离屏 Builder 截图，PDF 走 PDF Kit 文本路径。**

---

## (1) 自绘 QWERTY 机械键盘

**选项**

- A. 全自绘键盘组件（推荐）：Row/Column 拼键位，每个键是轻量组件，状态自管。外观、键程、音效、震动完全可控，美术优先的要求只能这条路。
- B. `TextInput` / `RichEditor` 的 `customKeyboard` 属性：把自绘组件绑成键盘，优点是系统负责键盘避让（`KeyboardOptions.supportAvoidance`）与焦点生命周期；缺点是键盘形态仍受输入框激活逻辑约束。适合“以输入框为锚点”的实现，不适合“键盘本身就是机器一部分”的拟物设计。
- C. 系统键盘加皮肤：不可行，系统键盘无法由应用换肤。排除。

**多点触控（关键，勿用 onClick）**

- 用 `onTouch`，不用 `onClick`：onClick 是单点、抬手才触发，拿不到按下瞬间，也做不了多指同按。
- `TouchEvent.touches` 是当前全部触点，`changedTouches` 是本次变化的触点，`TouchObject.id` 区分手指。注意两点：touches 数组不按 id 排序，不要按数组顺序取；手指抬起后 id 会被复用，抬起时必须清理该 id 的按键状态。
- 推荐做法：键盘容器级 `onTouch` ＋ 坐标到键位的映射（不要每键各挂 onTouch），这样多指同按、手指滑过换键都能处理；按键视觉状态用 `Map<触点id, 键>` 维护，Down 压下、Up/Cancel 回弹。

**按下、回弹动画**

- `animateTo` ＋ 弹簧曲线：按下用高刚度短弹簧（社区实践 `curves.springCurve(0, 1, 200, 18)`，缩放约 0.92，下沉干脆）；松开用 `curves.springMotion()` 或低刚度弹簧（`springCurve(0, 1, 120, 12)`），带一次微震荡的 Q 弹回弹。`animateTo` 的弹簧动画支持中断重入，新动画自动继承当前帧位置与速度，快速连打不会抽搐。
- 注意：`keyframeAnimateTo` 不支持 springMotion / responsiveSpringMotion / interpolatingSpring（时长不生效），键程动画不要走关键帧。
- 60fps 要点：动画只动 transform（scale/translate）与透明度，不要在按下瞬间改宽高、字号、布局；键盘状态与文档状态分离，敲一个键只刷新该键与当前行，不 whole-page 刷新；键数固定（约 30～40 个），不需要 LazyForEach。

**音效与震动同步**

- 音效用 **SoundPool**（`@kit.AudioKit` 的 `media.createSoundPool`）：专为短促音效设计，一次加载、多次低时延播放。要点：启动时预加载整套机器音包（不要现用现加载）；单音解码后不超过 1MB，时长建议 100ms 内，OGG/WAV、44.1/48kHz；`maxStreams` 1～32，快速连打要留足并发；`AudioRendererInfo` 里 `rendererFlags: 1` 走低延迟通道，`StreamUsage.STREAM_USAGE_MUSIC`；**声音必须在 TouchType.Down 当刻触发**，不要等 Up。
- 同 soundId 正在播放时再次 `play()` 会先停再播，快速连打会出现“吃音”；缓解办法是每台机器准备 2～3 个同类音色变体轮询播放，并可用 `rate` 参数做轻微随机（RENDER_RATE_NORMAL 附近），避免机关枪效应。此点需真机验证重叠行为。
- 震动用 `@ohos.vibrator`：`vibrator.startVibration({ type: 'time', duration: 15～30 }, { id: 0, usage: 'touch' })`；或预置 effectId（先 `isSupportEffect` 查设备是否支持）。需声明 `ohos.permission.VIBRATE`。注意系统触感开关可能关掉震动，震动只能做加分项，不能做唯一反馈。
- 同步顺序：同一 Down 回调里依次触发动画状态、SoundPool.play、startVibration（fire-and-forget，不要 await 震动再播声音，否则延迟叠加）。

## (2) 纸面渲染与走纸

**选项**

- A. Text 行组件列表（推荐作主体）：`List` ＋ `LazyForEach` ＋ `IDataSource` ＋ `@Reusable`，`cachedCount` 设约半屏。原生文本排版（换行、字体、行距）免费获得，长文档按需创建、滑出回收，内存与帧率都有官方最佳实践背书。`getData` 里不要做耗时操作。
- B. Canvas 全量重绘：墨晕、抖动、做旧可控到每字，但换行、断词、measureText 全要手写，长文档重绘成本高。只适合可视区小幅面，不适合整文档。
- C. 混合（推荐）：纸面主体用 A；墨色不均、落字冲击、纸纹做旧用背景图层＋当前行 Canvas 叠加层做短暂特效；导出时用离屏渲染（见 §6），保证所见即所得。

**走纸与换行**

- 推荐“光标行锚定”：纸张随打字上移，当前行始终停在打字区高度，`Scroller` 平滑滚动；换行时（拨杆手势或自动换行）纸张做一次弹簧上移动画＋叮声。不要每敲一字就移动整张纸，视觉会晕；真实打字机是字车横移、纸纵移，屏幕上等价为光标前进＋行切换时纸上移。
- 加分细节（公开竞品都有，见 §5）：行末 margin bell——距右边界约 8 字时响一声预告铃；拨杆滑动换行；滚轮/旋钮滚纸（对应滚动查看历史行）。

**墨色渲染**

- 墨色（黑/蓝/红）以“段”为单位换 `fontColor`，成本最低；想做旧色带“深浅不一”，以“行”为单位微调透明度；到“字”为单位的浓淡变化才需要 Canvas 或带做旧纹理的专用字体。
- 字体：`font.registerFont({ familyName, familySrc: $rawfile('font/xxx.ttf') })`，在 `aboutToAppear` 或 Ability 启动后注册，`Text.fontFamily` 引用；支持 TTF/OTF。Canvas 路径则用 `@ohos.graphics.text` 的 `FontCollection.loadFontSync`。
- 长文档性能：文档模型按行存数组，不要存一个巨型字符串；导出长图时按官方长截图模式分段截图＋`readPixelsSync`/`writePixelsSync` 拼接，并限制总高度防内存爆炸（官方示例提 5000px 量级上限，实际值按真机定）。

## (3) 中文输入（本模块最关键，推荐已定）

**系统输入法接入自绘编辑器的官方路径（IME Kit）**

- `inputMethod.getController()` 拿 `InputMethodController`，`attach(showKeyboard, textConfig, callback)` 绑定自绘编辑框；`showTextInput()` 拉键盘、`hideTextInput()` 收键盘、`detach()` 解绑，attach/detach、show/hide 必须成对。
- 关键事件：`on('insertText')`（上屏提交文本）、`on('deleteLeft')`、`on('deleteRight')`、`on('moveCursor')`、`on('sendFunctionKey')`；用 `updateCursor` / `changeSelection` / `updateAttribute` 把光标与选中态同步回输入法（否则候选窗位置不对）。
- 拼音预编辑文本：`on('setPreviewText', (text, range) => void)`（API 17+），**必须在 attach 之前订阅，且与 `on('finishTextPreview')` 配对订阅**。拼音输入时未确定的候选串走这条事件，选定后才走 `insertText`。

**提交上屏时如何叠加打字机音效与落字动画**

- 渲染分两层：预编辑层（拼音串/候选串）用浅色＋下划线样式显示在光标处，**不发音、不落墨**；提交层（insertText 到达）才进文档模型。
- insertText 一次可能带多个汉字（整词上屏）。不要整词瞬间弹出：把提交串拆成单字队列，以约 30～50ms 间隔逐字落字，每字触发一次按键音＋落字动画（字车式依次敲击），这样中文也能保留打字机节奏。这是中文体验成败手感的关键设计点。
- 删除：`deleteLeft(length)` 按输入法给的长度删，注意长度单位与多码元字符的对应关系需真机验证；中文删除同样配一声音效（退格声与按键声区分）。

**自绘键盘加拼音候选行的成本对比**

- 自绘拼音候选行意味着自建输入法：拼音切分、候选词库（离线词库体积大）、排序、模糊音、联想词、用户词学习，全套做下来等于再做一个输入法，且拼不过用户已习惯的系统输入法（搜狗/讯飞等的手写、语音、剪贴板能力也全丢）。成本量级远超收益。
- **推荐：首发双通道**——自绘 QWERTY 负责英文/数字/符号（直接改文档模型，不走 IME）；中文走系统输入法 attach；两者用一个切换键切换。自绘键盘外观做成机器的一部分，系统输入法弹出时纸面相应上移（键盘避让），视觉上仍可接受。这是 Hanx 的做法（自绘键盘＋蓝牙键盘），也是成本最低、中文体验最好的组合。

## (4) 折叠屏

**API（`@kit.ArkUI` 的 display 模块，旧称 `@ohos.display`）**

- `display.isFoldable()` 判设备是否可折叠；`display.getFoldStatus()` / `getDefaultDisplaySync().foldStatus` 取当前态。
- `display.on('foldStatusChange', cb)`：`FoldStatus` ＝ 0 UNKNOWN / 1 EXPANDED（展开）/ 2 FOLDED（外屏）/ 3 HALF_FOLDED（半折叠）。注意物理折叠态变化在前、屏幕显示模式变化在后，另有 `display.on('foldDisplayModeChange')` 监听显示模式，两者时序不同，不要混用。
- `display.on('foldAngleChange', cb)`（API 12+）：回调 `Array<number>`，0～180°；双转轴设备给两个值。角度事件是连续触发的，必须做节流/防抖，不要每度都重排布局。
- `display.getCurrentFoldCreaseRegion()`：返回 `FoldCreaseRegion`，取 `creaseRects[0]`（px 单位），用 `uiContext.px2vp` 转 vp 后算上下半屏尺寸；页面退出时 `display.off('foldStatusChange')` 取消监听防泄漏。

**半开判定与布局实践**

- 半开（桌台模式）判定＝`HALF_FOLDED` ＋ 横屏 ＋ 角度落在约 60°～120° 区间（社区实践值，Mate X 真机校准后定）。不要只看角度，也不要只看状态。
- 布局：上半屏高度＝折痕 top，下半屏＝剩余高度减折痕 height；纸与键盘的分界对齐折痕，任何内容不横跨折痕，折痕区留空当铰链避让带。
- 状态保留：文档模型、光标、纸张滚动位置放在 ViewModel / AppStorage，不放在随布局重建的页面局部 `@State`；三态切换只换布局参数（纸高、键盘高、单双栏），不要重建编辑器组件实例；**折叠切换时不要 detach/re-attach 输入法**（attach 只跟随焦点变化），否则中文输入会断。
- 外屏（FOLDED）＝便签＋文档列表单栏；展开（EXPANDED）＝宽纸＋大键盘，文档库与机器收藏可走双栏。兜底：非折叠大屏用 `window` 的 `windowSizeChange` 做尺寸自适应。

## (5) 公开信息中的 Hanx、Printique、Rebi 手感（只用公开描述与评测）

- **Hanx Writer**：3 台机器（免费 Hanx Prime Select；Hanx 707 字体更粗；Hanx Golden Touch 更现代），每台外观＋字体不同；声音被描述为 SHOOK SHOOK / KLOCK-KLOCK / FITT-FITT，带字车移动感；可去掉 Delete 键走“传统模式”（错字用 X 覆盖，评测称这是亮点之一）；无自动纠错、无自动大写；页面可归档到文件夹，导出走邮件/PDF；支持蓝牙键盘；纸张样式与墨色可购。短板（评测原话方向）：新奇感为主，不是全功能文字处理；缺“写作本”式合集管理。
- **Printique**：卖点句是“每次按键都真实，每句话都印成卡片”；触感声音＋震动；写完印成卡片、可划掉已完成想法、保存分享卡片；iCloud 同步；免费＋终身买断。形态与回车不同：它是“卡片式短想法”，不是长文档；可借鉴的是“产出物＝卡片”的分享思路。
- **Rebi Typewriter（Android）**：纸张纹理四种（折痕纸、帆布纸、老化纸、横格纸）、页/字/高亮颜色、Roughness 功能（模拟旧机器的不完美）、可从相册导入背景图、多语言键盘（拉丁、西里尔、韩文、日文、德文、西班牙文）、真实打字机声音、保存/打开/分享页面、完全免费。评测抱怨点正好是回车要避的坑：页面存成图片而非可编辑文本、多页文档不支持、回车时没有叮声、偶有冻结与渲染错误。
- **TypePress（Product Hunt 公开描述，附带参考）**：手感清单最完整，值得抄作业：按键下沉、字杆摆起击打色带、每字字车滑动、纸张上 creep、行末响铃、滑动字车换行、旋钮滚纸；黑红蓝三色色带可句中切换；墨量分浓/正常/淡、清晰/柔和，淡墨会逐词不均匀褪色；错字可覆盖重打或删除线保留；每页独立字体（Courier Prime、Special Elite 等）。
- **合成给回车的手感清单**：键下沉＋弹簧回弹；字车微移（只做光标前进，不要整纸横移）；行 creep；行末预告铃；拨杆换行＋叮；句中换色带；墨量浓淡；错字 X 覆盖与删除键双模式；可编辑文本模型（绝不学 Rebi 存图片）。

## (6) 文档本地存储与导出

**存储**

- 文档本体：`@kit.CoreFileKit` 的 `fileIo` 读写 `context.filesDir`（应用沙箱，无需权限）。文档存两份：JSON（文本＋机器、纸张、色带、字体、时间戳等元数据）＋纯文本（.txt，UTF-8，`OpenMode.CREATE | WRITE_ONLY`，追加用 APPEND）。
- 用户可见位置：用 FilePicker `DocumentSaveOptions`（`newFileNames`、`fileSuffixChoices` 如 `['Document|.txt', '.pdf']`）让用户选保存位置；或 `pickerMode: DOWNLOAD`（需用户授权，在 Download 下建以包名命名的文件夹）。
- 自定义内容导入（信纸、色带、字体）：FilePicker 选文件后拷入沙箱并校验格式（图片 png/jpg/webp；字体 ttf/otf），字体走 `font.registerFont` 注册；导入时提示用户自担版权（只导自己有权利的素材）。

**图片导出（主路径）**

- `componentSnapshot`：`uiContext.getComponentSnapshot().get(id, { scale, waitUntilRenderFinished })` 截已加载组件，或 `getSync`（API 12+）；**推荐 `createFromBuilder`**：用专门写给导出的 Builder 做离屏渲染，把交互 UI 与导出模板解耦，宽高、边距、阴影可控，所见即所得；注意截图只取组件区域内内容，超边界不进图。
- PixelMap → `image.createImagePacker().packing(PixelMap, { format: 'image/jpeg' | 'image/png', quality })` → ArrayBuffer → `fs.write` 落沙箱 → 系统分享。注意：截图不要放在 `aboutToAppear` 等构建期调用（会截到上一帧），放在点击事件里；预览器不支持，真机/模拟器才行。

**PDF 导出（两条路，推荐 A 为主、B 为兜底）**

- A. PDF Kit 文本 PDF（`@kit.PDFKit` 的 `pdfService`，API 12+，系统能力 `SystemCapability.OfficeService.PDFService.Core`）：`new pdfService.PdfDocument()` → `createDocument(宽, 高)`（单位 Point，1 英寸＝72pt，如 A4 用 595×842）→ `insertBlankPage(index, 宽, 高)` → `getPage(index)` → `page.addTextObject(文本, x, y, TextStyle)`（**只可按行添加，无自动换行，分页与断行必须自己算**；字体用 `font.getFontByName('HarmonyOS Sans')?.path` 填 `FontInfo`）→ `page.addImageObject(沙箱图片路径, x, y, 宽, 高)`（纸纹当背景图贴）→ `saveDocument(沙箱路径)`。社区已报告的坑：`createDocument` 后直接 `getPage(1)` 而不是先 `insertBlankPage` 会导致文本图片没写上、保存进度回调不触发——页索引必须与插入顺序对齐。
- B. Webview createPdf（兜底）：把纸面渲染成 HTML（纸纹、墨色、字体用 CSS 还原）放 Web 组件，`WebviewController.createPdf({ width: 8.27, height: 11.69, margins, shouldPrintBackground: true }, 回调)` 拿 `PdfData.pdfArrayBuffer()` 写文件。优点是像素级还原纸面，缺点是多一套 HTML 模板。
- 纯文本导出：`fs.write` UTF-8 .txt 即可。

**系统分享**

- Share Kit 的 `systemShare`：`new systemShare.SharedData({ utd, content | uri })`，可 `addRecord` 多条；`new systemShare.ShareController(data)`，`controller.show(context, { previewMode: DETAIL, selectionMode: SINGLE })` 拉起系统分享面板；`controller.on('dismiss')` 监听关闭。
- 两个硬坑：分享记录的 uri 必须是 `fileUri.getUriFromPath(沙箱路径)` 转出的 file:// URI，裸沙箱路径会被系统判 uri 为空而拒收（且 Promise 照常 resolve，应用层零感知）；缩略图 `thumbnail` 限制 32KB 以下，超了用 ImagePacker 压。

## 未决问题（需真机或进一步核实）

1. **PDF Kit 的手机可用性**：官方 API 未在检索片段中限定设备，但 PDF Kit 是否在手机上完整可用（还是仅平板/2 合 1）需在 Mate 系列真机上实测 `createDocument → addTextObject → saveDocument` 全链路。
2. **拼音预编辑的第三方输入法兼容性**：`setPreviewText` 是 API 17+ 能力，需实测搜狗、讯飞等第三方输入法是否都发该事件；若某输入法不发，预编辑层需降级为“只显示提交串”。
3. **`updateCursor` 的坐标空间**：光标同步给输入法时坐标是 px 还是 vp、相对窗口还是屏幕，需对着文档实测，否则候选窗会飘。
4. **SoundPool 重叠行为**：同 soundId 重播是停旧启新还是多流重叠，需真机确认；若为前者，轮询变体音色的方案必须做。
5. **折叠屏角度阈值**：60°～120° 是社区实践值，Mate X 真机上的 HALF_FOLDED 上报角度与折痕 rect 需实测校准；三折叠设备的双角度数组处理方式也需确认。
6. **PDF 自定义字体嵌入**：`addTextObject` 的 `FontInfo.fontPath` 能否指向应用注册的自定义字体（还是仅限系统字体），需实测；若不行，PDF 路径只能退回“图片贴页”方式。
7. **分享 UTD 的 PDF 标识**：图片（general.png/jpeg）与文本已确认，PDF 的 UTD 串需按 `utd.getUniformDataTypeByFilenameExtension` 实测确认，不要硬编码猜测。
8. **长图导出内存上限**：分段拼接的单张高度上限（官方示例提 5000px 量级）需按目标机型实测，过长文档应自动分页导出而非一张长图。
9. **机器外观版权边界**（产品侧，非技术）：致敬历史上著名打字机时，只能做“风格近似”的原创设计，不得复刻品牌名、铭牌、 trade dress；每台机器上线前需过一遍品牌元素清单——此条属产品决策，不属本次技术调研结论。

## 附：输入法适配清单（2026-11-03 用户核定中文走系统输入法后补记）

- 预编辑开关（2026-11-03 20:29 用户定）：setPreviewText 开。理由：中文
  输入没有 inline 预编辑就是盲打加整词蹦出，违背逐字反馈；预编辑串
  “铅笔痕变墨字”是拟物质感的一部分；风险靠下述三条铁律加真机专项
  回归兜住；某家输入法不发则自动降级。

- 候选词归属：候选词栏是输入法应用自己的 UI，App 不用也不应自绘；
  App 的一侧是预编辑（preview / composing）通道：输入法发 setPreviewText
  时，App 把预编辑串以浅色加下划线显示在光标处，不发音、不落墨；
  用户选词或取消时输入法发 finishTextPreview，App 清理预编辑态，
  随后 insertText 送达的才是提交串。
- 订阅顺序（官方文档原话，漏订会丢事件）：insertText、deleteLeft、
  setPreviewText、finishTextPreview 等事件订阅必须在 attach 之前完成，
  且 setPreviewText 必须与 finishTextPreview 成对订阅；attach 与 detach
  必须成对；自绘控件所在窗口必须处于聚焦态，否则 attach 失败。
- TextConfig：textInputType 配 TEXT，enterKeyType 配换行（不要配成搜索
  之类的动作键）；attach(showKeyboard) 后用 showTextInput 拉起键盘。
- 状态同步：光标每次移动调 updateCursor（CursorInfo：left/top/width/
  height），选区变化调 changeSelection（全文、start、end），属性变化调
  updateAttribute；三者只在 attach 之后可用。
- 提交串处理：insertText 整词拆单字、以约 30–50ms 间隔逐字落字，
  每字一音加落字动画（与本报告中文一节一致）。
- 键盘避让：系统键盘弹起时纸面要避让（缩小或滚动），不能被键盘盖住；
  折叠切换时不要 detach/re-attach 输入法（否则中文断）。
- 仍需真机验证（定义稿 §8.1 原有项）：① 搜狗/讯飞等第三方输入法是否
  发 setPreviewText，不发则预编辑层降级只显示提交串；② updateCursor

## 附：候选词为什么不接管（2026-11-03 用户提出 UI 混乱担忧后补记）

- 架构事实：客户端 @ohos.inputMethod 模块面向普通前台应用，只提供对输入
  法的控制和管理（绑定、显示/隐藏、光标与选区同步、事件监听）；键盘面板
  与候选词栏由输入法应用自己画——输入法是一个独立的
  InputMethodExtensionAbility，在自己的 Panel 窗口里渲染键盘并把结果回写
  给前台应用。框架没有给客户端提供接收或绘制候选词列表的接口。
- 因此“接管候选词”等于自建输入法：另起 InputMethodExtensionAbility，
  外加拼音解码、词库、候选排序，还要用户把系统输入法切换成它；同时丢掉
  用户已有输入法的词库、云联想与使用习惯。成本量级与首发不符，不做。
- 用户担心的 UI 混乱与 bug 是真实存在的，但根源不在候选词归属，而在
  四处，逐项有解：
  1. 键盘盖住纸面：走系统规避区，不归候选词管。软键盘是 TYPE_KEYBOARD
     规避区，用 getWindowAvoidArea 加 on('avoidAreaChange') 或
     on('keyboardHeightChange') 监听高度；setKeyboardAvoidMode 配
     OFFSET（上抬，默认）、RESIZE（压缩）或 NONE（不避让，会被盖住）。
     对打字机这种光标不断下移的场景，优先用 OFFSET_WITH_CARET 或
     RESIZE_WITH_CARET：光标位置变化也会触发避让，当前行始终可见。
  2. 预编辑串生命周期（最易出 bug 的一处）：铁律是预编辑串只显示、不进
     文档模型；finishTextPreview 到达必须清掉预编辑态；insertText 到达
     时先清预编辑串再落提交串，否则重复上屏；预编辑存在时退格由输入法
     内部消化（发新的 setPreviewText），App 不应删正文；只有无预编辑时
     deleteLeft 才删正文。把预编辑串混进文档模型就会出现重字、幽灵文本、
     光标乱跳。
  3. 光标同步：每次光标移动都调 updateCursor，选区变化调
     changeSelection；缺了它输入法感知不到编辑上下文，联想与选词上屏
     位置会错。
  4. 双通道互斥：自绘英文键盘是 App 内 UI，系统输入法是独立窗口；切换
     时必须互斥（先 hideTextInput/detach 再亮自绘键盘，反之亦然），否则
     两个键盘同屏才是真正的 UI 混乱。
- 真机验证三项（排 bug 用）：搜狗/讯飞是否发 setPreviewText（不发则降级
  只显示提交串，不会乱）；updateCursor 坐标空间；键盘避让模式下光标行
  是否始终可见。

- 分输入法逐项配置与测试（2026-11-03 用户定）：不追求一份通用结论；
  开工后真机阶段按输入法一个个测，每家单列配置与结果，维度包括
  setPreviewText 有无、预编辑显示、光标与选区同步、删除语义、回车键
  行为、键盘高度与避让。
