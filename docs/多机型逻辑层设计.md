# 多机型逻辑层设计（1930s 落地批）

> 目标：换机（1920s ↔ 1930s）时，打字视图的分层件（滚筒／中央件／拨杆／压纸卷／底座／字杆篮／字杆）全部换成当前机型的素材与几何，不再是 1920s 一套打天下。
> 事实源：1930s 素材已入仓（`layers/1930s-portable/` 7 件＋`typebar/1930s-portable-*.png` 3 件，`08aa905`）；锚点实测值见 `docs/素材分层锚点表.md` 的 1930s 节。
> 范围：本批只做 1930s 接入逻辑层（1920s 回归零像素）；1950s／1960s 素材未到，逻辑上留好口子、不硬编造。

## 2. 铁约束：`$rawfile()` 只接受编译期字符串常量

MachineCatalog.ets 文件头已写明：`$rawfile()` 只接受编译期字符串常量，组件里用 if/else 静态分支取图，**不要拼变量**。即下面这种写法是**不允许**的：

```arkts
// ❌ 禁止：运行时拼路径，$rawfile 编译期求值会失败
Image($rawfile('layers/' + this.layerDir + '/lever.png'))
```

**唯一合法写法是按 `MachineKind` 静态分支**（`CarriageStrip.ets` 已是现成范例：它接 `machineKind` @Prop，用 `if (1920s) … else if (1930s) …` 分支取各机 `carriage/*-carriage-strip.png`）：

```arkts
// ✅ 合法：静态分支，每个分支都是编译期常量
if (this.machineKind === MachineKind.PORTABLE_1930S) {
  Image($rawfile('layers/1930s-portable/lever.png'))
} else {
  Image($rawfile('layers/1920s-upright/lever.png'))
}
```

几何数（宽高比、锚点比例）是纯数字，**不受**此约束，可以进 `MachineSpec` 按机型取数。路径与几何分两条路走，不可混为一谈。

## 3. 设计原则

1. **几何进目录，路径走分支**：所有按机型变化的数字（宽高比、锚点、孔位）进 `MachineSpec` 字段，Index 从 `findMachine(machineKind)` 取数后当 @Prop 传给组件；所有图片路径用 `MachineKind` 静态分支，不拼字符串。
2. **组件不自己查全局机型**：`CarriageLayers`／`LeverLayer`／`TypebarLayer` 只认传入的 `machineKind` @Prop ＋几何 @Props，不读全局状态、不自己 `findMachine`。换机时 Index 重建传参即可。
3. **1920s 零回归**：1920s 的字段值与现行写死值完全一致；改完后 1920s 打字视图截图与改前分毫不差（平板＋手机各一遍）。
4. **1930s 先通后精**：本批先做到“换机后 1930s 分层件正确加载、位置正确、不错位、不出屏”；细部视觉（色调、压暗、阴影）后续再调，不在本批扩范围。
5. **1950s／1960s 留口子**：分支里对未到的机型走 1920s 分支（或 `CarriageStrip` 兜底），不许用 1930s 素材顶替，不许编造不存在的路径。

## 4. `MachineSpec` 新增字段（几何参数表）

在 `MachineCatalog.ets` 的 `MachineSpec` 里加下面字段（数字型，按机型取数）。1920s 的值与现行写死值一致；1930s 的值按锚点表实测值填。

| 字段 | 含义 | 1920s | 1930s |
|---|---|---|---|
| `leverAspect: number` | 拨杆图宽高比（宽÷高） | 536/2522 ≈ 0.2125 | 711/2178 ≈ 0.3264 |
| `leverPivotX: number` | 拨杆支点孔 x 比例 | 0.500 | 0.538 |
| `leverPivotY: number` | 拨杆支点孔 y 比例 | 0.952 | 0.960 |
| `bracketAspect: number` | 支架图宽高比（宽÷高） | 1105/1374 ≈ 0.8042 | 1420/1099 ≈ 1.2921 |
| `bracketPivotX: number` | 支架销钉孔 x 比例 | 0.503 | 0.519 |
| `bracketPivotY: number` | 支架销钉孔 y 比例 | 0.293 | 0.199 |
| `rollerWidthRatio: number` | 滚筒纸卷占比（W = Pw / 此值） | 0.9528 | 0.9528（暂沿用，桌面实测后修正） |
| `baseRailAspect: number` | 底座轨道图宽高比（宽÷高） | 4144/548 ≈ 7.56 | 2640/895 ≈ 2.95 |
| `basketAspect: number` | 字杆篮图宽高比 | 1878/400 ≈ 4.70 | 2679/863 ≈ 3.10 |
| `bailRollerLX: number` | 压纸卷左辊 x 比例 | 0.280 | 0.027 |
| `bailRollerRX: number` | 压纸卷右辊 x 比例 | 0.724 | 0.974 |
| `bailRollerY: number` | 压纸卷辊 y 比例 | 0.747 | 0.500 |
| `centralWindowX: number` | 中央件窗中心 x 比例 | 0.500 | 0.502 |
| `centralWindowY: number` | 中央件窗中心 y 比例 | 0.550 | 0.522 |

同时把 1930s 的三个空字符串字段填上（素材已到）：

| 字段 | 1930s 值 |
|---|---|
| `typebarRawfile` | `typebar/1930s-portable-typebar-vertical.png` |
| `leverRawfile` | `typebar/1930s-portable-lever-single.png` |

另：1930s 的 `keybandFoldRawfile` 现在指着 phone 图（`machine/1930s-portable-keyband-phone.jpg`），而 `machine/1930s-portable-keyband-fold.jpg` 文件已存在——本批顺手改指 fold 图。

## 5. 组件改造清单

### 5.1 `CarriageLayers.ets`（滚筒／字杆篮／底座／压纸卷／中央件）

- 加 `@Prop machineKind: MachineKind`（默认 1920s）。
- 6 处 `layers/1920s-upright/…` 改按 `machineKind` 静态分支（1930s 分支取 `layers/1930s-portable/…`，其余机型走 1920s 分支兜底）。
- `rollW()` 里的 `0.9528` 改用传入的 `rollerWidthRatio` @Prop（Index 从 spec 取）。
- 底座高、字杆篮高、压纸卷辊位等用到宽高比／锚点的地方，改用传入的 `baseRailAspect`／`basketAspect`／`bailRollerLX`／`bailRollerRX`／`bailRollerY` @Props。

### 5.2 `LeverLayer.ets`（拨杆）

- 加 `@Prop machineKind: MachineKind`（默认 1920s）。
- `LEVER_ASPECT`／`PIVOT_X_RATIO`／`PIVOT_Y_RATIO` 三个模块常量改成 @Prop（`leverAspect`／`leverPivotX`／`leverPivotY`，Index 从 spec 取），`leverH()`／`.height()`／`.rotate()` 的 centerX／centerY 全改用 @Prop。
- `Image($rawfile('layers/1920s-upright/lever.png'))` 改按 `machineKind` 静态分支（1930s 取 `layers/1930s-portable/lever.png`）。
- 其余不动：`REST_DEG`／`SWING_DEG` 仍由 Index 按平板／手机传入（§19.1）；触摸仍走总成层（§18.11／§18.12，拨杆自身不接手势）。

### 5.3 `TypebarLayer.ets`（字杆击打层）

- 加 `@Prop machineKind: MachineKind`（默认 1920s）。
- `Image($rawfile('typebar/1920s-typebar-vertical.png'))` 改按 `machineKind` 静态分支（1930s 取 `typebar/1930s-portable-typebar-vertical.png`，其余机型走 1920s 分支兜底——1950s／1960s 素材未到前不许编造路径）。
- 文件头注释“仅 1920s 有完整动画层，其余三台不编造动画层”改成“1930s 已接入，1950s／1960s 待素材”。

### 5.4 `CarriageStrip.ets`（不动）

已是静态分支范例，不动。本批后它只在“分层件未覆盖的机型”时作兜底（见 §6）。

## 6. `Index.ets` 改造

1. **去门控**：约 2791／2813／2856 行的 `machineKind === UPRIGHT_1920S` 条件去掉，改成“分层件已覆盖的机型”（1920s／1930s）才渲染 `TypebarLayer`／`CarriageLayers`；1950s／1960s 仍走约 3136 行的 `CarriageStrip` 兜底（素材未到，不硬上分层）。
2. **传参**：`CarriageLayers`／`LeverLayer`／`TypebarLayer` 调用处加 `machineKind: this.machineKind`，并把 §4 的几何字段从 `findMachine(this.machineKind)` 取出当 @Prop 传入（`leverAspect`／`leverPivotX`／`leverPivotY`／`bracketAspect`／`bracketPivotX`／`bracketPivotY`／`rollerWidthRatio`／`baseRailAspect`／`basketAspect`／`bailRollerLX`／`bailRollerRX`／`bailRollerY`／`centralWindowX`／`centralWindowY`）。
3. **定位公式改用机型值**：
   - `bracketH()`：`bracketW() / 0.8042` → `bracketW() / spec.bracketAspect`。
   - `pinXRel()`：`0.503 * bracketW()` → `spec.bracketPivotX * bracketW()`。
   - `pinYRel()`：`0.293 * bracketH()` → `spec.bracketPivotY * bracketH()`。
   - `leverHForDrag()`：`leverW() / (536/2522)` → `leverW() / spec.leverAspect`。
   - 约 2899 行拨杆 offsetYVp 里的 `(leverW()/(536/2522)) * 0.952` → `(leverW()/spec.leverAspect) * spec.leverPivotY`。
   - 约 1089 行 `paperWidthVp / 0.9528` → `paperWidthVp / spec.rollerWidthRatio`。
4. **其余不动**：`applyMachine()`／`reloadKeymap()`／换机落盘流程不动；`useLayers` 开关不动；§18.11／§18.12 的总成层手势（拖拽＋点按）不动——它接的是总成层位置，与机型素材无关。

## 7. 实施顺序

1. `MachineCatalog`：加 §4 字段、填 1930s 三字段、1930s `keybandFoldRawfile` 改指 fold 图。
2. `LeverLayer`：@Prop 化＋静态分支（最小、最独立，先做先验）。
3. `CarriageLayers`：@Prop 化＋静态分支。
4. `TypebarLayer`：静态分支＋注释更新。
5. `Index`：去门控＋传参＋定位公式改用机型值。
6. 回归＋验收（见 §8）。

## 8. 验收（识屏为准）

- **1920s 零回归**：平板＋手机各打 5 行中文＋换行／退行／换纸，截图与改前分毫不差（拨杆位置、滚筒、中央件、底座、字杆篮位置逐像素对）。
- **1930s 接入**：换到 1930s 后打 5 行中文，截图确认——拨杆／滚筒／中央件／压纸卷／底座／字杆篮全是 1930s 素材（不是 1920s 的）；拨杆支点对位正确（拨杆绕支架销钉孔转，不飘）；底座不出屏、不压键盘；换行／退行／换纸正常；切回 1920s 后一切复原。
- **1950s／1960s 兜底**：换到这两台，打字视图仍是 `CarriageStrip` 静态条（不崩、不白屏、不显示 1930s 素材）。
- **平板／手机各一遍**：§19 的手机分支保护仍在（手机系数、ROLLER_K、maxTravel 不动）。

## 9. 禁忌

- ❌ 不许拼变量取图（`'layers/' + dir + '/lever.png'`），`$rawfile` 编译期常量是铁律。
- ❌ 不许把 1930s 素材当 1950s／1960s 的顶替。
- ❌ 不许为省事把 1930s 几何数写死成新常量（那只是把 1920s 写死换成 1930s 写死）；一律进 `MachineSpec` 按机型取。
- ❌ 不许动与机型无关的量（行高、travelPerChar、ROLLER_K、拨杆角度、§18.11／§18.12 手势）。
- ❌ 不许改 `CarriageStrip.ets`（它是静态分支范例，动它等于动口径）。
