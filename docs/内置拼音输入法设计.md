# 内置拼音输入法设计（回车 CarriageReturn）

**本稿为内置拼音输入法的事实源。** 界面重设计稿 §7.2 的中文输入部分以本稿为准：原“双通道”（英文自绘键／中文系统输入法）改为“三通道”——英文自绘键、中文系统输入法、中文内置拼音。

## 0. 决策

- **双线共存**：系统输入法通道保留；**内置拼音为默认引擎**（2026-11-07 用户拍板）。
- 内置拼音既是默认体验也是补充措施：系统通道是 fallback，设置里一 tap 切回。
- v1 范围：全拼输入、候选栏、组词状态机、词库管线、引擎单测。**不做**：模糊音、用户词库持久化、长句预测、双拼／九键、云端联想。
- 背景结论（不再论证）：系统输入法引擎路线走不通——IME Kit 客户端 API 无候选词查询、无向输入法发按键的接口；`customKeyboard` 是替换系统键盘不是前端；`attach(false)` 藏了键盘就没了输入源。唯一可行路线是 App 内自建拼音引擎。
- 质量预期（先说清楚）：v1 弱于华为／搜狗输入法——词库小、无云端、无长句预测、无模糊音、无自学习持久化。换来的是全程无系统键盘、候选栏长在打字机里、全离线、风格统一。

## 1. 模式与切换

- `langZh` 不动（中／EN 语言切换）。
- 新增 `cnEngine: 'builtin' | 'system'`，持久化进 `AppPreferences`（补 `getString`／`setString` ＋ `PrefKeys.CN_ENGINE`），默认 `'builtin'`。
- 设置页加“中文输入”行（放在“删除方式”之下），点切内置／系统。**必须走 AppPreferences 持久化**，不许用页面内部 `@State`——设置页其余开关不持久化是已知缺口，本行不许重蹈。
- `applyChineseMode(on)` 按引擎分叉：system 走现有 attach 通道；builtin 不 attach、不弹系统键盘、显示候选栏、键区当拼音键盘。
- 悬浮 A 键只在 system 模式出现（builtin 没有系统键盘盖住底行，不需要它）；`kbShift` 只在 system 模式有意义，builtin 下恒为 0。
- `leaveChinese()`：builtin 下先按 §4 退出规则提交首选候选，再清组词、关候选栏。

## 2. 词库

### 2.1 来源（v1）

| 来源 | 许可 | 作用 |
|---|---|---|
| jieba `dict.txt` | MIT | 词表＋词频（约 34.9 万词），候选排序的燃料；取词频前约 8 万词 |
| pypinyin／phrase-pinyin-data | MIT | 约 4.7 万条人工校对的词组读音，纠多音字（重庆、音乐、银行） |
| pinyin-data／Unihan `kMandarin` | MIT／Unicode License v3 | 单字读音表，兜底覆盖 |

- 此溯源链与 2026 年新输入法 inputx-pinyin（MIT／Apache 双许可）公开的 attribution 表一致。
- **不用**：rime-ice 整包（GPL-3.0-only，进不了 MIT 仓）；搜狗细胞词库（专有）；libpinyin 二进制模型（LGPL 且只有 C++ 实现，无干净文本数据）；qingjian（GPL-3.0）；HanLP（Apache 2.0 但无独立拼音词库文件）；THUOCL／八股文（2016 年左右老数据、无拼音，已降为备份）。
- 许可细则：单字读音以 Unihan 为主源；pypinyin 只取词组读音覆盖层；CC-CEDICT v1 不进仓（可作构建期交叉校验，不分发）。
- CC-CEDICT（CC BY-SA 4.0，12.35 万条、带声调读音、无词频）为 **v1.5 可选精度补充**，不进 v1。

### 2.2 管线

- 脚本：`tools/build-pinyin-dict.py`（Python 3，只用标准库＋pip 装 pypinyin；不用 pip 就改走 phrase-pinyin-data 与 pinyin-data 两个仓库的原始数据文件，任选一种，提交里写明选了哪种与为什么）。
- 步骤：下载三源（钉版本＋SHA-256）→ 解析 jieba 词频 → 每词读音：pypinyin 词组覆盖优先，否则单字主读音拼接 → 按词频排序截前 8 万 → 输出两 JSON → 写 `DICT-ATTRIBUTION.md`（来源、许可、版本、SHA-256，与 `SOUND-ATTRIBUTION.md` 同格式）。
- 输出：`entry/src/main/resources/rawfile/dict/pinyin-words.json`（`{拼音串: [词...]}`，数组即词频序）与 `pinyin-chars.json`（`{音节: [字...]}`）。体积预算：字表 ≤400KB，词表 ≤2.5MB；超了先截词频尾部，不改格式。
- 加载：字表启动时异步加载；词表首次进内置中文模式时懒加载；加载失败不崩，只退单字候选＋候选栏提示“词库加载失败，仅单字”。加载方式复用 `KeymapModel.ets` 的 `readRawTextSync` 范式（词库 JSON 用异步版读，不许在主线程同步解析几 MB）。

## 3. 引擎

- 新文件 `entry/src/main/ets/services/PinyinEngine.ets`：`PinyinEngine` ＋ `PinyinSession`。**纯 TypeScript，不引任何鸿蒙 API、不含 `@State`／装饰器，同一文件必须能在 Node 下跑单测。**
- 数据：音节表（约 420 个合法音节）、`charMap: Map<音节, 字[]>`、`wordMap: Map<拼音串, 词[]>`（数组已按频排好）。
- 切分：输入字母串 DP／回溯拆音节（最长音节 6 字母）；每种切分查词表；候选＝词＋单字回退，按频取前 N。
- 排序：词频预排序＋用户选词提频（L0，v1 只记内存）。
- 模糊音 v1 不做；扩展点：切分时音节展开走一张 `fuzzyMap`，以后加模糊音只换表不重构。
- 性能口径：精确 Map 查＋DP，每击键远低于 1ms；FST 不需要（40 万条前缀搜索才需要，我们只要精确键查）。

## 4. 状态机与按键语义

- `PinyinSession` 三态：空闲 → 组词中（有拼音串）→ 选词后剩余字母继续组词。
- 拦截点：`Index.ets` 的 `onCapDown`；`queueChar`／`commitChar`／`onDelete`／`onNewline` 全部复用。
- `v` 是 ü（`lv`、`nv`）。

| 按键 | 组词中 | 组词为空 |
|---|---|---|
| 字母 a–z | 追加拼音串，重新切分，候选栏刷新；预编辑串复用 `cnPreview` Span（浅色＋下划线） | 开始组词，不落字 |
| 退格 | 删最后一个字母 | 走现有 `onDelete` |
| 空格 | 选首选候选 | 走现有空格直通 |
| 数字 1–9 | 选第 N 个候选 | 正常落数字 |
| 数字 0 | 下一页候选 | 正常落 `0` |
| 换行 | 先把拼音串按原样上屏（`nihao` → 拉丁字母 `nihao`），下一次换行才是真换行 | 走现有 `onNewline` |
| Shift＋字母 | 先提交首选候选，再按原样打大写字母（中文里插英文的逃生口） | 现有 Shift 行为 |
| 字符键／中 EN 切换／换纸／换机／离页 | **统一规则：退出组词时提交首选候选**（换行除外），绝不丢已敲字母 | — |
| 点候选词 | 走 `enqueueChinese`（40ms 逐字落字）；只消耗该词覆盖的音节，剩余字母继续组词（`nihaoma` 选“你好”后 `ma` 留下） | — |

## 5. 候选栏 UI

- 新组件 `components/CandidateBar.ets`：一排候选词（点选）＋ `‹` `›` 翻页，高 44–48vp，放在 FontBar 与 PhotoKeybed 之间（标准输入法候选栏在键盘正上方）。
- **空间常驻**：内置中文模式下 44vp 一直占位（无组词时栏是空的），不许随组词出现／消失伸缩——否则键盘上下跳、纸面跟着跳。英文与 system 模式不占位。
- 数字键 1–9 与栏内序号对应；翻页键同步。

## 6. 与现有通道的关系

- 复用点：`PhotoKeybed`（拼音键盘壳）、`cnPreview`（预编辑显示）、`enqueueChinese`／`commitChar`（落字）、`onDelete`／`onNewline`（删除／换行）、`readRawTextSync`（词库加载范式）。
- 系统通道保留：`ChineseInput.ets` 不动；其 9.5 两 bug 修复已落地（`e7543c4`、`14db253`：订阅累积修、多重输入修，实测 +2 无重复）；退格键位仍未定位（`52798e1`，自动化注入找不到退格键位，用户手测仍须覆盖中文退格）。
- 两通道不许互相改对方状态；builtin 下绝不 attach、绝不 focus `cn_anchor`。
- 仓内 `AGENTS.md` 的“中文输入”一节里“禁自建拼音候选行”一句自本稿起作废（仅适用于系统通道时代），其余系统通道规则继续有效。

## 7. 持久化

- `AppPreferences` 补 `getString`／`setString`；`PrefKeys.CN_ENGINE`，默认 `'builtin'`。
- 用户词库 v1 不持久化（只内存提频）；v1.5 再落盘。

## 8. 测试

- Node 单测（引擎纯 TS，`node --test`）：切分（`nihao`、`xian`、`shanghai`、`zhongguo`、`nvhai`、`nih` 不完整、`xyz` 无效）、排序（`nihao` 首选你好）、选词余量（`nihaoma` 选“你好”后剩 `ma`）、多音字（重庆、音乐、银行、行、乐、长）、每击键耗时（p95 <1ms，语料为常用词组表）。
- 对照基准（推荐不强制）：inputx WASM（npm `@goliapkg/pinyin`）在 Node 里跑同一语料的前 5 候选对照，报告一致率与可解释差异；跑不通不许停工，写清原因与替代证据。
- 真机验收（第 4 批）：打一句中文全流程、退格／空格／数字／换行语义、引擎切换、英文回归、system 模式回归。

## 9. 分批

1. **词库管线**：脚本＋两 JSON＋`DICT-ATTRIBUTION.md`；验收＝体积、许可、抽查（`nihao→你好`、`zhongguo→中国`、`xian→西安／先`）。
2. **引擎**：`PinyinEngine`＋`PinyinSession`＋Node 单测；不碰 UI、不碰 Index。
3. **接线**：`CandidateBar`＋`onCapDown` 拦截＋设置行＋持久化＋`applyChineseMode` 分叉。
4. **真机验证＋打磨**。模糊音、用户词库持久化、CC-CEDICT 补充排 v1.5。

## 10. 已知限制

- 多音字 v1 只取每字最常用读音＋pypinyin 词组覆盖；未覆盖的多音词可能读错（候选里仍有正确词可点选，但首选可能不对）。
- 词表截到约 8 万词后，生僻词、网络新词可能查不到（单字回退仍可逐字打出）。
