### 出入（与稿不符，逐项）

1. **1920s 缺预切 `carriage-strip.png`**：三台新机都有，1920s 没有。按 §2.1 的 45%–59% 带从 `carriage-layer.png` 现切（2048×287，与其余三台同规格），未改上游 assets/。
2. **§2.1 与 §9/§8.3 对「hero 底」的表述冲突**：§8.1 明写「hero 主屏已不用整机舞台」，§2.1 的无机器段纵向构成也证实主屏不放整机图；§9 表格却写「分层舞台：hero 底 + …」。按 §2.1（尺寸钉死、"不许加段"）执行：主屏不放 hero，分层舞台 = 纸面 + 字车条 + 字杆/拨杆层（第 4 步接入）。请确认。
3. **「纸的上缘被字车条压住 8vp」与纵向顺序矛盾**：表格顺序是 纸面 → 字车条，物理上字车条在纸面下方。按表格顺序实现（字车条压住纸面**下缘** 8vp）。
4. **字体条显示名**：稿只写「当前字体名」，实现取字体专名（如 Courier Prime）而非 familyName；字体专名不翻译，未走 string.json。
5. **本步键盘仅静态**：照片键区与功能行只铺外观，触摸命中、键帽叠字、中英切换在第 3 步接入；纸面舞台与行内光标在第 2 步重做。
6. **HAP 体积 96 MB**：17 款字体 74 MB + 素材，属 §8.4「17 款全部进换装字体区」的必然代价。
