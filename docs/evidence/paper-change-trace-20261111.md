## 3. 600ms 去向分解（以 R1-1 为例，单位 ms）

```
t=0      start（入口）
t≈5      step1（第一段 animateTo 调用，立即赋终值）
t≈306    step1-settled（300ms 定时器实际到达；漂移 +6）
t≈308    step2-work：clear 0 + syncRows 1 = 1ms
t≈309    step2-hide（新纸藏到滚筒处）
t≈318    step2-begin（第二段 animateTo 调用）
t≈639    end（320ms 定时器实际到达；相对 step2-begin +321，漂移 +1）
```
**合计 639ms ≈ 300（第一段定时器）＋约 12（同步工作＋hide/begin 调用开销）＋320（第二段定时器）＋约 7（调度）**。
定时器漂移：第一段 300ms 定时器 +4～+9ms；第二段 320ms 定时器 +1～+6ms（由 end 与 step2-begin 差推得）；**总漂移 +13～+26ms**（相对名义 620）。

## 4. 结论（按设计稿 §6 口径）

* **主判据：15/15 次 end dt 633–646ms，全部 ≤1000ms；无一次缺 end 行（锁均释放），无任何 start→end ≥8000ms 的样本。**
* **"8–11 秒"在当前版本未复现。** 旧版本根因无数据可考（PAPER_CHANGE_TRACE 自第 0 批起为 false，历史无样本），保留打点继续观察。
* **未达到"阶段异常"标准**：任何阶段都没有超出期望值 3 倍且绝对超 1000ms 的情况（step1-settled 最大 309ms，step2-work 最大 2ms，end 最大 646ms）。
* **resume 说明**：resume dt = end＋约 200–320ms；其中包含 `uitest uiInput click` 的派发延迟（约 0.2–0.3s），即"操作员立即按键"的上界；不构成复现判据（设计稿 §6）。
* 打点保持默认 on，作为长期观测留在代码里。
