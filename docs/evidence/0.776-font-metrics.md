# 0.776 比值：字体文件实测结论（2026-11-05 round4）

## 实测方法（无需构建，直接用 fontTools 读 rawfile 里的 ttf）
路径：`entry/src/main/resources/rawfile/font/CourierPrime-Regular.ttf`

## 结果
- `post.isFixedPitch = 1`
- `unitsPerEm = 2048`
- i / m / V / a / b 的 advance **全部 = 1228 units = 0.600 em**

## 推论
1. **字体文件本身没问题**，是标准等宽 Courier Prime。
2. 按 0.600 em 计算，fontSize=17vp 时每字 advance 应为 **10.20vp**。
3. 但 MeasureUtils 实测 `i=4.15 / m=14.52`（3.5 倍，比例字体）——**说明 MeasureUtils 量的不是这个字体**，
   即 `registerFont` 三种方式全都未生效（与原假设「未注册 → 注册即修」不符：注册了也没用）。
4. 纸面用户实测 pitch `8.74vp`。若用 Courier Prime，`8.74 / 0.600 = 14.57vp` 等效字号；
   而 `this.fontSizeVp = 17`。即纸面 Text 的**有效字号约为 14.57vp，不是 17vp**（比例 0.857）。

## 结论（两个独立缺陷）
- 缺陷 A：`registerFont` 注册的族名未进入文字系统（MeasureUtils 仍量到系统比例字体）。
- 缺陷 B：纸面 Text 的有效渲染字号 ≈ 0.857 × fontSizeVp，与 `fontSizeVp` 不一致。

`0.776` 是这两个缺陷叠加的表观比值，不是单一缩放。
