### §0.2 Foldtype 模式的准确描述（屏幕就是机器）

五张参考图只学设计语言，不抄它的图。五张图共同的模式是：

1. **屏幕本身就是机器，没有"机器的照片"。** 折叠半开薄荷绿款（`1000266117_12_npyx.png`）与黑色款（`1000266111_13_sfco.png`）：上半屏就是纸（纸是一个 UI 面板，上面是打出来的文章），下半屏就是按键网格，中间的字篮只是一个平面图形。整块屏幕就是一台机器，里面没有任何一台打字机实物的照片或三维渲染。
2. **纸是 UI 面板。** 纸面特写（`1000266114_14_5na8.png`）：纸占满上半屏，纸下是带刻度与两个红色页边三角的横尺，横尺下是齿状边。纸的边缘、横尺、页边标记都是 UI 元素，不是机器零件的照片。
3. **平板整屏就是一台打字机**（`1000266108_15_s6k3.png`）：纸在上、字篮在中、键盘在下，全部是屏上的 UI，一套配色、一种材质语言。
4. **实体键盘是后话**（`1000266105_16_18aa.png`）：平板显示纸＋字篮，面前放一把实体键盘。本稿不采纳实体键盘（§11 Q5 已定），只记录为后续项。

本稿把这一模式翻译成可执行的定义：打字机页自上而下是五个 UI 区——顶栏（App 铬，不属于机器）→ 纸区（纸面板＋横尺＋落字导件＋拨杆控件＋旋钮控件）→ 字篮区（扁平扇形图形）→ 功能行 → 键盘区（单套按键网格）。键盘区内含候选栏（第六条输入带，中文模式 44vp 常驻占位，§5.1.5；英文模式留空）。五个区共用一套配色、同一光影方向、同一圆角口径（§2），拼在一起就是一台机器，不需要任何一张机器照片来"证明"它是一台打字机。

## §1 目标与范围

### §1.1 "App 本身就是打字机"的六条可验收定义

"一体"不再由"机器照片拼得像不像"判定，改由以下六条判定（每条都可在拼合截图上验收）：

1. **屏幕即机器**：打字机页上没有任何一张机器照片、三维渲染或机器零件的拟物图片。纸、键、字篮、色带、横尺、拨杆、旋钮全部是 UI 元素（ArkUI 组件／生成的图片贴片／代码画的几何标记——落字导件是唯一的矢量例外，§7.2）。验收：拼合截图上逐区检查，出现机器照片即 FAIL。
2. **五区一屏**：自上而下是顶栏（App 铬）→ 纸区 → 字篮区 → 功能行 → 键盘区，五个区共用一套配色、同一光影方向、同一圆角口径（直角，缺省）。验收：五区拼合门图接缝区像素差 ≤30（沿用 21 号稿 §2.1 的口径）。
3. **纸是面板**：纸面板是屏幕上的一个 UI 面板，打出来的字是面板里的 Text，不是贴在机器照片上的文字。验收：纸面板与机身面板的边界是一条 UI 分界线（颜色／阴影），不是一张照片的边缘。
4. **键是按钮**：键盘区只有一套键盘，键帽是真正的 Button，图例是 Button 里的真文字。验收：Shift／Backspace／Return 等长标签完整显示（"hift"、"Shif"、"Sh" 一律 FAIL）；点按任一键帽有按下态（§2.3）。
5. **落字点恒定可指**：落字导件在机器几何中央（`archFixX = stageW / 2`，§11 Q4 已定），写实模式下每字都落在导件下（drift ≡ 0，±2vp，§4.2）。验收：连续打字截图上光标 x 与导件 x 的差 ≤2vp。
6. **折叠不断**：半开桌台态上纸下键，铰链是两区的界，没有任何一个 UI 元素横跨铰链；折叠／展开只触发布局变化，文档／光标／纸位全部保留（沿用第 7 批 F7 口径）。验收：三态截图＋状态保留检查。

## §2 质感标准（用户硬要求 ①，单独成节，可验收）

用户原话"整体细节方面的质感一定要做到位"的可执行翻译：扁平 UI 的质感不靠"画一台机器"来冒充，靠**每一件 UI 元素的材质表达**做到位。本节每条都有验收方法，不写"差不多就行"；验收只写"做到什么算过"，证据抓不到用替代证据继续做并在提交里写明不符点（桌面端提示词铁律，不在本稿重复）。

### §2.1 质感总则（六条硬线，沿用 21 号稿 §2.1，形态改成 UI 件）

| 维度 | 规范 | 验收方法 |
|---|---|---|
| 材质 | 金属／皱纹漆／塑料按时代原型区分质感（风格板 §4 已定），但质感只通过**均匀的表面颗粒＋渐变**表达，不通过破损表达；扁平 UI 里材质感来自三样东西：表面颗粒、边缘高光、按下态的阴影变化 | 目视＋质检清单（§10.3） |
| 光影 | 柔和顶光，方向固定**左上**，色温基准 **5500K**；所有 UI 件共用同一光源方向与色温：高光永远在左上、阴影永远在右下；纸面受光均匀 | 全批共用同一光影参数（§7.3），拼合后门图接缝区像素差 ≤30 |
| 色彩饱和度 | 沿用 21 号稿 §2.4 色板（纸 #eee4ce、机身黑 #312b24、键帽米白 #dbccb3、金属高光 #beb4a8、各机机身色），新 UI 件取色落在色板值 **±10%** 内 | 脚本量测（§10.3）：契约文件登记每件 3 个采样点相对坐标，`tools/check-part-colors.py` 读像素 RGB，逐通道与色板值比对，任一通道偏差 ＞10% 即 FAIL |

### §2.2 纸面板的质感（纤维、受光、卷边）

1. **纤维**：纸面用生成的纸纹理贴片（`rawfile/ui-parts/` 下的 `paper-{kind}.png`，§7.4），纤维可见但不抢眼，颗粒对比度 ≤15%（§2.1 纹理强度行）。纸纹现状干净（21 号稿已核：纸张照片无脏做旧），纳入标准件时**不重生成**，只补几何契约与色温校验（沿用 21 号稿 §3.2 #4 的处置，形态从"照片"改成"贴片"）。
2. **受光均匀**：纸面不受机身阴影污染——纸面板自带一块均匀的受光面，亮度自上而下衰减 ≤5%（脚本量测：纸面板上下两排采样点亮度差／均值 ≤5%，超了即 FAIL）。纸面板与机身面板之间有一条 1vp 的软阴影分界（纸浮于机身之上 1 层，不是贴死）。
3. **卷边**：纸面板顶边有一条卷曲阴影（顶边 6vp 内亮度渐暗 8–12%，矢量渐变实现，不 baked 进纸纹），表示纸从上方卷过来；纸顶卷曲是渲染效果，不 baked 进纸纹（沿用 21 号稿 §3.2 #4 的口径）。卷边固定在纸区顶缘、恒可见（纸从顶缘卷入的视觉标记，不随纸面板移动——R-m10）。
4. **文字是代码画的**：纸面文字一律 ArkUI Text（Courier Prime 等宽字体，沿用现行字体口径），不 baked 进纸纹；行距＝行高 lineHeightVp，字号＝fs（§4.1 公式）。

### §2.3 键帽的质感（厚度、倒角、高光、按下态）

键帽是本稿质感要求最严的一件——它是用户每天摸的东西，也是"hift"问题的案发地。

1. **厚度**：键帽不是一块扁色块。帽面＝顶面（键帽米白 #dbccb3，图片贴片 keycap-face，§7.2）＋侧壁（比顶面深 12–18% 的同色）＋底边 1vp 阴影。侧壁与底边阴影用 ArkUI 叠层实现（Button 背景＋内阴影），帽面用图片。
2. **倒角**：帽形分两种变体（§3.5）：圆角矩形（缺省，倒角半径＝帽宽的 12%）与圆形（1920s 圆帽变体，帽形为圆）。倒角半径是契约参数，写进契约文件，不许每帽一个值。
3. **高光**：每帽顶面左上有一条 1vp 的高光边（金属高光 #beb4a8，不透明度 60%），光源方向全键盘一致（左上，§2.1）。高光 baked 进帽面图（按下态图里高光变暗 30%，§2.3 第 4 条）。
4. **按下态**（逐帽对应，第 13 批 ① 的口径沿用）：按下时换按下态图（keycap-pressed，§7.2）、帽面下沉 2vp、底边阴影收掉、高光变暗 30%、同时触发打击（§4.3 的 snap 打击，约 85ms）。松开 70ms 内回弹（出处待批 1 核对：与删除弹簧 70ms 同数，疑似混用）。验收：慢速点按截图上按下帽与相邻帽的 y 差＝2vp ±0.5vp；快速连打 20 字 0 丢字 0 双落（沿用第 17 批的验收口径）。
5. **图例是真文字**：图例是 Button 里的 Text，字号按帽宽自适应（"Shift"、"Return"、"Backspace" 三个长标签在批 1 用真机截图验完）。"hift"、"Shif"、"Sh" 一律 FAIL（§1.1 第 4 条）。**结构保证**：图例不再是"照片＋代码叠字"两层，叠字层随 PhotoKeybed 退役一并删除（§8），"hift"式截断的结构根因已消除；长标签放不下仍可能由帽宽不足引起——缩字号／换短文案／宽帽三选一仍待用户定夺（13 号稿待定夺 #2），本稿不预设缩字号口径，批 1 只验真机截图、不代判。

### §2.4 字篮图形的质感（金属渐变与刻线）

1. **形态**：扁平扇形（效果图 01 式，§11 Q12 缺省 (a)），扇形由 43–58 根字杆刻线组成（根数与蓝图 `basketAspect` 一致：1920s 43／1930s 58／1950s 49／1960s 52，沿用现行键帽数口径——字杆数与键帽数一致是真打字机的结构，沿用）。
2. **金属感（分两档，Q12 已按缺省 (a) 线稿档执行）**：(a) 线稿档（Q12 缺省 (a)）：细刻线为主、填充极淡或不填；(b) 金属渐变档（Q12 (b)）：扇面用两段线性渐变（金属高光 #beb4a8 → 机身中调 #574d43，自上而下），刻线是 1vp 的深色线（不透明度 70%），扇面下缘有一条 2vp 的底边阴影。扇形图是图片件（basket-fan，§7.2），渐变与刻线 baked 进图；(a)／(b) 是两个变体（各出图，缺省 (a)）。
3. **字篮是打击动画的动件（不是静态件）**：字杆绕左右向水平枢轴旋转、正面看纵向缩短（§4.3 的 snap 打击）；16 号稿 §12 Q6"字杆击打视觉保持不画"与 17 号稿"`typebarAngle` 恒 55°，无可见摆动"已被用户 2026-11-16 23:51 直接指令推翻（用户直接指令高于旧定案），本稿不沿用。打击的视觉反馈在三处：键帽按下态（§2.3 第 4 条）、字杆摆起与色带抬起（§4.3）、落字字符在撞击帧干净出现（§4.3）。扇形底图本身不动，动的是字杆。

## §3 标准件系统（用户硬要求 ②，核心）

### §3.1 标准件的定义（沿用 21 号稿 §3.1，形态改成 UI 件）

一个标准件 = **一个 UI 件** ＋ **几何契约** ＋ **材质 token** ＋ **变体维度** ＋ **动画行为** ＋ **交互 affordance**。六者缺一不可：只有图没有契约的是旧素材（现状）；动画／交互两栏空着的件视为未完成（整体设计要求，2026-11-16 20:21 用户立规）。

- **UI 件**：该件是什么 ArkUI 元素（Column／Button／Grid／Image／Path）＋哪部分是生成的图片（§7.4）＋哪部分是代码画的（矢量层，仅落字导件例外与生成失败占位，§7.2）。不许出现"机器照片"形态的件。
- **几何契约**：该件在蓝图坐标系里的尺寸（vp）、锚点（以哪个点对齐）、与相邻件的对齐关系（边对边／中心对中心／间距 vp 数）、z 序（谁压谁）。
- **材质 token**：该件的材质名＋色板值（§2.1 的色板子集），变体只换 token 不换几何。
- **变体维度**：该件可换的维度（如纸面板：纸纹；键帽：帽形／帽色；机身面板：配色），每个维度列出可选值。
- **替换规则**：换一个件不破坏整体——新件必须满足同一几何契约与同一光影规范（§2.1），否则不许入库。
- **动画行为**：该件在打字／换行／换纸／切机／模式切换时如何动——动什么量、跟谁走（跟 O 还是固定）、时序（§4 的时序表）。
- **交互 affordance**：该件接受什么手势／点按、命中区（几何＋随 V 的变化）、反馈（视觉／声音／震动）。不接受手势的件写"不接受手势"并写理由（装饰面／纯视觉件），不许留空。

契约文件落位：`entry/src/main/ets/model/PartContract.ets`（新建，纯数据，可 Node 单测）＋ `docs/标准件契约表.md`（新建，人读版）。每件的契约含六项（通式见 21 号稿 §3.3，本稿只改第一项的形态与 z 序映射）。

**z 序（新 UI，不再是 Canvas 三层）**：机身面板 0 → 纸面板 1 → 色带条 1（与纸面板同层、后绘制，平时藏在落字点下方、抬起时盖在纸面上）→ 横尺 2 → 落字导件 3 → 字篮图形 4 → 功能行 5 → 键盘网格 6 → 拨杆控件 7 → 旋钮控件 7 → 候选栏 8（候选栏出现时在最上层，沿用现行口径）。数字越大越上层。ArkUI 实现：Stack 内按此顺序挂载，后挂载的在上层。

**布局常量（不随新 UI 件变）**：`lineHeightVp = fs × (30/17)`（行高与语言解耦，沿用现行口径）、纸张长宽比 `Ph = Pw × 1.414`（A 系纸，沿用）。新 UI 件按此比例出图，批 1 验收核对符合度（偏差 ≤2%），不符合打回重生成，不改公式。

**纸区高度**：`H_paperZone` 由批 1 五区分配实测登记（§3.2.1 的分配规则），取代旧 `carriageHeight`（Hc）——旧 Hc 在新方向下无定义（R-M3）；`knobD`／`perLineDeg`／拨杆几何的 Hc 依赖在批 1 重算表里按新定义重算。

### §3.3 每个标准件的接口契约（通式，逐件实例见 §3.2 表＋实施批的契约文件）

每件的契约含六项：

1. **几何**：`xVp／yVp／wVp／hVp`（蓝图坐标系，手机／平板两档由蓝图换算，不硬编码两套数）、`anchor`（锚点：如纸面板锚 paperBaseX、键盘网格锚 keyGridTop）、`align`（与相邻件的对齐关系，如"字篮底缘与功能行顶缘重合 0vp"、"横尺与纸面板同视觉位移 V"）、`z`（z 序：机身面板 0、纸面板 1、色带条 1（后绘制）、横尺 2、落字导件 3、字篮图形 4、功能行 5、键盘网格 6、拨杆控件 7、旋钮控件 7、候选栏 8）。
2. **材质 token**：`material`（如 `black-metal-matte`／`crinkle-grey`／`cream-plastic`／`lightgrey-plastic`，沿用 21 号稿 §3.3 的 token 名）＋ `color`（色板值，§2.1）＋ `finish`（0 级，§2.1）。
3. **变体维度**：每件列出可换维度与可选值（如机身面板：`colorway ∈ {1920s-black, 1930s-grey, 1950s-cream, 1960s-lightgrey}`；键帽：`capShape ∈ {rounded-rect, round}`、`capColor ∈ {ivory, dark, cream, lightgrey}`；纸面板：`texture ∈ {letter, manuscript, postcard, memo}`——已有）。
4. **替换规则**：新件入库必须满足：① 几何契约逐项对齐（偏差 ≤1vp）；② 光影规范（§2.1 左上顶光、5500K）；③ 色板 ±10%（§2.1）；④ 无 baked 文字（键帽图例一律 Button 里的 Text，纸面文字一律 Text）；⑤ 无品牌／型号／logo（风格板 §8 已定）。五条全过才入库，否则打回重生成。
5. **动画行为**：该件在打字／换行／换纸／切机／模式切换时的运动——动什么量、跟谁走（跟 O／固定／跟 V）、时序（§4.3 的时序表）；逐件填表见 §3.2 第 5 列；**动画数字的推导式**（如导件位 archFixX＝stageW／2、纸基线 paperBaseX＝archFixX－marginH）写进契约文件，不写死数字（数字待批 1 按本节重算）。
6. **交互 affordance**：该件接受的手势／点按、命中区（几何＋随 V 的变化公式）、反馈（视觉／声音／震动）；逐件填表见 §3.2 第 6 列；不接受手势的件写清理由，不许留空。

**键帽中心是硬契约**：键盘网格的帽心相对坐标（xRatio／yRatio）与 keymap 的 `CapDef` 逐帽对应（`PhotoKeybed.ets` L181 的 hitAt 定义——退役时该逻辑原样迁入新 KeyGrid 组件，§8）。新键盘网格的帽心偏差 **≤2%**（相对坐标），超出即重测 keymap——不许"差不多对齐"。帽心不从图片反推：出图方在契约文件登记帽心相对坐标，与 keymap 的 `CapDef` 比对，偏差 ≤2% 即过（量测口径见 §10.3）。

### §3.4 自由搭配的粒度与约束（沿用 21 号稿 §3.4，Q3(a) 已定：全自由搭配）

**粒度**：以**区域**为单位换变体（一次换一个标准件的一个维度）。例如：只换键帽的帽色、只换机身面板的配色、只换纸面板的纹理——换一件，其余九件不动。

**跨机型混搭**：(a) 全自由搭配——跨机型任意组合（**已定**，21 号稿 Q3(a)，用户 2026-11-16 21:07 点选），只作两道校验，不作人工限制：

1. **几何校验**：新件的几何契约必须与当前蓝图对齐（偏差 ≤1vp），不对齐不许装（不是"不建议"，是装不上——契约文件里写死）。
2. **色温校验**：新件取色必须在 §2.1 色板 ±10% 内；超出时换装页提示"色温不匹配"，用户仍可强制装（只提示、不拦截——用户要的就是自由搭配，拦截违背定案）。

**为什么全自由不会重新割裂**：割裂的根因是各件光影材质各行其是（21 号稿 §0.3 证据 3／4），不是"件来自不同机型"。本稿所有变体按同一光影规范（§2.1）与同一色板生成，任意组合仍满足 §1.1 的六条一体判定。反之，若限制"同机型内搭配"，等于把"四机完全独立"的蓝图边界误用到素材搭配上——蓝图独立说的是代码零引用，不是用户不许混搭。

**不允许的组合（只有两条，都是结构性的）**：

- 同一区域一次只装一个变体（不许叠加两个机身面板）。
- 横尺件只在有纸时显示（无纸空态不画横尺——横尺是纸的附属件，不是机身件）。

除此之外无不允许的组合；实施批不许擅自加限制，加一条须回 EGM。

### §3.5 标准件与蓝图的关系

- 蓝图（`machines/<机型>/`）仍是"一个机型＝一个蓝图＝独立目录"（多机型逻辑层 §10–§14 已定，不动）：蓝图持有该机型的**缺省搭配**（10 个件的缺省变体）与几何参数（`MachineSpec` 的 `leverAspect`／`bracketAspect`／`rollerWidthRatio`／`basketAspect`，`MachineCatalog.ets` L44–52——现行字段仍是旧机器照片口径：`leverAspect`／`bracketAspect` 是拨杆／支架图的宽高比，`rollerWidthRatio`＝0.9528 是滚筒宽比；新方向下这些字段的含义在契约文件里重登记（拨杆控件／旋钮控件的 UI 几何），字段本身的改名／删除随批 3 的 Canvas 退役走，不在本稿预支为"已重命名"）。
- 标准件是**跨蓝图的共享层**：件的定义（契约文件 `PartContract.ets`）与变体库（`rawfile/ui-parts/`，见 §7.4）不属于任何一个蓝图；蓝图只引用件，不拥有件。蓝图之间零引用（多机型 §14）指的是蓝图代码之间不互相引用，共享层不属于任何蓝图，蓝图引用共享层不违反该禁令；多机型 §14.4"资产只出现在该蓝图自己的组件里"一句与共享件冲突，须随多机型稿修订（跨稿缺口，批 1 前承接，本稿不代修）。
- 换机型＝换整套缺省搭配（10 个件一起换）；换装页改单个件＝只换该件的变体（§3.6）。

### §3.6 与现有换装页的关系（方案与取舍）

换装页（CustomizePage）框架不动，内容改成新 UI 件：

- **按区域选变体**：换装页每区域一行（纸面板／横尺／落字导件／字篮图形／键盘网格／功能行／拨杆控件／旋钮控件／机身面板／色带条，10 行），每行列出该件的变体（缩略图＋名字），点选即换、即时生效（沿用 19 号稿 §4-7 的开关即时生效口径：改值后 Index 经 prop 链得知，重挂载生效——19 号稿 resolve 已裁定生效路径是重挂载＋初值同步，不是"切机本身就是整机重建"）。

- **取舍**：不做"整机主题一键换"（那会掩盖自由搭配的粒度）；不做变体预览大图（缩略图够用，预览大图是后续项）。

## §4 动画设计（按新 UI 几何重设计）

### §4.1 走纸模型（形式化定义；几何量＝公式＋待重算）

新 UI 的走纸模型只有三个对象：**纸面板**（平移的 sheet）、**落字导件**（固定或追踪的标记）、**机身面板**（不动的背景）。没有滚筒、没有压纸卷、没有拱——旧模型里的"纸筒一体"不变量改写成"纸面板与横尺一体"（横尺跟纸面板走，§3.2 #2）。

核心公式（完整推导表见附录 A；数字一律由公式重算，不抄 20／21 号稿的旧几何数当定案）：

- **D1** 导件位：`archFixX = stageW / 2`（机器几何中央，§11 Q4 已定）。
- **D2** 纸基线：`paperBaseX = archFixX − marginH`（行首时纸的左页边对准导件；marginH 沿用现行纸张预设的 customMarginH，实测 25vp，Index L1804——批 1 在契约文件里登记为纸面板件的几何参数并复核）。
- **D3** 视觉位移：`V = K × O`，其中 O＝`carriageOffsetVp`（逻辑值，每字减一个 advance，`stepCarriageLeft(ch)` L1608 终于改成注释写的样子：`O −= advance(当前字符)`，不再用 travelPerChar——D1 纠错已定案的注释与代码矛盾在此终结；`stepCarriageRight(ch)` 同款签名，删前取被删字符——R-M2）；K＝模式系数（§4.2）。
- **D4** 纸面板位置：`paperLeft(V) = paperBaseX + V`；`paperRight(V) = paperBaseX + Pw + V`。Pw 由 §11 Q16 已点选 (a) 满幅面板（见 §4.4）。
- **D5** 行宽：`lineWidth = charsPerLine × advance`；`advance` EN＝0.6em、中文＝1.0em（em＝fontSizeVp，`measureAdvance` L2256 的口径沿用）；`charsPerLine = floor((Pw − 2 × marginH) / advance)`。混语行按当前语言 advance。
- **D6** O 的范围：`O ∈ [−lineWidth, 0]`；到界只钳制不自动换行（沿用现行 `stepCarriageLeft` L1608 的钳制口径）。
- **D7** 行高：`lineHeightVp = fs × (30/17)`（行高与语言解耦，沿用）；`Ph = Pw × 1.414`；`maxRows = floor((Ph − 44 − 20) / lineHeightVp)`（44＝内容顶、20＝底边距，沿用现行口径）。

**三难已解（诚实记录）**：20 号稿的三难（每字都落在固定导件下 ⟹ 纸每字走满 advance ⟹ 行末出屏约 120vp）在机器照片路线下无解，在新方向下**同时成立**，因为"出屏"这个概念本身变了——纸面板是 UI 元素，它的父容器（stage）按布局裁剪，超出屏边的部分 simply 不绘制，没有"一台机器滑出屏幕"的视觉对象需要遮挡。22 号稿的遮挡设计（壳唇）因此整稿作废（§0.3 V4）。行末／行首的真实视觉后果有三条（§4.4 的重算表与 §4.1 裁剪机制写明）：纸面板左缘被屏边裁剪（行末）；左旋钮随纸面板移出屏左（行末）；纸面板右缘／右三角／右旋钮／拨杆在行首已出屏（行首不可见，§5.2.4 接受＋披露）。三条都是布局裁剪，不判 FAIL。

**行末裁剪是布局本身，不是遮挡**：纸面板的父容器在 stage 边界做 `.clip()`（ArkUI 标准裁剪），裁剪线就是屏边，没有任何额外的遮挡元素（没有唇、没有渐隐、没有壳颊）。验收：行末截图上纸面板左缘与屏左缘重合、裁剪线笔直、无锯齿、无半透明带（§10.1）。

**裁剪机制（行首 vs 行末）**：行首（V＝0）时纸面板左缘在屏内（paperLeft＝paperBaseX，手机 156.35vp），但右缘已出屏：Q16(a) paperRight＝487.05vp（超屏 124.35vp，D24）、Q16(b) 410.95vp（超屏 48.25vp）——纸面板在行首就是左右都被裁剪的状态，左缘留白、右缘出屏（裁剪线即屏边）。右三角：(a) 462.05vp，前约 10 字不可见；(b) 385.95vp，前约 2 字不可见。右旋钮：(a) 414.25vp，超屏 51.55vp；(b) 338.15vp，在屏内（两数均按 H_paperZone＝360vp 假设，批 1 重算——§4.4 注）。拨杆：(a) 469.05vp，约第 10 字才进屏；(b) 392.95vp，约第 3 字才进屏。行首不可见的处置见 §5.2.4（接受＋披露，不钳制——R-B9）。每打一字 V 减一个 advance，纸面板整体左移，左缘在 V＝−156.35vp（约第 15 个英文字）时触到屏边，此后左缘被裁剪、裁剪量随 V 线性增长（D8）；右缘随 V 左移、行末回到屏内（行末 (a) 211.65vp、(b) 206.95vp，D9 正常为 0）。换行时 V 回 0，纸面板回到行首位置——裁剪是行内的瞬时状态，不是永久损伤。纸面板的纵向同理：纸是长纸（Ph＝Pw×1.414），纸区只显示其中一段，上下超出部分由纸区的 `.clip()` 裁掉；换行时纸面板上滑一行高（§4.3），上一行的文字滑出纸区顶缘、下一行从底缘进入——纵向裁剪与横向裁剪是同一机制。

### §4.2 分机型双模式（19 号稿模式矩阵沿用，几何量按新 UI 重算）

19 号稿的模式矩阵数学沿用，但**主语全部换成新 UI 对象**，两个模式重新定义如下（不许照抄旧文）：

- **写实模式（缺省，§11 Q7 已定）**：纸面板每字走满一个 advance（K＝1.0，V＝O）；落字导件固定在 archFixX（波动 0.00vp）；每字的新字符都落在导件下，**drift ≡ 0**（验收硬指标 ±2vp，§1.1 第 5 条）。纸面板行末左缘被屏边裁剪（§4.4）。写实的含义是"像真打字机一样走纸"，不是"像真打字机一样长得像机器照片"。
- **模拟模式（K＝0.3，§11 Q9 已定）**：纸面板每字只走 0.3×advance（V＝0.3×O）；落字导件追踪落字点，每字右移 0.7×advance（`guideX = min(archFixX + 0.7 × accumW, stageW)`，accumW＝本行已打字符的 advance 之和，屏边停住，D10）；导件在行首从 archFixX 出发。模拟的含义是"纸小幅走、导件追着字跑"，给觉得写实"纸动得太厉害"的用户。
- **1960s 电动单设一套**（沿用 19 号稿 Q1(a)）：1960s 不设模式开关，只有一套电动行为＝写实走纸＋回位 150ms（§4.3 时序表）。理由：电动打字机没有手动字车的"写实／模拟"之分。
- **模式切换**：200ms 过渡内插（纸面板 V 与导件 x 在 200ms 内从旧模式值插到新模式值，§4.3）；切换即时生效（换装页开关，§3.6）；过渡期间禁打字（沿用 19 号稿的过渡状态机口径）。

**模拟模式的行末缺口（本稿自查发现，批 1 须闭合）**：模拟下导件行末位置＝`archFixX + 0.7 × lineWidth`。Q16(a) 手机口径下 lineWidth＝275.4vp，导件行末＝181.35＋192.78＝**374.13vp，超出屏宽 11.43vp**——导件在行末约 2 字前触到屏边；平板 (a) 口径下导件行末 740.05vp，超屏 66.35vp，约 3 字（R-m6）。Q16(b) 口径下导件行末＝181.35＋142.80＝324.15vp，在屏内。本稿不悄悄消化这个缺口，§11 Q17 已点选 (a)：导件在屏边停住、最后 2 字漂移验收放宽（手机 (a) ≤11.43vp、平板 (a) ≤66.35vp，其余字仍 ≤2vp——R-M15）。

### §4.3 动画驱动（17 号稿帧时钟沿用，渲染目标改成 ArkUI 字段）

- **时钟配置定死**（沿用 17 号稿）：`Animator.create`，duration 1,000,000ms 线性，iterations -1，`now` 即 onFrame 的 value，全稿单一时间源。**宿主：Index 内新建 `ensureFrameClock()`**（不新建独立服务——R-B4 D9；帧时钟唯一现行宿主是 Canvas，`frameClock` L205–206、`ensureFrameClock()` L1056、`Animator.create` L1062、`onFrame` L1063 起，批 3 迁入 Index）。
- **触发通道**：tick 计数 prop（`canvasStrikeTick` 已有，`canvasDeleteTick`／`canvasNewlineTick`／`canvasPaperTick`／`canvasBackTick` 四个也已有——**沿用**，不是新增；17 号稿的 prop 名，含义不变）。归属：Index 侧 @State（`canvasPaperTick` L173、`canvasDeleteTick` L322、`canvasBackTick` L324、`canvasNewlineTick` 由 `newlineTick()` 在 L5117 传入；`canvasStrikeTick` @State L496）／Canvas 侧 @Prop @Watch（L89／L100／L102／L110）／递增点（`queueChar` L2988–2994 递增 `canvasStrikeTick`，其余 tick 在对应 handler 内递增）。
- **逻辑值 vs 渲染值**：逻辑值是 Index @State（O、行、列、模式）；渲染值改成 **ArkUI 可动画字段**（`paperOffsetVp`、`guideXVp`、`leverRatio`、`knobAngle`、`typebarAngle`、`ribbonY`），由帧时钟在 onFrame 里写，**不再经过 Canvas draw()**（Canvas 机器层已退役，§8）。空闲规则沿用：无活动动画不写渲染值。

## §5 交互设计

### §5.1 键盘交互（按键 → 字杆打击 → 落字 → O 步进的完整链路）

链路（沿用 D1 纠错已定案的活链，渲染目标改成新 UI 件）：

1. **点按**：用户点按键盘网格的 Button → `hitAt` 按帽心判定（keymap `CapDef`，偏差 ≤2% 硬契约，§3.3）→ 键帽按下态（下沉 2vp、换按下态图，§2.3 第 4 条）→ `queueChar`（Index L2982，`canvasStrikeTick` 递增在 L2988–2994）→ `canvasStrikeTick+1` → snap 打击约 85ms（字杆摆起＋色带抬起＋扔＋撞击，§4.3）→ `onStrikeArrive()`（L3115）→ `landHead()`（L3060）→ 新字符在撞击帧干净落在导件下、纸面板 V 步进一个 advance（写实）／0.3×advance（模拟）。（Canvas 内 `onFinish`／`onArrive` 零命中，链路描述里不许再写 `onFinish`——R-B2／R-ADD2。）
2. **多点触摸**：键盘网格支持多点同时点按（沿用现行口径）；快速连打 20 字 0 丢字 0 双落（§2.3 第 4 条的验收口径）。
3. **Shift 按住模式**：按住 Shift＋点字母＝大写，松开回小写（沿用现行口径）；Shift 帽是宽帽（§3.2 #5），图例是真文字"Shift"，完整显示（§1.1 第 4 条）。
4. **符号键盘**：FunctionRow 第 6 键"字符"切符号键盘（EN／中文各 42 符号，沿用现行 `SYM_EN`／`SYM_ZH`）；切回同键。
5. **候选栏**：中文输入时候选栏 44vp 常驻占位（沿用现行口径），位置在键盘网格上方（§11 Q11 缺省 (b)）；点按候选＝上屏，长按候选与点按同一 handler（沿用现行口径）；候选栏与纸面板无重叠（V5 已验的口径沿用）。组字中串显示在导件下方，不触发纸步进；选字上屏时按上屏字总 advance 一次步进（R-m15）。
6. **删除**：删除键＝`stepCarriageRight(ch)`（Index L1639–1644）：`onDelete` 内删前取被删字符，O 右移该字符的 advance，70ms 弹簧回弹（§4.3，一格退格）；删到行首时退行（回上一行末，O 250ms＋纸飞出 300ms，§4.3；已在第一行则无动作）。

### §5.2 拨杆交互（直驱拖拽＋过半触发）

拨杆控件是纸区右缘的一条竖向手柄（§2.5 第 3 条），不是机器照片里的拨杆：

1. **点按**：点按手柄＝换行（与键盘 Return 键同一 handler）。
2. **纵向拖拽**：手柄跟手下移（ArkUI 直驱，`leverRatio` 由帧时钟写，Move→首个上屏帧 p50 ≤10ms，§4.3）；角度微摆：`leverAngle = leverRestAngle + dragRatio × leverSwing`，`dragRatio = clamp(dy / leverH, 0, 1)`，静止角手机 15°／平板 30°（冻结，沿用现行口径），摆角手机 20°／平板 35°。（本条按 Q14(a) 竖向手柄写——Q14(a) 前提。）
3. **释放判定**：松手时 `dragRatio ≥ 0.5`（`LEVER_COMMIT_RATIO = 0.5`，沿用）触发换行；不到半 150ms 弹回（沿用现行口径）。
4. **命中区**：手柄命中区随 V 变宽——手柄 x＝`paperBaseX + V + Pw − leverW − leverMargin`（§4.5），命中区＝手柄几何向外扩 8vp（手指容差）；**行首手柄不在屏内**：Q16(a) 手机行首手柄 x＝469.05vp（约第 10 字才进屏）、Q16(b) 392.95vp（约第 3 字才进屏）——每行开头这几字内拨杆不可点，接受＋披露（Q16 决策材料已写明，不钳制——R-B9 D7）；行末手柄在屏内（Q16(a) 手机行末手柄 x≈193.65vp）。
5. **形态已点选 (a) 竖向手柄**（§11 Q14，2026-11-16 23:32）：拨杆挂载按 (a) 写死（R-M6 的重做分支不触发）。

### §5.3 换纸／换行／切机／模式切换

- **换行**：拨杆控件（§5.2）或键盘 Return 键或功能行"换行"项——三路同一 handler；换行三段编排见 §4.3 时序表；换行到最后一行按换行触发换纸（`maxRows` 公式见 §4.1 D7）。
- **换纸**：功能行"换纸"项＝手动换纸动作 600ms（沿用现行口径），期间禁打字（`paperChanging`）；换纸真清空（`DocModelCore.clear()`，沿用）；换纸动画 300ms 飞出＋300ms 飞入（§4.3）。
- **切机**：换装页／主页换机型＝换整套缺省搭配（10 个件一起换，§3.5）；生效路径是重挂载＋初值同步（19 号稿 resolve 已裁定），过渡状态机是挂载时 prop 变化的护栏（沿用 19 号稿的裁定）；切机时纸面板位置验收沿用 19 号稿 §4-4 的口径（切机在行中时纸面板位置以 O=0 基准重算，不许带旧 O 的偏置；"底座偏差"是机器照片路线的旧词，新方向无底座，改称纸面板位置重算）。
- **模式切换**：换装页每机型一行动画模式开关（写实／模拟），切换 200ms 过渡内插、过渡期间禁打字（§4.2）。

### §5.4 自由搭配的交互（换装页按区域选变体）

- **操作流**：换装页 → 选区域（10 行，每行一个件）→ 该行列出变体（缩略图＋名字）→ 点选 → 即时生效（纸面板／键帽／机身面板当场换色换形，不重启 App）；几何校验失败时该变体置灰不可点（§3.4 第 1 条）；色温校验失败时提示"色温不匹配"、用户仍可强制装（§3.4 第 2 条）。
- **撤销**：每区域一行"恢复缺省"（回蓝图缺省变体）；整页一个"恢复整机缺省"（回该机型的 10 件缺省搭配）。
- **持久化**：变体选择落 prefs（沿用 19 号稿的 `anim.mode.<machine>` 键的先例：新键 `ui.part.<part>.<machine>`，共 40 键（10 件 × 4 机型）；PrefKeys 常量（33）与 PrefRegistry 规格（32）两数本身不一致（差 1，原因未写：是否一为常量数、一为规格数），＋40 键后的总数（若全进 PrefKeys 应为 73）与两表关系由批 1 核对并写明，不归 `SWITCH_KEYS`——R-m3／R-m24，批 1 重算）。

### §5.5 折叠三态（半开桌台是重点）

重表述为扁平 UI（§0.4）：

- **半开桌台（约 90°，重点）**：上半屏＝纸区＋字篮区，下半屏＝功能行＋键盘区；顶栏保留在上半屏顶缘（与 Foldtype 图 02 一致——R-m17）；铰链是两区的界，**没有任何一个 UI 元素横跨铰链**（纸面板底缘对齐铰链上沿、键盘区顶缘对齐铰链下沿，对齐偏差 ≤1vp）；效果图 02 是此态的视觉基准（上屏纸、下屏键盘）。折叠／展开只触发布局变化，文档／光标／纸位全部保留（沿用 F7 口径）。铰链带位置以模拟器实测为准（DevEco Pura X Max 内屏：creaseTop＝434.2vp／creaseBottom＝505.5vp，沿用现行模拟器口径——批 4 实测复核，实测值不同时按公式重算）。
- **展开（内屏）**：单屏五区布局（§1.1 第 2 条），与手机主页面同一结构、尺寸按平板蓝图换算。
- **外屏**：紧凑布局——纸区＋键盘区两区（字篮区与功能行折叠进顶栏菜单，顶栏"?"旁加一个"更多"入口，复用 AppMenu，新增"字篮区"开关一项与"功能行"一项——R-m22）；纸区高度不小于 8 行（`8 × lineHeightVp`），否则字太少没法打。
- **验收**：三态截图（DevEco 折叠模拟器，hdc `127.0.0.1:5555`，Pura X Max 内屏 1828×2584／外屏 1264×1848——沿用现行模拟器口径；机队无折叠真机）；铰链避让检查：任一元素横跨铰链即 FAIL。

## §6 一体性（改动传播图＋全链实例）

### §6.1 改动传播图（改一个标准件 → 影响哪些动画量 → 影响哪些交互）

```
纸面板.Pw / marginH 变了
  → charsPerLine / lineWidth / O 范围（§4.1 D5–D6）重算
  → paperLeft / paperRight（D4）→ 横尺位置、拨杆 x、旋钮 x（§4.5）
  → 行末裁剪量（§4.4）→ 验收表更新
  → 命中区：拨杆命中区、旋钮命中区（§5.2、§5.3）

键帽.帽形 / 帽色变了
  → 帽心（CapDef）→ hitAt 命中区（§3.3 硬契约 ≤2%）
  → 按下态几何（下沉 2vp 的阴影，§2.3）
  → 键盘网格行高（帽高变了 → 键盘区高度变了 → 纸区高度变了 → H_paperZone → Q16(b) 的 Pw）

机身面板.配色变了
  → 色板校验（±10%，§2.1）→ 拼合门图（接缝区 ≤30）
  → 不影响任何动画量（机身面板不动，§3.2 #9）

落字导件.archFixX 变了（只可能由 stageW 变引起）
  → paperBaseX（D2）→ 整套走纸重算（§4.1）

模式 K 变了（写实 ↔ 模拟）
  → V＝K×O → 纸面板步进、导件追踪（§4.2）→ 行末裁剪量、导件行末位置（Q17）
```

传播图的铁律：**任何一件的几何量变了，附录 A 的推导表必须整表重算**，不许只改一个数。批报告附推导表（§10.4）。

### §6.2 全链实例 1：换纸面板变体改了 marginH

用户在换装页把纸面板从 letter（marginH＝25vp）换成 manuscript（marginH＝40vp，假设值——批 1 登记实测值）：

1. `paperBaseX = archFixX − marginH`：181.35−40＝141.35vp（手机），纸基线左移 15vp。
2. `charsPerLine = floor((Pw − 2×marginH)/advance)`：Q16(a) 手机 (330.7−80)/10.2＝24（原来 27），每行少 3 字。
3. `lineWidth`＝24×10.2＝244.8vp；O 范围 [−244.8, 0]；行末裁剪量＝141.35−244.8＝−103.45vp（原来 −119.05vp）。
4. 横尺页边三角位置＝paperLeft＋marginH／paperRight－marginH，跟着重算；拨杆 x、旋钮 x 跟着 paperRight 重算。
5. 验收：换变体后截图上导件仍在机器中央、落字点恒在导件下（drift ≤2vp）；`maxRows` 不变（Ph 没变）；换纸频率上升（每行少 3 字）如实记录在批报告里，不许瞒。

### §6.3 全链实例 2：换键帽变体改了帽心

用户在换装页把键帽从圆角矩形换成圆形（1920s 圆帽变体）：

1. 帽心相对坐标变了（圆形帽的帽心＝圆心，圆角矩形帽的帽心＝矩形中心——同一格子两种算法，契约文件登记两套帽心表）。
2. `hitAt` 按新帽心表重算；帽心偏差 ≤2% 硬契约（§3.3）——超了即重测 keymap，不许"差不多对齐"。
3. 按下态几何：圆形帽下沉 2vp 时阴影是圆形阴影（不是矩形阴影），§2.3 的三层叠层按帽形换。
4. 键盘区高度不变（帽高是契约参数，帽形变不改帽高）→ 纸区高度不变 → H_paperZone 不变 → Q16(b) 的 Pw 不变。本例证明：换帽形只影响键盘区内部，不向上传播到纸区——传播图（§6.1）第 2 条的括号里写明的条件（帽高变了才向上传播）在此不触发。
5. 验收：换变体后逐帽抽查（§10.2）：Shift／Return／空格条三帽必查，其余抽 10 帽；长标签完整显示（§1.1 第 4 条）。

### §7.3 风格一致性控制方法（三选一，选其一并写理由）

选 **(a) 同一套生成参数＋拼合校验**：所有 UI 件共用同一套生成参数（光源方向左上、色温 5500K、色板、0 级干净），生成后拼合截图门图校验（接缝区像素差 ≤30）。理由：(b) 参考图锚定（拿一张图当锚、其余件向它对齐）会把锚图的偶然偏差传给全批；(c) 事后统一调色（生成完再批量调色温）会洗掉每件的材质特征。(a) 的代价是每件都要单独写全参数，但这是唯一不把误差从一件传到另一件的方法。

### §7.5 包体与性能

- 包体大小不用担心（用户 2026-11-08 定，不动）。UI 贴片比机器照片小一个量级（贴片是局部纹理，不是整机大图），包体只会比现在小。
