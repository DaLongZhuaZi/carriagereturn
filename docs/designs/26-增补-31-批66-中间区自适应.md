## 1. 扇图宽版（三版已入库）

### 1.1 为什么必须换图（不是调代码）

- 原图 `basket-fan-3d-v4.png` 1904×1129，宽高比 **1.69**。扇是 Contain 显示，**可视宽 ＝ 井高 × 1.69**：井 155.1vp → 扇最多 262vp，已经到顶。纸会盖住井以上的部分，盒子再大也没用。
- 换一张更宽比例的图，是唯一不加高井、不动纸区就能让扇变宽的办法。

### 1.3 扇盒子：宽高系数统一乘 kx（口径统一，无视觉变化）

- 现行扇盒子是 `213×sx、126.3×sy`（宽高用两个系数分裂，是老 xk/yk 残留）。改成统一乘 kx：`213×kx、126.3×kx`。
- 可视宽不变：图是 Contain 且宽限，盒宽 213×1.857＝395.6vp，扇宽仍约 396vp（盒宽 395.6vp、图高 395.6/2.6＝152.2vp，井高 155.1vp 装得下）。
- **注意底对齐不变**：扇底贴井底（Stack Bottom 对齐）。盒高变大后（126.3×1.857＝234.5vp），图在盒内居中会抬高扇的位置——必须保证扇底仍贴井底，不能上浮。

## 2. 功能行等比放大（选项 B 的延续）

### 2.1 现行问题

- `FunctionCaps26` 固定 **216×36vp（六键 36×30）**，批 64 写明“不再乘 k”。手机上功能键（30vp）比键盘键（27.6vp）略大；批 65 后平板键盘键已 51.3vp，功能键还停在 30vp——**视觉层级翻过来了**，这是功能行看着又小又挤的根因。

### 2.2 修法

- 六键按 kx 等比放大：36×30 → **66.9×55.7vp**，行 216×36 → **401×67vp**（≈纸宽 408vp）。
- `FUNC_ROW_H` 从 36vp 改成 **67vp**（Stage26 固定高区；FIXED_SUM 191.6→222.5vp）。
- **代价（写清）**：纸区 359.6→约 329vp（−31vp），可见行数约 11.5→约 10.4 行（行高 28.6vp）。扇不加高井，扇不占纸区。满行 31–32 字不变（行宽由纸宽定，与功能行无关）。
- **范围**：本批只做尺寸等比，不动功能。六问⑥的功能行重做（换什么功能、EN 切“中”、按下动画）另立批。
