# 26-增补-38-批76-空格键校平与落字逐台对齐＋字盘区参数化

> 批 76。基于最新提交 `5202c15`（批 75 补记）与批 75 截图 2342–2346 的实测分析。
> 用户原话（2026-11-22）：“①除了我们已经调好的版本，其他的所有键盘的空格键都是歪的，并且很多键盘连落字的地方都没有对齐键帽，而是落到了键帽的侧面，需要逐个进行优化，并且是以自适应方式进行的，确保一次适配就可以适应各种分辨率②字盘区域的素材依然是固定的，这个不行，需要分析下怎么进行设计比较好”

## 0. 实测结论（截图＋代码双证，全部复核过）

### 0.1 空格键歪：实测倾角（平板截图 2342–2346，PIL 量顶边）

| 机型 | 空格条顶边倾角 | 左右端高差（≈1000px 跨度） |
|---|---|---|
| 1920s | −2.25° | 53px |
| 1930s | −1.57° | 24px |
| 1950s | 目测歪（井底奶油色，亮度阈值量不到） | — |
| 1960s | −3.10° | 110px |
| 2020s | −3.28° | 116px |

倾角为负＝右端高于左端（条向右上斜）。**五台全歪**，不是某台个别问题。

**根因（素材，不在代码）**：`cap3d-space-<era>.png` 是三维透视渲染——生成时用了“斜上方三刻度视角”，条身在图里本身就是斜的（向远端收拢、一端高一端低）。`KeyGrid` 用九宫格（`resizable slice left:64 right:64 top:6 bottom:6`）只拉中间段，**拉伸不改倾角**，斜的图拉完还是斜的。代码的九宫格本身没错，错的是源图里条就不平。

**修法（素材重生，已做）**：五张空格条按“正视、平视、无透视、条身绝对水平”重生（`cap3d-space-<era>.png` 同名替换，见 §1）。新图实测倾角全部 ≤0.05°（1920s −0.02°／1930s −0.02°／1950s 0.00°／1960s 0.04°／2020s −0.05°），抠图白边 0–228px（rembg u2net，见 §1）。**代码不用改九宫格**，换图即平。

**自适应口径**：空格条的平直是素材属性（图里就是平的），与分辨率无关；九宫格的 slice（left/right 64px）是图内比例，盒宽由布局量（kx、stage 宽）派生，换分辨率自动跟。**不要在代码里给空格条加旋转修正**（那是给歪图打补丁，换图后反而会把平图转歪）。

### 0.2 落字不对齐：`KB_LEGEND_UP = 5.0` 一个值管五种帽形，必然错

**代码实情**（`KeyGrid.ets` 第 30 行）：`const KB_LEGEND_UP: number = 5.0;`——图例 Text 先在盒内居中，再统一上移 5vp（第 415／426／434 行三处同值）。这 5vp 是给**一种**帽形调的，但五台帽的顶面高度各不相同：

**顶面中心实测**（键帽源图 503×512，顶面中心 y 占图高的比例；目测＋亮区质心双法对过）：

| 机型 | 帽形 | 顶面中心 y 占比 | 应有上移比 `(0.5 − 占比)` | 平板应有上移（帽高 51.3vp） |
|---|---|---|---|---|
| 1920s | 高圆（立式机经典圆键） | ≈0.215 | 0.285 | ≈14.6vp |
| 1930s | 中圆（便携机） | ≈0.254 | 0.246 | ≈12.6vp |
| 1950s | 低圆盘（流线型） | ≈0.352 | 0.148 | ≈7.6vp |
| 1960s | 方角（电动机方键） | ≈0.313 | 0.187 | ≈9.6vp |
| 2020s | 扁平方（现代） | ≈0.371 | 0.129 | ≈6.6vp |

**对照**：现行统一 5.0vp。1920s 的图例实际落在顶面底缘、几乎贴到侧壁（调试图红线＝图例线，正好压在 1920s 顶面下缘；见 `~/workspace/carriagereturn-assets/debug-legend-strip.jpg`），这就是用户说的“落字落到了键帽的侧面”。1950s／2020s 的偏差小（仍在顶面上、略偏下），1960s／1930s 居中偏下。

**修法（代码，按机型分比，见 §2）**：把 `KB_LEGEND_UP` 从常量改成**按机型的比例** `legendUpRatio[machine]`（上表第三列），图例上移量＝`legendUpRatio × 帽盒高`。帽盒高由布局量派生（`KB_CAP_H × kx()`），所以上移量自动随分辨率缩放——**一次适配，全分辨率通用**，不写死任何设备的 vp 数。比例值以本表为准，桌面端按截图验收微调（见 §4），不要凭感觉改回固定值。

**附带注意（不修，但要知道）**：键帽图用 `ImageFit.Fill`（`KeyGrid` 第 341 行起），盒比 40.1:51.3（0.78）与图比 503:512（0.98）不一致，纵向多拉约 26%。Fill 是 binding 明文禁的，但本批不动它（改 Contain 会改键帽尺寸与布局，另立批）。比例法算出的上移量是**纵向比例**，Fill 是均匀纵向拉伸，不改变纵向比例，所以上表比例在 Fill 下仍然成立。

### 0.3 字盘区素材固定：`fanwell-back-v2.png`＋`basket-fan-*.png` 两张定图

**代码实情**（`Parts26.ets` 第 400–410 行附近，`Basket26` 的 `build()`）：
- 井背：`fanwell-back-v2.png`（预渲染贴图：纵向渐变＋7 道杆影），`ImageFit.Contain`，全机共用一张。
- 扇：`basketFanImage(machine, fanWide)`（`basket-fan-*.png` 定图，每台一张），盒宽×kx、盒高＝盒宽／图比。
- 枢轴／井口软影：代码画（Column／Row＋linearGradient），已是参数化，不动。

**为什么“固定”不行（已有实锤）**：批 75 补记 `5202c15`——“扇区浅薄荷绿块根因＝`fanwell-back-v2.png` 预渲染井背图未随 base 重生成”。定图跟不上机型色（base 改了，井背图还是旧色，露出一块浅薄荷绿）；定图也跟不上井尺寸（换分辨率只是等比缩放，杆影间距、渐变位置与井的真实几何脱节）。字盘区是“机器的心脏”，定图是这块最不该定图的地方。

## 2. 代码改动 A：图例按机型分比（`KeyGrid.ets`）

1. 删常量 `KB_LEGEND_UP = 5.0`（或保留作废弃注释），新增按机型查表：
   - `legendUpRatio(machine)`：1920s `0.285`／1930s `0.246`／1950s `0.148`／1960s `0.187`／2020s `0.129`。
   - 查表方式沿用 `MachineCatalog` 的既有风格（`tierToken` 那种按机型分支），不要另起一套机型枚举。
2. 三处图例 `.translate({ y: -KB_LEGEND_UP })`（第 415／426／434 行：普通键双行、SHIFT LOCK、单行）统一改成 `.translate({ y: -legendUpRatio(this.machineKind) * KB_CAP_H * this.kx() })`。
   - 必须是**比例 × 帽盒高**（`KB_CAP_H × kx()`），不要写死 vp 数；不要按设备分支（不要 `if (平板) … else …`）。
3. 空格条九宫格不动（slice 仍 `left:64 right:64 top:6 bottom:6`）；不要给空格条加旋转。

## 3. 代码改动 B：字盘区参数化（`Parts26.ets`，`Basket26`）

**目标**：字盘区不再用定图；井背与扇全部由布局量派生，换机型、换分辨率自动跟。

### 3.1 井背：代码画（替掉 `fanwell-back-v2.png`）

- 删 `fanwell-back-v2.png` 的 Image 节点（文件留仓，不删图）。
- 改成两层代码元素（都在井的 Stack 内，位置与尺寸沿用现行井盒）：
  1. **纵向渐变**：Column，`linearGradient`，方向 Bottom（上亮下暗，沿用定图的明暗走向）；颜色从 `tierToken(machine,'base')` 与 `tierToken(machine,'paperwell')` 派生（上＝paperwell 浅、下＝base 深，中间按明度插值），不要写死色值——这样 base 改色，井背自动跟（根治 `5202c15` 的浅薄荷绿块）。
  2. **杆影**：N 道细竖条（Column，宽 `1.5×sx`、高＝井高、黑 8%–12% 透明、圆角），横向均匀排布；道数 N 与间距由井宽派生（`N = max(5, floor(井宽 / 30vp))`，间距＝井宽／(N＋1)），不要写死 7 道、不要写死间距。杆影只画在井背层，不压扇。
- 渐变与杆影的色值、透明度以批 40 定图的观感为准（上亮下暗、杆影淡），不要另创新观感。

### 3.2 扇（字杆扇）：逐杆代码画（替掉 `basket-fan-*.png`）

- 删 `basketFanImage(this.machine, this.fanWide)` 的 Image 节点（文件留仓，不删图；`basketFanImage()` 函数本身不动，留给以后或别的调用点）。
- 改成 **N 根字杆**（每根一个组件），全部由井的几何派生：
  - **枢轴**：井底中央（现行枢轴位置不变，`x＝井宽/2`，`y＝井高−1vp` 附近）。
  - **每根字杆**：一个细长 Column（宽 `2.5×sx`、长＝井高×0.82，钢色 `linearGradient` 沿用 `STEEL_HI`→`#4c4c4f`，与现行枢轴同系），顶端一个小字钉（圆角矩形，`6×sx` 见方，`tierToken(machine,'steel')` 色，上面一个字母 Text，字号 `7×sx`——字母从现行扇图的字钉字母取，顺序沿用扇图从左到右的顺序）。
  - **排布**：根数 N 与井宽同 §3.1 的 N（同一组杆影对齐字杆，一一对应）；第 i 根的角 `θ_i ＝ startAngle ＋ i × stepAngle`，`startAngle ＝ −38°`，`stepAngle ＝ 76°／(N−1)`（扇面总张角 76°，沿用现行扇图的张角观感）；每根绕枢轴旋转 `θ_i`（`.rotate({ angle: θ_i })`，旋转中心＝杆底＝枢轴点），杆底固定在枢轴、杆顶沿扇面散开。
  - **机型区分**：杆的钢色、字钉色、字钉字母由 `machineKind` 派生（钢色＝`tierToken(machine,'steel')`，字钉座色＝`tierToken(machine,'base')` 的明度派生）；不要每台另画一套扇图。
- **Shift 抬扇**：整组字杆（一个 Stack 包住 N 根）沿用现行 `.translate({ y: shiftLiftVp })`（−10vp）＋弹簧动画，不要改。
- **宽／窄**：`fanWide` 的宽窄分支沿用现行盒宽逻辑（`fanW26()`／`fanH26()`），字杆组装进同一盒，N 与张角按盒宽重算（宽盒 N 大、窄盒 N 小），不要写死 N。

### 3.3 不动的部分

- 枢轴（井底中央的 Column／Row＋铆钉）不动。
- 井口曲线、井口软影、井的圆角与 clip 不动。
- 盖面、纸、键盘井不动。

## 4. 验收（截图号从 2348 起，平板优先）

算过＝同时满足：

1. **空格条平**：打字页（平板）切到每台机，空格条顶边水平（PIL 量倾角 ≤0.5°，左右端高差 ≤5px／1000px 跨度）；五台全过。不要只凭肉眼，量了再报。
2. **图例居中**：打字页（平板）切到每台机，每行抽 3 个键（数字行、Q 行、A 行各一），图例字母居于该键顶面中央（顶面内，不压侧壁、不出顶面）；五台全过。1920s 重点验（原先最偏）。
3. **字盘区跟机型**：打字页（平板）切到每台机，井背渐变色与该机 base／paperwell 一致（无浅薄荷绿块、无旧色残留）；字杆扇面均匀、杆顶字钉字母清晰、杆底收束于枢轴；五台全过。
4. **字盘区跟尺寸**：手机抽查 1 台（任选），井背杆影与字杆数随井宽变、扇面不溢出井口、不留大块空白。
5. **主链回归**：打字、换纸、回车、Aa 切换、字母／符号切换、Shift 抬扇均正常；抬扇时整组字杆同抬 10vp（不要只抬一半杆）。
6. **无拉伸**：空格条九宫格 slice 不变；字杆为代码元素，无图比问题；自检写清每台机的 N（杆数）与张角。
