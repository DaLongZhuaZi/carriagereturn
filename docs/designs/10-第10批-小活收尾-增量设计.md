## 2. R3：删字体后同会话刷新

1. **现状（读码坐实）：** `FontManagerPage.ets` L150 `removeFont()`、L176–177 遍历四机型命中被删 family 即 `CustomizeStore.setFontFamily(kind, '')` 回退默认（第 8 批已落地，`machine … font reverted` 日志）；但 `Index.ets` L285 `fontFamily` 是会话内 `@State`，只在启动／换机时读 `CustomizeStore.fontFamily()`（调用点 L1598／L1630／L1638／L1707），删除成功后没有任何通知链，当前打字机仍显示已删字体名，重启／换机才更新。写点在 `applyMachineFont()` 内（L1616／L1624 两处赋值），不在调用点（评审 Nit：v1 引文不精确，已订正）。
2. **修法（第 8 批已写死的做法）：** 删除成功后由 `FontManagerPage` 通过回调通知 Index，Index 重读 `CustomizeStore.fontFamily(当前机型)` 并调 `applyMachineFont()`（`Index.ets` L1605，已有，不新增函数）。**不许** Index 轮询 store；**不许**改 `removeFont` 已有的回退逻辑（只在其后加通知）。
3. **接线点（评审 Nit：回调名写死）：** `FontManagerPage` 新增 `onFontDeleted: () => void = (): void => {}`（照抄同文件 `onApplyFamily` 的回调形态）；Index 传入 `onFontDeleted: (): void => { this.refreshFontAfterDelete(); }`；Index 新增私有方法 `refreshFontAfterDelete()`，只做"重读＋`applyMachineFont`"两件事。
4. **验收：** 真机（平板）删当前机型的正在用字体 → 同会话内打字机标签立即变回 Courier Prime（截图＋`font reverted` 日志）；再切一次机型仍为默认字体；重启后仍为默认字体（无回归）。门图 vs 917 重跑一次（Index 动过，预期 0.00%）。
