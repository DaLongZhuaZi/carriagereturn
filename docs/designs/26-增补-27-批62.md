# 26 号稿增补-27：批 62——修设置不生效（字号重置、纸张纹理/自定义、无障碍覆盖层）

> 依据：用户 2026-11-20 02:27 六问；沙箱代码调查（报告 `~/workspace/tmp-verify/carriagereturn-6q-report-20261120.md`，远端 main HEAD 5e36b83）核实：字号滑杆当时生效、随后被 measureStage 无条件覆盖；纸张纹理/自定义颜色/纹理/横线存了、渲染没用；无障碍覆盖层是死开关。本批只修“设置了但不生效”的 bug，不加新设置、不改设置项的语义。

## 一、字号滑杆被重置（根因：measureStage 无条件覆盖）

- 现状：换装页最末组字号滑杆（CustomizePage.ets:339-351，12–26，step 1），`onFontSize` → `applyFontSize`（Index.ets:2150-2160）当时生效（clamp → setFontSize → fontSizeVp → lineHeightVp → measureAdvance/recalcTravel/rewrap/syncRows/recalcPaperHeight，链路完整）。但 `measureStage`（Index.ets:1865-1879）先算出 17–26 的 computedFs 后丢弃不用，无条件执行 `this.fontSizeVp = this.paperPanelWidthVp() / 220 * 11.9`（Index.ets:1876，手机约 11.9）。measureStage 调用点：启动（1441）、折叠（1733）、换机（2320）、insets 到达（2405）、载入文档（4708）、窗口尺寸变化（5430）。`effectiveFontSize` 只在 Index.ets:110 被 import，全文件零调用；`CustomizeStore.fontSize` 在 Index 里只在 2152（写）与 4772（传给换装页显示）出现，启动/换机/载入时从不读回。
- 修复：measureStage 不再无条件覆盖。读回 `CustomizeStore.fontSize`（若未设置过用 FONT_SIZE_FALLBACK=17），clamp 到 [12,26]，用该值作为 fontSizeVp；只有当 CustomizeStore 里确实没有存过字号时，才用现行计算值（paperPanelWidthVp()/220*11.9）。启动、换机、载入文档、转屏、尺寸变化时都要读回（即 measureStage 的所有调用点都要走同一条读回逻辑，不要只修一处）。
- 滑杆数值回显：`SettingsRow` 的字号滑杆补 `sliderValueText`（显示当前字号，如“20”），不要只显示滑杆不显示数。未设置过时显示 fallback 17，但实际字号以读回值为准，两者一致（不要出现“显示 17、实际 11.9”的不一致）。

## 二、纸张纹理不生效（textureRawfile 是死 prop）

- 现状：`paperPanelTexture()`（Index.ets:1643-1648）按纸种返回文件名，传给 Carriage26（Index.ets:4941 前后 `textureRawfile`）→ Carriage26.ets:172 透传。但 `PaperPanel26.texture()`（Parts26.ets）写死 `$rawfile('ui-parts/paper-cream-v5.png')`；`textureRawfile` prop（Parts26.ets:555）在 build 里一次都没用。结果：换纸种不换纹理，纸面永远是 paper-cream-v5。
- 修复：`PaperPanel26.texture()` 改用传入的 `textureRawfile`（按纸种的文件名），不要写死。若某纸种没有对应纹理文件，落回 paper-cream-v5（不要编造路径、不要留空）。

## 三、纸张自定义颜色/纹理/横线不生效（存了、渲染没用）

- 现状：`PaperCustomPage.ets` 色板 → `CustomizeStore.setPaperColor`（CustomizeStore.ets:138）；`importTexture()` → `setPaperTexture`；横线开关 → `setPaperRuled`。`refreshPaperCustom`（Index.ets:2128-2135）读入 `customPaperColor`（:2133）、`customPaperTexture`（:2134），之后全文件无任何其他引用；`ruled` 在 Index/Carriage26/Parts26 全文件零出现。结果：自定义颜色/纹理/横线只存在 prefs 里，打字页看不见。小样预览（PaperCustomPage.ets:210-240）里看得见（预览组件内直接使用），打字页不生效。
- 修复：把 `refreshPaperCustom` 读到的 customPaperColor / customPaperTexture / ruled 真正接到 PaperPanel26 的渲染上（纸底色、纸纹理、横线），与小样预览的口径一致（预览里怎么画，打字页就怎么画）。若自定义值为空/未设置，落回纸种默认值（不要留空、不要崩）。

## 四、纸张自定义边距可见部分不生效（可见文字边距写死）

- 现状：三个边距滑杆 → `setPaperMarginH/T/B`；`marginH/T/B()` 进入换行量宽/光标 X/纸高/打击线计算（布局数学跟随）。但纸面渲染边距写死 `marginLVp: 25*xk()` / `marginRVp: 30*xk()` / `marginTVp: 31*yk()`（Index.ets:4937-4939）。结果：改边距后换行/光标/纸高跟着变，但纸面上文字的左右/上边距肉眼不动。
- 修复：纸面渲染的 marginLVp/marginRVp/marginTVp 改用 `marginH/T/B()`（自定义边距）的返回值，不要写死 25/30/31。未自定义时，marginH/T/B() 应返回现行默认值（25/30/31 的等效值），保证不改自定义时外观不变。

## 五、无障碍覆盖层死开关（双重断点）

- 现状：设置页“界面”组 (2b) → `onToggleA11y` → Index.ets:5165 只翻转 `@State a11yOverlayEnabled`（Index.ets:990）；该 state 在 Index 全文件仅 3 处（990/5164/5165），在全部已读 .ets 里无任何其他引用（没有任何渲染读它）。另 `SettingsPage.ets` 里 `a11yEnabled` 是普通字段（非 @Prop/@State），Index 的值变化不会同步进开关显示。
- 修复：让 `a11yOverlayEnabled` 真正驱动无障碍覆盖层的显示/隐藏（按该开关的设计意图渲染覆盖层）；同时把 `SettingsPage.ets` 的 `a11yEnabled` 改成响应式（@Prop/@State），使开关显示与 Index 的值同步（拨了开关，开关本身要变，覆盖层也要跟着变）。若覆盖层本身尚未实现（只有开关、没有覆盖层组件），先接通开关到一个可见的覆盖层占位（不要只改开关显示、不接覆盖层）。
