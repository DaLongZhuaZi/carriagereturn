# 增补-37（批 75）：每台机各一套键盘设计＋机盖按年代分色

> 承接用户 2026-11-22 02:20 三问：① 现代键盘怎么是 1920s 的配置、2020s 反而是老键盘设计；② 1930／1950／1960 没有各自的键盘设计吗；③ 为什么所有机型的机盖都是完全一样的薄荷色。
> 本稿只改前端（换图＋接线＋分色），不改引擎／输入法／文档模型／成就／导出／音效。

## 0. 根因（沙箱已核，HEAD `9e13d66`）

三问全是真问题，根在批 74 之前就有的两处“同名不同物”：

1. **四台老机的键帽是同一张图**。`cap3d-1920s-matte.png`／`cap3d-1930s-matte.png`／`cap3d-1950s-matte.png`／`cap3d-1960s-matte.png`（各 503×512）沙箱并排比对过：四张一模一样，都是同一个方顶白帽。`KeyGrid.slug()` 虽然按机型取图，但取到的四张图没有区别——所以 1930／1950／1960 **没有**各自的键盘设计，只有文件名不同。空格条 `cap3d-space-<era>.png` 同理（同批生成，极大概率也是同一张）。
2. **2020s 键帽的形是老的**。批 74 沙箱生成的 `cap3d-2020s-matte.png` 是圆柱形（圆顶高帽）——圆键恰恰是老式打字机的经典形；与此同时打字机里现在用的“现代”键帽是 1920s 那张方顶白帽。所以用户看到的“现代键盘是 1920s 配置、2020s 是老键盘设计”是准确的：形与年代标签装反了。
3. **机盖全薄荷色是批 37 的决定**。`TIER_TOKENS` 的 base 列四台全是薄荷绿系（1920s `#adc4b8`／1930s `#8fae9e`／1950s `#d3e0d8`／1960s `#c2d2c8`），`lidColor()`＝`tierToken(machine,'base')`，所以四台机盖一模一样。批 74 沙箱因用户未定而没动 base 列；用户现在明确问了，本批改成本真年代色（§4）。

## 1. 本批交付的素材（15 个，已推仓，见 §7）

### 1.1 键帽（哑光，主用）——`rawfile/ui-parts/`，503×512 RGBA

| 文件 | 形／色 | 年代特征 |
|---|---|---|
| `cap3d-1920s-matte.png` | 圆，**高**，亮面暖象牙白 | 立式机经典圆键，高圆柱＋微凹顶 |
| `cap3d-1930s-matte.png` | 圆，**中**，哑光象牙白 | 便携机圆键，比 1920s 矮、顶更平 |
| `cap3d-1950s-matte.png` | 圆，**低**，暖奶油色 | 流线型低圆盘键 |
| `cap3d-1960s-matte.png` | **方**（圆角），浅灰 | 电动机方键，开始转方 |
| `cap3d-2020s-matte.png` | **方**（圆角），**低**，纯白 | 现代扁平方键（比 1960s 更扁、更白） |

- 五张已并排验过：圆（1920s／1930s／1950s）与方（1960s／2020s）两组，高／中／低三档，象牙白／奶油／浅灰／纯白四色，**一眼可辨不同**。
- 磨损口径（全批统一）：自然使用痕迹——顶面极轻微抛光；绝无锈、划痕、掉漆、发黄、霉斑。
- 2020s 圆帽（批 74 的 `cap3d-2020s.png`／`cap3d-2020s-matte.png` 圆版）**作废**，由本批方版替换。`cap3d-2020s.png`（亮面）暂不补，静态分支若引用它，桌面端先报缺（见 §6.3）。

### 1.2 空格条——`rawfile/ui-parts/`，1024×270 RGBA

`cap3d-space-{1920s,1930s,1950s,1960s,2020s}.png`，各与同年代键帽同形同色：1920s 圆端高条亮面象牙白／1930s 圆端中条哑光象牙白／1950s 圆端低条奶油／1960s 方角中条浅灰／2020s 方角低条纯白。

### 1.3 键盘区背景（键井底）——`rawfile/ui-parts/`，1170×582 RGB

`keywell-floor-{1920s,1930s,1950s,1960s,2020s}.png`，各与同年代 `keybed` 色一致、带细腻材质：1920s 深棕黑毡面（`#3b342b`）／1930s 深绿灰毡面（`#453e38`）／1950s 暖奶油搪瓷面（`#cabba7`）／1960s 浅灰塑料面（`#96908a`）／2020s 深炭色（`#2e2b28`，与现代机 `keybed #3b342b` 同系）。
- 尺寸与现行 `keywell-floor-v2.png` 相同（1170×582），渲染方式沿用现行做法，只换图。

## 2. 接线：键盘按机型分（换图为主，代码只改两处）

### 2.1 键帽与空格条（已接线，换图即生效）

- `KeyGrid.slug()` 取 `machineKind` 的 `-` 前缀；`cap3dRawfile()`→`cap3d-<slug>-matte.png`，空格→`cap3d-space-<slug>.png`。本批 10 张同名替换，**不改代码**，切机即换。
- 核验：切到每台机，键帽与空格条确为该年代形（1920s 高圆／1930s 中圆／1950s 低圆盘／1960s 方灰／2020s 扁平方白），五台可辨不同。

### 2.2 键盘区背景（新增一处接线）

- 键盘井底改按 `machineKind` 取 `keywell-floor-<era>.png`（`era`＝`slug()`：1920s／1930s／1950s／1960s／2020s）。渲染方式（Contain／Fill／平铺）**沿用现行 `keywell-floor-v2.png` 的做法**，只换图；若现行井底根本没用这张图（沙箱在 `KeyGrid`／`Stage26`／`Index` 里没搜到引用），桌面端先报实情：井底若只是 `tierToken keybed` 纯色，则本批 5 张底图暂不接线、只留仓，键盘区背景由 `keybed` 色（§3）承担区分——**不要为了接线而新造一个拉伸的渲染**。
- `keybed` 色本身已按机型分（§3），不改。

## 4. 自适应原则（本批重申）

- 键帽／空格条／井底的尺寸、盒比、位移均由布局量派生（`stageLayout`、`kx`、`fanW26()`／`fanH26()`），不写死设备常量；新图只提供与盒比一致的宽高比（键帽 503×512、空格 1024×270、井底 1170×582），不改布局代码。
- 平板优先验收；手机侧同源改动一并做，手机基线仍暂缓。
