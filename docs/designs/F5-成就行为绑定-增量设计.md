# F5 成就系统重设计（行为绑定版）增量设计（草稿 v2.1）

* **批次状态：** 已批准（2026-11-10，用户批准，按缺省执行）→ 实施
* **范围：** 成就系统正式落地（行为绑定版）。不含新机器、不改核心几何、不动 1920s 冻结基线。
* **相对总纲的增量：** 本稿取代旧成就设计（`docs/成就体系设计.md`）的机型绑定口径；总纲 Q2（成就阈值＋迁移口径）由本稿的待点头事项承接，用户点头后 Q2 关闭。

## 1. 相对旧设计的改动（本稿的核心决定）

1. **机型绑定作废**：旧设计"成就解锁新机器"（1920s → 1950s → 1960s → 1930s 的解锁顺序与对应成就）**全部作废**，依据是用户 2026-11-10 铁律——成就与使用行为绑定，不与特定机型绑定。
2. **四台机永久全开**：临时全解锁（2026-11-08 用户定）转为永久状态。`CollectionPage.ets` 的 `unlocked(kind)`（L59）与 `CustomizePage.ets` 的 `unlockedMachine()` 继续返回 `true`；两处"临时全解锁"注释都更新（`CollectionPage` L58 与 `CustomizePage` L71，正文相同，L58 多一个"解锁判定："前缀："解锁判定：临时全解锁……成就系统落地时改回按条件判定"——后半句与本稿"永久全开，不重锁"直接矛盾，留着会误导后续维护，随本批改掉）；收藏页的锁定态渲染分支（深色罩、锁图标、剪影透明度 0.35）成为死代码，随本批删掉（见 §7）。
3. **成就只奖行为本身**：成就是徽章＋进度，不再开任何功能、不再锁任何机器。成就名仍用时代、技术名，不用品牌名（旧设计 §1 原则保留）。
4. **分享不设检查机制**：用户原话——导出分享到社交平台一次，走常规的导出分享就行，不会设定检查机制。分享类成就只按"分享面板已调起"计数（总纲已定的 ShareKit"成功"定义：面板调起＋文件已保存），绝不检查用户是否真发出去了、发到哪里。
5. **旧设计其余部分保留**：计数口径以 §4 为准（纸张一条与旧设计不同，见 §4 注）；不做清单（不做付费解锁／排行榜／每日任务／限时活动）、史实文字与机器外观分离使用的版权口径，全部沿用。

## 3. 判定触发点

* **判定只在保存／导出事件边界跑，不走打字热路径**：落字只进 `recordChar()` 内存计数；成就判定在 `flushPending()`／`flushFoldTyped()`／保存／导出完成时跑一次（与总纲"计数在保存／导出事件时更新"一致），**且在 flush 完成之后跑**。
* **不变量（写死，防漏判）**：`consecutiveDays()` 与 `goalReached()` 都是当日快照值（今天无落字即 0，跨日归零）。判定以达成当日的 flush 时刻为准——`AchievementService` 在每次 `flushSave()` 完成后调一次 `evaluate`（保存／导出即 flush，每日至少跑一次），否则跨日后 streak 值归零、成就会漏判。**一旦达成即写 prefs 永久保存，次日值归零不影响已达成态。**
* **判定函数是纯函数**：成就条件判定（输入＝派生值＋事件计数，输出＝已达成 id 集合）写在 `model/` 纯函数里，Node 单测可断言；UI 只消费结果，不许在 UI 里再算一份。
* **达成即落盘**：新达成的成就写入 prefs（键见 §7），同时打 hilog（`achieve <id> reached`——不用"解锁"词汇）；同一成就只记一次，不重复弹窗。
* **多成就同时达成**：一次判定出多个时，AppDialog 一次只弹一个，按清单顺序排队；用户关掉一个再弹下一个，不许叠弹窗。

## 4. 计数口径（沿用旧设计 §4，实施时定稿）

* 字数：按持久化累计落字计数器计（落盘时累加，见 §7）；删除／改短不扣减；`totalWords()`（全部 active 文档字数之和）仍用于 F11/F14 显示，不用于成就判定。
* 连续天数：按自然日（Asia/Hong_Kong）有落字（≥1 字）计一天；断一天即重新累计；今天无落字＝0（`consecutiveDays()` 现行实现）；判定不变量见 §3。
* 导出分享：按成功拉起系统分享面板计；面板拉起后用户取消也计（拉起即代表完成导出动作）；**不检查是否真发出、不检查发到哪个平台**。分享与保存分开计：`onShared` 处记 `doc_shared`，`onSaved` 处记 `doc_exported`（此前两处记同一个事件，只保存不分享 10 次也会触发 `share_10`，已修）。
* 换装（字体／色带）：切换即计（事件在切换处记，见 §7 接线点）；§2 表的条件本就是"换过字体／色带 1 次"，v1 的"只切换不落字不计"删掉——该规则无实现机制。
* 纸张种类：按 `applyPaper` 成功并写入 `stats.paper.kinds` 集合计；同一种纸重复换只计一次。**与旧设计不同**：旧设计要求"切换并落字"，但 `recordPaperKind` 在 `applyPaper` 内换纸即写（`Index.ets` L1721），kinds 集合无法感知是否落字；旧设计该条随本批作废，改为换纸即计。
* 半开：按 HALF_FOLDED 状态下有落字计（`fold_typed` 计字数，第 5 批回批 F7 已落地）。
* 计数只存本地（文档元数据与成就进度均本地存储，零遥测、不上传）。

## 5. 成就达成反馈（走 AppDialog）

* 达成时弹 `AppDialog`（现有共享弹窗，遮罩与卡片须为兄弟节点——AGENTS.md 弹窗铁律：点遮罩关、点卡片不关）。
* 弹窗内容：成就名＋一句话说明（文案走资源文件，不硬编码在渲染逻辑里）；**不与 HintBar（瞬时反馈）／GuideOverlay（首次浮层）合并**（总纲提示机制分工）。
* 弹窗不阻塞打字：只在保存／导出边界触发，不在落字中途弹；用户关掉即消失，不再重弹（已落盘的成就不重复提示）。
* 收藏页常驻成就列表：每项显示成就名、说明、进度（当前值／阈值）与已达成态；未达成只显示进度，不锁任何东西（见 §6）。

## 6. 展示面与半开成就的设备差异

* **展示面＝收藏页**：收藏页在机器列表之外新增成就列表区（每项：名、说明、进度、已达成态）。F14（第 4 批）的"收藏进度"显示收敛为本成就列表的进度（阈值未批前显示"待定"，与总纲 F14 口径一致；本稿阈值批了之后才出数字）。`CollectionPage` 现有 F14 行（总字数＋连续天数，L113–130）收敛为成就列表顶部的进度区（总字数＋连续天数仍显示，阈值批了之后才出数字），不另留一行。
* **A13 半开成就（`fold_1`）**：仅折叠设备可达成。**缺省建议：保留为折叠设备专属成就，非折叠设备上该项显示"仅折叠设备"，不编造等价条件**（与旧设计"不先行编造替代规则"一致）。替代方案（用户另选）：删掉 A13。已由用户批准：保留为折叠设备专属。
* **锁定态 UI 退场**：四台机永久全开后，收藏页的锁定态渲染（深色罩、锁图标、剪影 0.35 透明度）永不触发；本批删掉这部分分支（见 §7），不留死代码。

## 9. 验证方式

* **真机逐项核对**：14 项成就逐项在平板真机上核对（截图＋hilog）：判定触发（保存／导出边界）、达成弹窗（AppDialog 内容与关闭行为）、收藏页列表（进度数字与已达成态）、追认（上线首次评估）。**A13 例外**：机队无折叠真机，A13 在折叠模拟器上验（半开态落字 ≥1 字），E1 的"真机结论"对 A13 指模拟器，另行注明。**A4/A5 时间条件**：按总纲 L367 时间条件验证法——日期注入或纯 TS 引擎单测（判定逻辑）＋单日计数验证；真实跨 3／7 天的自然验证记缺口，不冒充已验。
* **分享类只验"面板已调起"**：A7/A8 的验收＝导出后分享面板出现＋`doc_shared` 计数＋1；**不验是否真发出、不验发到哪个平台**（用户铁律：不设检查机制）。
* **判定逻辑走 Node 单测**：`achievement.test.mjs` 覆盖阈值边界与多成就并发；UI 逻辑不写 Node 单测，走真机验证。
* **基线检查逐阶段截图确认**：本批不改打字机页几何，门图（当前有效基线 917）按 AGENTS.md 口径重跑一次即可；但**绝不完全依赖自动化测试脚本**——不同屏幕有未知像素偏移，系统临时通知／消息弹窗会打乱测试；脚本只做比对辅助，逐阶段截图由实施方确认（用户 2026-11-10 铁律）。
* **不代判项**：成就弹窗的主观文案观感、收藏页成就列表的视觉密度，由用户真机看过为准；音效／实机体验／碰一碰不在本批验证范围内（"需要用户实际参与"清单）。
