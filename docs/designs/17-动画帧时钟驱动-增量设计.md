## Part I — 16 号稿 §3 的实施规格（方向已批准）

### §0 问题与根因（已读码验真）

**用户报告（2026-11-15）**：所有动画帧率低到离谱、完全不跟手、完全是机械动作。

**根因**：实现偏离了 16 号稿 §3。16 号稿 §3 明写：

> "渲染插值量（字车偏移 O、拱 x、texOffsetVp、旋钮角 knobAngle、拨杆角、字杆角）改为 Canvas 组件内部普通字段，**由帧时钟驱动，不再是 @State**（Canvas 不靠 ArkUI 状态驱动重绘）"

当前代码（远端 `c1bb9f2`，沙箱 2026-11-15 亲核）恰恰反过来：

| 插值量 | 当前实现 | 应有（16 号稿 §3） |
|---|---|---|
| 字车偏移 O | Index `@State carriageOffsetVp`，`animateTo(30ms, Linear)` 改值 → `@Prop` → Canvas `@Watch` → `draw()` | Canvas 内部普通字段，帧时钟算 |
| 拱 x | Index `@State archXVp`，`animateArch` 里 `animateTo(FastOutSlowIn)` → `@Prop` → `@Watch` → `draw()` | Canvas 内部普通字段，帧时钟算 |
| jolt | Index `@State joltYVp` → `@Prop` → `@Watch` → `redrawPaper()`（注：调的是 `redrawPaper()`，不是 `draw()`） | Canvas 内部普通字段，帧时钟算 |
| 拨杆角 | Index `@State leverRatio`（Canvas 回调 → Index 算 → `@State` → `@Prop` → `@Watch` → `draw()`） | Canvas 内直接由触摸算（见 Part II） |
| 字杆角 | 32ms Animator **已建但从未启动**（全文无 `.play()`/`.start()`），`typebarAngle` 恒为 55°，字杆从不动 | **不插值**（保持静止 55°，见 Part II Q3） |
| 打击（落字） | `runCanvasStrike()` 里 `setTimeout(() => onStrikeArrive(), 90)`——90ms 定时器一到跳变落字，中间无逐帧插值（L621 注释误称它为"Canvas 帧时钟"，迁移时一并修正） | 帧时钟 90ms 逐帧插值，结束帧调 `landHead()` |

另有两处加重：

- **同帧多 prop 变化会触发多次 `draw()`**：换行时 O、拱 x、纸一起变，每个 `@Watch` 各触发一次 `draw()`（机制推断，非实测帧数）。
- **打击是定时器＋跳变，不是插值**：90ms 内字车/纸/拱不动，90ms 一到"啪"一下到位。这就是"机械"的直接来源。

**设计本身的缺口**：16 号稿只定了"播多久"（时长＋缓动），没定"跟手程度"（输入→视觉延迟预算、动画期间帧率、拨杆直驱）。时序验收（第 18 批）只验了"播了多久"（全在容差内），没验"播得顺不顺、跟不跟手"。

**不是原理层问题**：Canvas 与设备能跑 120fps（P2 探针手机 122fps、p95 绘制 1ms）。`draw()` 本身也不贵——它主要是拼已缓存的 ImageBitmap（背景/机器/纸/前层）＋画动层。问题在**驱动机制**，不在 Canvas 能力。另有一处已知逐帧开销：`drawRollerLayer` 每次调用都新建一个 `CanvasGradient`（`createLinearGradient`＋5 个 `addColorStop`）——本次不改；若帧时钟落地后仍掉帧，缓存渐变是最先动的点（见 §6）。

### §1 目标与非目标

**目标**

1. 动画由**单一帧时钟**驱动，数值按**时间**算（不是按帧数算），在 60Hz 与 120Hz 屏幕上都正确（同一时长、同一缓动曲线、同一落点）。
2. 输入直达画面：拨杆拖动 1:1 跟手（≤1 帧延迟）；打字/删除/换行等反馈在 1 帧内开始动。
3. 每帧只画一次（帧时钟的 `draw()` 每帧一次，不按 prop 个数重复）。
4. 时序表不变：90/200/300/70ms 等时长与缓动曲线原样保留；已测的时序数（第 18 批）仍为验收目标。

**非目标**

- 不改时序表的时长与缓动（不把 90ms 改成 50ms 来"显得快"——问题不在时长，在平滑与跟手）。
- 不改视觉外观、机器图、纸、拱、拨杆的画法；字杆保持静止 55°（不恢复摆动，见 Part II Q3）。
- 不改数据层（DocModelCore、换行/换纸逻辑、成就、导出）。
- 不做 60Hz 与 120Hz 的**对照实测**（同一动画在两种刷新率下各跑一遍比时长）；兼容性由时间插值设计保证。验收仍用 hilog 验时长与帧间隔（第 18 批口径）——这是时长验收，不是刷新率对照。
- 不碰声音（声音测试已暂停）。
- Canvas 不渲染滚筒纹理滚动与旋钮（`texOffsetVp`／`knobAngle` 留在 Index `@State`，仅供 ArkUI 回滚分支；是否在 Canvas 里恢复它们，另立项）。

### §2 核心设计（实施规格）

#### 2.1 一条原则：数值按时间算，不按帧数算

每个动画由**起点时间 t0（ms）＋时长 duration（ms）＋起点值 v0＋目标值 v1＋缓动函数 easing**定义。帧时钟每帧回调时：

```
now = 时钟时间戳（实际值，不假设帧间隔；来源见 2.2）
progress = clamp((now - t0) / duration, 0, 1)
value = v0 + (v1 - v0) * easing(progress)
if progress >= 1: value = v1（精确落点，不留帧量化误差）
```

这条原则是 60/120Hz 兼容的全部关键：

- **60Hz 与 120Hz 时长相同**：60Hz 一帧 16.7ms、120Hz 一帧 8.3ms，同一 90ms 动画在 60Hz 约 5 帧、在 120Hz 约 11 帧，但**墙钟时长都是 90ms**，缓动曲线相同，落点相同。帧数不同是正常的，不是缺陷。
- **掉帧不累计误差**：某帧丢了（设备忙），下一帧按实际 `now` 算 progress，直接跳到正确值，不会越拖越慢。动画永远按时完成。
- **短动画帧数少是正常的**：70ms 删除在 60Hz 只有约 4 帧（progress 约 0.25/0.5/0.75/1.0，经缓动），在 120Hz 约 8 帧。两者都正确。**不许**以"帧数太少"为由改时长或加帧——帧数是屏幕决定的，不是动画决定的。
- **不许假设帧间隔**：永远用实际帧时间戳算 `now - t0`。不许写"每帧 +8.3ms"或"每帧 +16.7ms"这类按固定帧率算的代码——那在另一帧率的屏幕上会错。
- **刷新率在动画中途变化同样安全**：progress 始终由墙钟时间算，帧数变化不改变时长与落点。本设计覆盖任意刷新率（60/90/120Hz 及自适应刷新）。

#### 2.2 帧时钟：单一、常驻、按实际时间戳，带空闲规则

- CanvasTypewriter 内建**单一帧时钟**：用现行 `Animator.create`（`'@kit.ArkUI'`，与 `strikeAnimator` 同一 API），配置定死为：
  `{ duration: 1,000,000, easing: 'linear', begin: 0, end: 1,000,000, iterations: -1, fill: 'forwards' }`。
  `begin=0、end=1,000,000` 使 onFrame 的 value 即已过毫秒（时钟时间戳）；`iterations=-1` 使时钟常驻不跑停（`iterations=1` 会在约 16 分钟后停摆）。若 `iterations: -1` 在目标 SDK 上不支持，改为"跑完重建并记 t0 偏移"，并在批报告里写明。
- `now` 即 onFrame 的 value（流逝毫秒）。**全稿只用这一个时间源**；不另用 `Date.now()`（时钟源唯一，不混用）。
- `onframe` 里做三件事（顺序固定）：
  1. 取本帧时间戳 `now`（onFrame 的 value）。
  2. 对每个**活动中的动画**，按 2.1 的公式算当前值，写入 Canvas 内部普通字段。
  3. `draw()` **一次**（若按空闲规则应跳过，则不画，见下）。
- **空闲规则**：onframe 里先判"是否有活动动画（任一动画 progress < 1）或正在进行的拨杆拖拽"；若无，**跳过 `draw()`**（不画），只更新时钟时间戳。动画是间歇的，静止是常态；跳过空闲 draw 既省电，也让屏幕可以自适应降帧（不把屏幕钉在高刷新率上）。
- **生命周期**（"只建不启"的现行 bug——`strikeAnimator` 从未 `.play()`——是警示，批 1 验收须验证时钟真的在跑）：

| 时机 | 动作 | 内部字段 |
|---|---|---|
| 挂载 `aboutToAppear` | 若时钟不存在则创建（2.2 配置）；按 2.5 从 Index 同步初值；调 `play()` 启动时钟 | 按 2.5 同步，不重置为 0 |
| 打字机页在前台 | 时钟跑；onframe 按空闲规则画或跳过 | 随动画更新 |
| 离页 `aboutToDisappear` | 调 `pause()` 停时钟（只停时钟，不清字段） | 保留（回页恢复原样） |
| 重进页 `aboutToAppear` | 调 `play()` 续跑（不重建、不重置字段） | 保留 |
| 导航栈顶非 typewriter | 同离页：暂停时钟 | 保留 |
| 卸载 | 调 `cancel()`，释放时钟 | — |

#### 2.3 逻辑值 vs 渲染值（双源问题定死）

Index 的 `@State` 与 Canvas 的内部字段分工如下，解决回滚分支与 Index 逻辑读数的冲突：

| 值 | 存放 | 谁写 | 谁读 |
|---|---|---|---|
| **逻辑值**（目标 O、目标拱 x、目标 paperTopVp 等） | Index `@State`（保留，不删） | Index 的逻辑（换行/换纸/删除算目标）＋ ArkUI 分支的 `animateTo`（见下） | Index 逻辑（`clampedStrikeXVp`、paperLeft、stepCarriage 目标计算）＋ ArkUI 回滚分支的 `CarriageLayers`／`LeverLayer` |
| **渲染值**（当前 O、当前拱 x、当前 paperTopVp 等） | Canvas 内部普通字段 | 帧时钟（按 2.4 的触发＋目标插值） | Canvas 的 `draw()` |

- **ArkUI 分支的 `animateTo` 保留**：canvas 关时，ArkUI 分支仍走现有 `animateTo`（字车、拱、jolt、旋钮、滚筒纹理、拨杆全按现行方式动）。`animateArch`、`stepCarriageLeft` 等函数不删，内部按 `canvasEnabled` 分流——canvas 开时走帧时钟触发，canvas 关时仍走 `animateTo`。双路径并存是回滚的代价。
- **同步**：Index 算出目标后（逻辑值），经 2.4 的 tick＋目标 prop 发给 Canvas；Canvas 的渲染值向目标插值。回滚切换瞬间，ArkUI 读 Index 逻辑值（始终是最新的目标值），不读 Canvas 渲染值——两者在静止时一致（渲染值最终落点即目标值），切换时无跳变。
- **四机 `leverRatio` @State 与 `leverRatio()` getter/setter 保留**：ArkUI `LeverLayer` 仍用它们；Canvas 的拨杆角改内部字段（见 Part II），不再读 `leverRatio` prop。

#### 2.4 触发通道：tick 计数 prop＋映射表

ArkTS 里父 struct 不能直接调子 struct 的方法。触发通道定死为 **tick 计数 prop**（复用现行 `canvasStrikeTick` 的已验证模式：Index 递增 → Canvas `@Watch` 触发）。

| 触发 | tick prop（Index 递增） | 伴随目标 prop（Index 先设值、再递增 tick） | 对应现行接口 |
|---|---|---|---|
| 打击 | `canvasStrikeTick`（已存在，保留） | 目标 O、目标拱 x | `onStrikeArrive`（Canvas 回调给 Index，保留） |
| 删除 | `canvasDeleteTick`（新增） | 目标 O（右退一格） | `stepCarriageRight` 的触发点（改发 tick，不再 `animateTo`） |
| 换行 | `canvasNewlineTick`（新增） | 目标 paperTopVp/paperContainerVp、目标 O（回 0） | `onNewline` 的触发点 |
| 换纸 | `canvasPaperTick`（新增） | 目标 paperTopVp/paperContainerVp（新纸） | `onPaperChange` 的触发点 |
| 退行 | `canvasBackTick`（新增） | 目标 O、目标 paperTopVp | `onBackLine` 的触发点 |

- **载荷**：tick prop 本身只是一个计数（无载荷）。目标值放在伴随的"目标 prop"里，Index 在递增 tick **之前**先设好目标值；Canvas 的 `@Watch` 收到 tick 变化时读目标 prop、记 `t0 = 时钟 now`、开始插值。jolt 不另设 tick（它是打击的附属小动画，与打击同 t0，见 2.6）。
- **命名**：v1 发明的 `onStrikeStart`／`onDeleteStart` 等名字全部删掉，改用 tick prop 名；现行回调 `onStrikeArrive`、`onLeverStart`／`onLeverUpdate`／`onLeverEnd` 保留，不擅自删除或改名。

#### 2.5 挂载初值同步：一次性初始 prop

CanvasTypewriter 在离页时销毁、回页时重建；内部字段若初值全是 0，文档打到一半回页会显示字车在 0 位。补同步机制：保留**一次性初始 prop**（如 `initialCarriageOffsetVp`、`initialArchXVp`），Canvas 在 `aboutToAppear` 里读一次、写入内部渲染字段，之后不再参与逐帧（不触发 `@Watch`→`draw()`）。切机/切纸时同样走一次初始同步（字段按新机/新纸的初值重置）。

#### 2.6 各动画的时间定义（按 16 号稿 §3.3，逐项定死）

共享**时钟**（同一个 `now`），但**各值用各自的 t0 与时长**（不许"同一 progress"）：

| 动画 | t0 | 时长与曲线 | 目标 |
|---|---|---|---|
| 打击·拱 | 打击触发时 | 90ms，FastOutSlowIn | clampedStrikeXVp |
| 打击·O（字车步进） | `landHead` 那帧（打击 90ms 结束、字符落下之后） | **30ms，Linear** | 当前 O − travelPerChar |
| 打击·jolt | 打击触发时 | 40ms：0–20ms Linear 上升到峰值 **1vp**，20–40ms 回到 0 | 纸面行文字与光标三角的 y 偏移 |
| 删除弹簧 | 删除触发时 | 70ms，`springCurve(0,1,260,20)` | O 右退一格 |
| 换行·纸上滑 | 换行触发后 150ms（拨杆段结束） | **300ms，EaseInOut** | 上滑一行高（`paperTopVp`／`paperContainerVp` 成对） |
| 换行·字车回位 | 换行触发后 450ms | 250ms（现行编排） | O 回 0 |
| 换纸 | 换纸触发时 | 300＋300ms（纸上滑 300ms＋新纸落位 300ms；实施时若映射不符，以代码为准并在批报告里写明） | 新纸位置 |
| 退行·O | 退行触发时 | 250ms | O（现行 L3208） |
| 退行·纸飞出 | 退行触发时 | 300ms | paperTopVp（纸飞出） |
| 换行/复位 jolt | 换行/复位触发时 | 40ms，峰值 **2vp** | 同打击 jolt |

- **打击的结束帧**：progress≥1 的那帧，值全部精确落点，并调 `onStrikeArrive()` → `landHead()`（与现行一致：去程结束帧落字）。200ms `armFallback` 兜底保留（判据 `arrivedSince` 不变；批 1 验收：20 连打中 `typebar fallback` 日志出现 0 次）。
- **字杆**：不插值，保持静止 55°（Part II Q3）。32ms Animator 作为死代码在迁移批里删除。
- **退行的 paperOpacity／knobAngle／texOffsetVp**：不迁入（ArkUI 分支专属值，Canvas 不渲染）。Canvas 的退行只移动 paperTopVp，不做透明度渐变。
- **拨杆的释放动画**：见 Part II（拨杆直驱批）。

#### 2.7 每帧只画一次＋onDocChanged 去重

- 帧时钟 `onframe` 里：算完所有活动动画的值后，`draw()` **一次**。
- `@Watch` 仍保留，但只用于**非逐帧**的 prop 变化（换机、换纸、候选栏变）：那些是低频事件，一次 `draw()` 是对的。逐帧的插值量不再是 `@Prop`，所以不会再有"多 prop 同帧改 → 多次 `draw()`"。
- **`onDocChanged` 去重**：文档内容变化（`lines`／`cursorXVp`／`cursorYVp`／`paperTopVp`／`paperContainerVp`）时，`redrawPaper()` **只更新纸层位图**（paperLayer），不上屏；上屏由帧时钟的下一帧 `draw()` 完成（≤1 帧延迟，符合启动预算）。帧时钟空闲（无活动动画）时，`redrawPaper()` 可直接 `draw()` 一次（避免文字延迟出现）。两者由"帧时钟是否活动"分流，不同时发生。
- `draw()` 本身不动（拼缓存 ImageBitmap＋画动层）。`drawRollerLayer` 每帧新建 `CanvasGradient` 的开销已知（见 §0），本次不改。

### §5 备选方案

| 方案 | 为什么不选 |
|---|---|
| **混合方案**（Index 单 animator 每帧写全部 @State 值＋拨杆直驱） | 它确实存在，且改动面比全量迁移小。但它**没有解决核心开销**：每帧仍要走 @State→prop→组件重渲染管线（6 个值 × 每帧），且多个 prop 的 `@Watch` 仍会在同帧触发多次 `draw()`（除非另加批处理逻辑——那就又引入一套批处理机制）。全量迁移只有一套机制（Canvas 内写 6 个普通字段＋1 次 `draw()`），且与已批准的 16 号稿 §3 一致（"Canvas 不靠 ArkUI 状态驱动重绘"）。选全量迁移的理由是**分层正确＋单机制＋与已批准设计一致**，不是"@State 做不到"。 |
| **用 requestAnimationFrame** | ArkTS Canvas 没有 requestAnimationFrame。`@ohos.animator`（经 `Animator.create`）是现有帧时钟机制，沿用它。 |
| **缩短时长来"显得快"**（如打击 90ms→50ms） | 问题不在时长，在平滑与跟手。缩短时长改的是手感（打字机打击本就有分量），不修根因。时序表不动。 |
| **只修拨杆直驱，不动其他动画** | 拨杆只是最明显的一处；打击的 setTimeout 跳变、O/拱的 @State 驱动是同一根因。只修拨杆会留下"打字仍机械"的问题，用户反馈的是"所有动画"。 |
| **每帧全量重绘改为局部重绘**（只重画动的部分） | `draw()` 已是拼缓存位图＋画动层，P2 证 1ms 量级，不是瓶颈。瓶颈在驱动机制（谁算值、多久算一次），不在绘制量。局部重绘是优化项，不是本稿范围；若帧时钟落地后仍有掉帧，再立项。 |

### §6 回滚与风险

- **回滚开关**：`canvas.enabled`（缺省 true，见 16 号稿 §6）保留。关掉回旧 ArkUI 主屏（现行 ArkUI 主屏保留作回滚，见 16 号稿 §2.2）。本稿不删旧 ArkUI 主屏。
- **风险 1：帧时钟不按显示帧率回调**。判定阈值：连续 10 帧中帧间隔超过 2×当前帧间隔的次数 ≥3，或单帧间隔超过 5×当前帧间隔，即判定成立。成立时：停、批报告记 BLOCKED（附 hilog 原文）、半成品代码留在分支不推 main、报用户定夺；**不许**用 `setTimeout` 绕路拼凑。
- **风险 2：帧时钟与 Index 逻辑的时序竞态**。应对：帧时钟只算**渲染值**（角度、偏移），不算**逻辑状态**（换行是否触发、纸是否满）；逻辑仍在 Index，渲染值只跟随逻辑下发的触发与目标。边界见 2.3 的逻辑值/渲染值表（不是一句"写进代码注释"）。
- **风险 3：60Hz 屏上短动画帧数少，看起来"跳"**（如 70ms 删除在 60Hz 只有约 4 帧）。应对：按 2.1 定案执行（帧数由屏幕定，不加帧）；若用户真机反馈跳，另立项讨论，不在本稿内解决。
- **风险 4：迁移中改坏现有时序**（第 18 批刚测完的数）。应对：每批验收都复测对应时序（hilog 口径不变）；批 1 验收明确要求"全部时序仍在容差内"（见 §7 回归项）。

## Part II — 新设计决定（报用户批准）

### §7 拨杆直驱边界（批 2）

**角度归 Canvas，逻辑归 Index。**

- Canvas 的 `onTouch` 里，`TouchType.Move` 时**直接**按 `LeverAngleCore.dragRatioFor(dy, leverH)` 算 `leverRatio`（内部字段），`leverH` 复用 `drawLever` 已有的计算（`leverW = Hc * 1.84/2.5 * leverSizeRatio(spec)`，`leverH = leverW / spec.leverAspect`）。**角度不经过 Index，不经过 @State，不经过 @Prop。**
- 触摸 Move 里**只改字段，不直接调 `draw()`**；重画由帧时钟的下一帧完成（≤1 帧，符合预算）。不许在触摸回调里直接调 `draw()`（避免与帧时钟同帧重复）。
- 回调 `onLeverUpdate(dy)` 仍调给 Index，但**只用于逻辑**：Index 据此判断是否过半（`LEVER_COMMIT_RATIO = 0.5`）、是否触发换行。Index 不回写角度。
- **一致性不变量**：Canvas 与 Index 用**同一纯函数**（`dragRatioFor(dy, leverH)`）、**同一 dy**、**同一阈值**（0.5）。dy 的源头是 Canvas 的触摸 Move 事件；Canvas 由它算角度（渲染），Index 由 `onLeverUpdate` 回调收到的同一 dy 算 ratio（逻辑）。**释放瞬间的判定以 Index 在释放事件到达时持有的最后 dy 为准**；Canvas 只负责画，不判过半。若某 Move 事件在转发中丢失导致两侧 ratio 短暂分歧，释放动画的触发以 Index 的判定为准（Canvas 按 Index 的判定结果播过半/不到半动画，不按自己算的 ratio）。
- **释放编排归属**：松手时——过半：Index 触发换行（`onNewline`，照旧），Canvas **并行**播 200ms 拨杆提交动画（拨杆摆到满摆，对应 16 号稿 §3.3"回程 200ms"）；两者不互相等待，各有 t0（拨杆动画 t0 = 释放时，换行编排 t0 = Index 触发时）。不到半：Index 不触发换行，Canvas 播 150ms 回弹动画（回静止角，对应 16 号稿 §3.3"拖拽回 0 时 150ms"；另有 150ms 去程）。提交进行中收到打字输入：正常排队（打击触发独立），拨杆动画与打击动画并行（都在帧时钟上），不阻塞输入（现有的 `paperChanging`／`newlineBusy` 逻辑闸门不变，是逻辑层闸门，不是渲染层阻塞）。

### §8 预算表（验收标准）

| 项 | 预算 | 测量方法 |
|---|---|---|
| 打字反馈启动 | ≤1 帧 | Index 发触发时记 hilog `trigger strike t=<时钟 now>`；Canvas 在首次画出新值（value ≠ v0）的那帧记 hilog `first frame strike t=<时钟 now>`。启动延迟 = 两者之差，要求 ≤1 帧间隔（按当前刷新率：120Hz ≤8.3ms，60Hz ≤16.7ms）。 |
| 拨杆跟手 | ≤1 帧 | 触摸 Move 事件时间戳（TouchEvent 自带）vs 首次角度变化的那帧（同上方法）。 |
| 删除/换行/换纸反馈启动 | ≤1 帧 | 同打字（各触发记 `trigger <kind>`＋`first frame <kind>`）。 |
| 动画期间帧率 | 跟随当前显示刷新率，无持续掉帧 | 帧间隔打点（见下）；**孤立掉帧 ≤2 次记 PASS（记不符点），连续掉帧（两次以上长间隔）为 FAIL**。掉帧定义：连续两帧间隔超过 2×当前帧间隔。 |
| 动画时长 | 时序表原值（±20ms） | 沿用第 18 批 hilog 口径（起点＋首次到达目标两条打点）。 |

**日志格式**（取代 `animateTo` 时代的旧事件名）：

- 触发 `trigger <kind> t=<now> target=<value>`（Index 发触发时）。
- 开始 `anim start <kind> t0=<now>`（Canvas 收到触发记 t0 时）。
- 到达 `anim arrive <kind> t=<now> dt=<now - t0>`（Canvas 在 progress≥1 的帧）。
- 帧 `frame tick now=<now> interval=<ms>`（只在有活动动画的测试段内逐帧记；空闲时不记，避免 hilog 本身扰动时序）。
- `canvas landHead dt=<ms>` 保留（帧时钟的 progress≥1 帧调同一 `onStrikeArrive()`→`landHead()` 链）。
- 旧事件名（`arch move start/finish`、`carriage spring start/finish`）在帧时钟动画里停用。

**刷新率获取**：不另取 API，**由帧间隔中位数推断**（8–9ms 判 120Hz，16–17ms 判 60Hz）。

**测试段定义**（掉帧验收的范围）：一次 20 连打＋一次换行＋一次换纸＋一次拨杆拖拽（过半）＋释放，各为独立 hilog 窗口。

**验收不靠视频**：视频是 VFR，不能作毫秒计时。验收靠 hilog 帧时间戳（帧间隔、启动延迟、到达时间）＋视觉确认（平滑、无跳变、拨杆跟手）。这是 16 号稿 §3.3 与手册 §5 的既定口径，本稿沿用。

**回归项**：

- 批 1 验收须复测——16 号稿 §3.3 时序表全部项（落字 90ms、删除 70ms、换行三段、换纸 300＋300ms、退行、jolt）＋第 17 批已 PASS 项（字车步进、跟手）＋第 18 批已 PASS 项（拱移动、删除弹簧、菜单/页面/换装、候选栏滚动）的**动画相关**项。
- 批 2 验收须复测 C2（过半 3 次／不到半 3 次）＋换行（拨杆触发它）。
- **主观验收**：用户手机真机确认"顺了、跟手了、不机械了"——这是最终验收，hilog 与视频都替代不了。
- **截图**：从 **1400** 起续号，若已占用则顺延并在记录里写明。
