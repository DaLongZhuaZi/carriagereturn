# 26-增补-35-批70-纸视口锁死：把裁切边界移到屏顶、纸高还给内容

## 0. 背景与判定

- 批 69 桌面端推回 `66f01ac`（2026-11-21 22:41）：删了 `capTop` 钳制与纸高封顶（`Index.ets` 两处）。自检 hilog 称 `paperTopVp` 一路下探到 −162.1vp、`paperGrowVp` 线性涨到 567.3vp、纸底恒定。
- 用户 2026-11-21 22:54 在最新提交上指出问题**依然没有解决**：纸在被上面“挡住”之后依然向下延伸，而不是正确向上移动。用户要求分析“被什么锁死的”。
- 沙箱结论（读码＋识屏＋PIL）：**锁死纸的不是 `paperTopVp`／`paperGrowVp` 这两个量，而是渲染纸的容器——`Carriage26` 里的纸视口。** 批 69 只改了 `Index.ets` 的量，没动 `Carriage26` 的布局，所以没修到点子上。批 68、69 两次“修纸”都只动了量、没动容器，这是第三次必须动容器的原因。

## 1. 根因（读码，`66f01ac`；识屏 2325）

### 1.1 锁一：视口 `.clip(true)` 把纸裁在纸区顶（56vp）——纸顶永远看不见 56vp 之上

- `Carriage26.ets` 纸视口 Stack：`.height(this.paperAreaH())`（319.9vp）＋`.clip(true)`。它在纸区（56–393.9vp）里，顶在 56vp。`.clip(true)` 把纸裁在 Stack 的边界内——**纸顶永远只能到 56vp，再往上就被裁掉、看不见**。
- 批 69 的 `paperTopVp → −162.1vp` 是**算出来的量**，不是渲染出的位置：渲染出的纸被这个 clip 裁在 56vp，−162.1vp 的那部分根本没画出来。用户看到的纸顶永远停在 56vp（屏上约 133px）——这就是“被上面挡住”。
- 批 69 自己的注释也承认了这一点（`paperVisibleTargetVp()`）：“多出来的部分从视口顶出去、**被视口 clip 裁住**”。桌面端以为“裁住”就是“出屏”，但裁住＝看不见＝挡住。用户要的是**看见纸往上走、超出屏幕边缘**，不是被裁在 56vp。

### 1.2 锁二：内层 Column 定高 `paperAreaH()` 把纸高钳在视口高（319.9vp）

- 内层 Column：`.height(this.paperAreaH())`（319.9vp，定值）＋`justifyContent(End)`。纸（`PaperPanel26`，高 `paperH()＝paperGrowVp`，16 行时 494.7vp）是它的 flex 子项。容器只有 319.9vp 高，纸再长也被钳在这个框里——**渲染出的纸高就是视口高（319.9vp），不是内容高（494.7vp）**。纸顶在 56vp、纸底在 375.9vp，一个固定大小的矩形，永远长不高、永远上不去。
- 实测证据（2325，PIL x=800）：奶油色从 y≈140px 到 y≈885px，**可见纸高 745px＝314vp≈视口高**，顶在纸区顶（约 133px）、底在视口底（约 893px）。纸高（内容）明明是 494.7vp，渲染出来却只有 319.9vp——锁二坐实。

### 1.3 后果：量与渲染错位——字被顶到视口之下（“向下延伸”）

- `paperScroll26()` 按**逻辑纸高**（`paperGrowVp`＝494.7vp）算滚动：16 行时只滚 3.5vp，以为纸够高、光标（纸内 466.1vp）装得下。
- 但**渲染出的纸只有 319.9vp 高**，光标（纸内 466.1vp）落在渲染纸底（319.9vp）之下 **146.2vp**——当前行被顶到视口之下、进字篮井区（或被纸自身的 clip 裁掉）。字出不来、纸面空白——**2325 的纸全是空白、一个字都没有，就是这个错位的铁证**（早先的行在视口之上被视口 clip 裁掉，当前行在渲染纸底之下被纸 clip 裁掉，两头都看不见）。
- 用户看到的“向下延伸”就是这个：纸（内容）长不上去（锁一＋锁二），字只能往下顶、顶出视口底。

## 2. 修法（都在 `Carriage26.ets`，布局层；`Index.ets` 不动）

### 2.1 把裁切边界从纸区顶（56vp）移到屏顶（0vp）——视口 Stack 向上长到屏顶

- 视口 Stack：高改为 `paperAreaH() ＋ topBarH`（319.9＋56＝375.9vp），并整体上移 `topBarH`（56vp），使其顶在屏幕顶（y=0）。`.clip(true)` **保留**——现在它裁在 0vp（屏顶）和 375.9vp（视口底）：纸从屏顶往下可见，纸顶（0vp 之上）自然出屏；纸底仍在 375.9vp 被裁住，拖纸下滑时不会画进字篮井（批 68 的滑动仍受保护）。
- `topBarH` 由 `stageLayout.topBarH`（`Stage26.ets` 的 `TOP_BAR_H＝56`）推导，**不写死 56**。`stagePaper()` 传新 prop `topBarHVp: this.stageLayout26().topBarH` 给 `Carriage26`。
- 纸长时会盖住顶栏区（0–56vp，含时间/设置字样），**这是用户要的效果**（纸往上走、超出屏幕边缘，本来就要从顶栏前面过；真打字机纸就是从机器顶前面出来的）。用户想看顶栏时把纸往下滑（批 68 的滑动）即可。自检里写清这一点，不当 bug。

### 2.2 把纸高还给内容——内层 Column 不再定高为视口高

- 内层 Column：`.height(this.paperAreaH())` → **`.height(this.paperH())`**（纸高＝内容高，`paperGrowVp`）。Column 随纸长高，不再把纸钳在 319.9vp。
- `PaperPanel26`（及纸上缘阴影、压纸杆）加 `.flexShrink(0)`——双保险，纸绝不被 flex 压扁回视口高。
- 内层 Column 在（加高后的）视口 Stack 里**贴底**（Stack 的 `alignContent` 改 `Alignment.Bottom`，或等效的贴底写法）：纸底恒在 Stack 底（375.9vp＝视口底），纸顶＝视口底 − 纸高，随纸高上移、可一直出屏顶。
- 落字指针／TriMark 的 y 目前是 `paperAreaH() − 15`／`paperAreaH() − 6`（相对 Stack 顶）。Stack 加高后，改为 **`(paperAreaH() ＋ topBarH) − 15`／`(paperAreaH() ＋ topBarH) − 6`**（相对 Stack 顶＝屏顶，仍落在视口底附近的落字位）。一律由 `paperAreaH()` 与 `topBarH` 推导，不写死。

### 2.3 自适应总则

- 本批所有尺寸：视口高 `paperAreaH()＋topBarH`、上移量 `topBarH`、内层 Column 高 `paperH()`、指针 y `(paperAreaH()＋topBarH)−15/−6`，一律由 `stageLayout`（`topBarH`／`paperH`）与 `paperGrowVp` 推导，**不引入任何写死的 y/vp 常数**。`Index.ets` 的 `paperTopVp`／`paperGrowVp` 不动（批 69 的量已经是对的，锁在容器）。
