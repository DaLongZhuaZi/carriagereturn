## D0：坐标帧与代码模型（v2 已钉死，v7 只补一处事实）

- **坐标帧（探针实测，PIL）**：内屏窗口 **1828（宽）×2584（高）px**，外屏 1264×1848 px。本 draft 一切 y 坐标均以该帧为准。
- **isTablet 是窗口派生的布局分级，不是设备类型**：`Index.ets` `measureStage()`（L1204–1240）每次 onAreaChange 重算：`newTablet = tabletDevice && (availW >= 600)`，`tabletDevice = dev === 'tablet' || dev === '2in1' || diagInch >= 7.0`，`this.isTablet = newTablet`。折到外屏时窗口缩到 1264×1848，若密度如常（vp2px > 2.11），availW 跌破 600，isTablet 自动翻 false；批报告记实测 vp2px。**该断言不是判定式的依据**（FOLDED 有显式分支兜底），只是"冗余一致"的说明。
- **窗口尺寸来源**：根 onAreaChange handler 在 `Index.ets` L4517（调 `measureStage()`）；L3388／L3898 为子组件 handler。`measureStage()` 在 L1204–1240；**首次 measureStage 在 aboutToAppear（L1145）**，首帧即执行。
- **diagInch 的不确定性**：`screenDiagonalInch()` 读 `display.getDefaultDisplaySync()`；折叠后默认显示屏是否切换到外屏、diagInch 是否随之变，本轮不依赖它做**折叠分支**判定（折叠分支只用 foldState 与折痕朝向；第 3 条 fallback 沿用现行 isTablet（含 diagInch），属既有行为，不动）；实施轮在批报告里记实测值，不阻塞。
- **总成结构**：外层 Column 顺序为 topInset 间隔→TopBar→总成内 Column（paperTopGap＋总成 Stack）→CarriageStrip（`useLayers` 为假时，`Index.ets:3953–3967`，高 `carriageHeight`，`.margin({ top: -CARRIAGE_PAPER_OVERLAP_VP })`，净高 stripH＝`carriageHeight − 8`；为真时为 0 高占位）→CandidateBar→FontBar→PhotoKeybed→FunctionRow。总成 Stack（`Index.ets:3420` 起，含 PaperStage）自身的高度表达式在 `Index.ets:3896`：`.height(this.isTablet ? this.availableHeightVp : this.regionHeightVp)`；其外层 wrapping 节点挂 `.layoutWeight(1)`（`Index.ets:3951`）。Stack 的 onAreaChange（L3898）实测 `assemblyHeightVp`（`Index.ets:153`）与 `stackTopGlobalYVp`（L194）。

## D0b：折叠感知的执行机制

**问题**：现行全部几何选择都按 `isTablet` 分支，与 `foldState` 无关——`recalcPaperHeight`（L1730–1810）的 kTop／H／strikeShift／bandShift、`measureStage` 的 stageW 上限／region／keybedHeight／candBarVp、`PhotoKeybed` 的 `foldBand`（Index.ets L4018 现传 `false`）、**总成 Stack 的高度表达式（L3896）**。D1 给了公式、D4 给了触发，但没有一处写明"函数在 HALF_FOLD 时改取上半区 H"——而 `frozenHVp`（L196／L1732–1737）会主动挡住它：首次稳定后 H 永远是整窗可用高，按 D4 字面调用现有函数，HALF_FOLD 时 `carriageTopVp = 0.56 × 整窗 H`，打击行仍落到折痕带之下。

**机制（写死五点）**：

1. **单一派生：`layoutMode`**。Index 内新增派生函数 `deriveLayoutMode(): 'tablet' | 'phone' | 'desk'`，输入为 FoldService.foldState＋creaseHorizontal＋isTablet，判定如下（唯一判定式，v4 以 foldState＋折痕朝向为输入）：
   - `foldState == FOLDED` → `'phone'`
   - `foldState == HALF_FOLD` ＋ 折痕横向（`creaseHorizontal == true`） → `'desk'`
   - `foldState == HALF_FOLD` ＋ 折痕纵向（`creaseHorizontal == false`） → `'tablet'`（回退展开态，D2 真值表；窗口不变、isTablet 仍 true）
   - 否则 → `isTablet ? 'tablet' : 'phone'`
   **存储形态与调用时序写死（v7：refresh 在 derive 之前）**：Index 新增 `@State layoutMode`；`measureStage()` 内顺序为：**先算 newTablet 并更新 isTablet（现行 L1237–1240），再调 `FoldService.refreshCrease()` 重读折痕区（见 D1），再调 `deriveLayoutMode()` 更新 layoutMode，再用 layoutMode 分支算 region／keybed**（先算后用，与现行 isTablet 的 newTablet 模式一致）；折叠回调里调 `deriveLayoutMode()` 后立即重算；几何函数只读该 @State，不直接调派生函数。**初值与首次派生**：`layoutMode` 初值为 `'phone'`（与 `isTablet` 初值 `false` 一致，`Index.ets:248`）；**首次 measureStage 在 aboutToAppear（L1145），首帧即派生 layoutMode**；初值仅在 aboutToAppear 之前（组件构造期）有效，不进入首帧布局；FoldService 未就绪（非折叠设备）时恒为 `isTablet ? 'tablet' : 'phone'`。
   **H 与 region／keybed 读 `layoutMode`；kTop／strikeShift／bandShift 在 desk 时沿用 `isTablet` 三元的平板值**（HALF_FOLD 时窗口不变、`isTablet` 恒 true），不另分支。
2. **分支点清单（逐个点名，HALF_FOLD／FOLDED 时以 `layoutMode` 为准）**：
   - `recalcPaperHeight`：`'tablet'` → 现行平板路径（`H = frozenHVp`）；`'phone'` → 现行手机路径（`H = regionHeightVp`）；**`'desk'` → `H = creaseTopVp − topInset`，绕过 `frozenHVp` 冻结（冻结只适用于非折叠态；`frozenHVp` 本身不清零——切回 EXPAND 时继续用冻结值，避免反复冻结／解冻）**。`'desk'` 时 kTop 沿用 0.56，strikeShift／bandShift 取 15（平板值）。
   - `measureStage`：`'desk'` → `regionHeightVp = creaseTopVp − topInset − topBarHeight − paperTopGap − carriageConsumed`（纸区＝上半区）；`keybedHeight = stageW / 折叠带比值`（按机：1920s／1950s／1960s 用 2.401，1930s 用 2.101；**desk 的 keybedHeight 在 `photoWidthCap` guard 之后算，或 guard 同步改用折叠带比值**——现行 guard（L1275–1281）在 `availW × vp2px > 2048` 时把 keybedHeight 改回 `capped / 2.101`，会把折叠带图压扁约 14%；模拟器上不触发（内屏 1828px ＜ 2048），批报告记实测是否触发）；`candBarVp = 0`（与平板同）；stageW 上限 776 不变。`'phone'`／`'tablet'` → 现行路径。
   - **总成 Stack 高度**：高度表达式（`Index.ets:3896`，`.height(this.isTablet ? this.availableHeightVp : this.regionHeightVp)`）补进分支点清单：`'desk'` 时取**上半区高（`creaseTopVp − topInset − topBarHeight − paperTopGap`，与 region 公式同源）**；`'tablet'`／`'phone'` 时沿用现行表达式。**推导**：Stack 顶边位于 `topInset ＋ topBarHeight ＋ paperTopGap`（总成内 Column 里 paperTopGap 之下即 Stack）；Stack 高取上半区高 ⇒ Stack 底边＝`creaseTopVp`。该推导与 region 公式自洽（region＝Stack 高 − carriageConsumed）。
   - `PhotoKeybed`：Index 传 `foldBand: (layoutMode == 'desk')`。该 prop 已存在（`PhotoKeybed.ets` L34，L204／212／218 按机静态分支切折叠带图；1930s 无折叠分支、恒用手机带，与 2.101 比值一致）。`'desk'` 之外一律 `foldBand: false`。
   - **键盘落点（Column 算术）**：在总成内 Column（layoutWeight(1) 的 wrapping 节点）与 CandidateBar 之间插入一段空白间隔（Spacer），高度**直接用折痕值算：`SpacerH = max(0, creaseBottomVp − creaseTopVp)`（即折痕带高 vp 值），不测总成底边、不依赖实测值**——求值无循环、无反馈（Stack 高与 Spacer 高均为折痕 rect＋窗口尺寸的纯函数，求值顺序：**`measureStage()`（内含 newTablet → `refreshCrease()` → `deriveLayoutMode()` → 分支计算）→ `recalcPaperHeight()` → build 读 `layoutMode`；折叠回调路径上 `deriveLayoutMode()` 先由回调调一次、再由 measureStage 内部调一次，两次幂等**）。折痕 rect 退化（`h ≤ 0`）时 Spacer＝0 并走 50% 回退。**CandidateBar 顶边推导**：CandidateBar 顶边＝topInset ＋ topBar ＋ wrapping 节点高 ＋ SpacerH ＋ stripH（CarriageStrip 净高，`useLayers` 为真时 0、为假时 `carriageHeight − 8`）＝ `winH −（candBar ＋ fontBar ＋ keybed ＋ functionRow ＋ bottomInset）` ＝ `winH − 下半区内容高`。stripH 与 SpacerH 在 Column 算术里抵消（wrapping 节点取剩余空间，Spacer 与 CarriageStrip 均为定高兄弟节点）——故 CandidateBar 顶边只取决于下半区内容高；**容量校验（下半区内容高 ≤ 下半区高）即保证 CandidateBar 顶边 ≥ creaseBottomVp**（Spacer 本身并不移动 CandidateBar，它只占折痕带的位置；移动键盘的是 Column 的剩余空间分配）。**Stack 容纳证明**：wrapping 节点高 − Stack 高 ＝（下半区高 − 下半区内容高 − stripH）＋ paperTopGap；若该余量为负，Stack 溢出 wrapping 节点该量，但溢出区为 Stack 底部空区（纸与字车在 Stack 上部），无可见后果，批报告记实测 stripH 与余量。**下半区容量校验**：CandidateBar(44)＋FontBar(38)＋keybedHeight＋FunctionRow(52)＋bottomInset ≤ `winH_vp − creaseBottomVp`；若超高，批报告记实测并按 §2.5 口径处理（高度只由宽高比派生，不许固定高裁切）。
   - **under-fill 口径**：下半区内容短于下半区时，多余空间为空底色（无节点），键盘位置下移但不跨铰链，属可接受，不另做居中／拉伸。D7 折痕带断言的节点范围：**只含渲染节点（文本／图片／按钮／可交互节点），不含布局容器（Stack／Column 自身）与空白间隔**——容器自身越过折痕带（空底色）不算"有内容跨铰链"。
3. **触发分工（过渡帧口径）**：`foldStatusChange` 先于窗口尺寸变化到达（产品定义稿 L140）。**折叠回调只为 HALF_FOLD 显式触发重算**（窗口不变、onAreaChange 不会 fire，必须显式触发）；FOLDED／EXPAND 的重算由 onAreaChange 驱动（窗口尺寸变化会 fire），折叠回调不为这两态强制立即重算——避免"旧窗＋新 foldState"的杂交帧。**"foldState 优先"指：重算运行时分支由 foldState（经 `layoutMode`）决定，不指折叠回调为 FOLDED 强制立即重算。** 过渡帧"先算旧窗、后由 onAreaChange 纠正"是预期行为（单帧杂交可接受）；验收截图取 settled 态，不以过渡帧为验收依据；若实现实测杂交帧持续可见（＞1 帧或截图可见错位），须加窗口尺寸校验（FOLDED 时 availW 仍 ≥600 则不切分支、等 onAreaChange），批报告记。
4. **联动传输（写死，v7 删 foldState 镜像）**：FoldService 用**回调注册**——`onFoldChange(cb: (s: FoldState) => void)`；Index 在 aboutToAppear 注册一次。**Index 不保留 `@State foldState` 镜像**（v7 删掉该镜像，选方案 b）：回调里只调 `deriveLayoutMode()`（＋按第 3 点触发重算），不另存 foldState；理由：`deriveLayoutMode()` 直接读 FoldService 的值，`@State layoutMode` 的变化已足以触发重渲染；单一事实源为 FoldService，镜像只会带来初值与同步的分叉风险。**状态变化守卫落在 FoldService 内**（`setFoldState` 时比较新旧值，**不同则先赋值、再回调（回调里读到的已是新值）；相同则不回调**）；Index 的 `onFoldChange` 回调不另设守卫。**已放弃方案：AppStorage／@StorageLink——本仓 grep 零使用，不为本轮引入新状态机制。** `foldAngleChange` **不逐度触发布局重算**（角度事件连续触发，逐度重算会抖布局）；**唯一例外是边沿触发进入（见 D2）**：角度由区间外进入 [60,120] 且物理态为 HALF_FOLDED、折痕横向时，重估一次入场门——每折叠一次最多多一次重算，仍满足"不逐度重算"。折叠回调开头先置 `paperAnimateNext = false` 再调 `recalcPaperHeight`（折叠切换走瞬时赋值，不走换行编排的 animateTo 分支；**换行中途折叠时不新起编排动画、纸按新 H 直接落位；行内动画与直接赋值的交互（是否打断）由实施轮 hilog＋截图实测，批报告记**）。`recalcTravel()` 是纯重算、`recalcPaperHeight()` 在 `paperAnimateNext == false` 时直接赋值，重复调用无害；两路触发（折叠回调＋onAreaChange）幂等——onAreaChange 的 ＜1vp 去抖仍适用于窗口路径。
   **折叠回调的重算函数集（v8 补，S-R2-N2）**：折叠回调依次调 `deriveLayoutMode()` 与 `measureStage()`（内含 derive 重算，幂等）；**`measureStage()` 末尾已无条件调 `recalcPaperHeight()`（`Index.ets` 末尾段已核实：`this.recalcTravel(); this.recalcPaperHeight();`，另有条件式的第二遍重算），故回调里无需在 measureStage 外另调一次 recalcPaperHeight()**——"只调 deriveLayoutMode()" 指不另存 foldState 镜像，不指回调只做派生；desk 的 region 公式活在 measureStage 内，若实现者只调 recalcPaperHeight() 而不调 measureStage()，region 不会切换到 desk 公式，纸区会溢出上半区。

- **折痕读法（产品定义稿 §6 L140 口径）**：折痕 rect 为 **px 单位**，`creaseRects[0]` 按 **`[x, y, w, h]`** 读，经 `uiContext.px2vp` 转 vp 后再与窗口 vp 高比较；现场核实字段顺序与换算系数，批报告记实测值。**实施轮须先确认折痕值的原始出处**（探针脚本 `tools/probes/*.py` 里 crease 零命中，自检记录里的 `[0,1194,1828,196]` 没有入库的原始出处——实施时确认是 hidumper 还是探针页 API 调用，批报告写明）。**折痕坐标系（v7 统一顺序）**：折痕 rect 为显示屏 px 坐标（与窗口同向，x／y／w／h 均按当前显示方向）；**旋转时折痕 rect 的重读触发器：窗口旋转触发 onAreaChange → measureStage()；measureStage() 内顺序为 newTablet／isTablet 更新 → `FoldService.refreshCrease()` 重读 `getCurrentFoldCreaseRegion()` 并更新 creaseRect／creaseHorizontal → `deriveLayoutMode()` → 分支计算（与 D0b 第 1 点一致）**；旋转中途的瞬时值不用于布局（只取 settled 态——onAreaChange 去抖后的稳定值）；**实施轮须以 hilog 验证旋转后 creaseRect 已更新（批报告记实测旋转行为）**。**失败动作（v8 补，S-R1-N1）**：**若 hilog 验证发现旋转后 creaseRect 未更新（仍为旧值），在下一轮 onAreaChange 或下一次折叠回调时重读并重派生；若始终不更新，记为未验证路径，批报告记实测。**（前提说明：settled 轮次同步读到新折痕区的假设无一手证据——探针从未旋转过设备；该句把"检测"闭环为"检测＋处置"。）**180° 旋转限定（v8 补，S-R1-N3）**：**180° 旋转（窗口尺寸不变）不触发 onAreaChange**（根 handler 的 ＜1vp 去抖直接 return，`Index.ets:4517–4526` 已核实）；探针折痕 `[0,1194,1828,196]` 对 2584 高垂直居中（中心 y＝1292＝2584／2，已验算），故 180° 旋转后 rect 不变，在当前设备上不可观测；**若真机折痕非居中，须在折叠回调或窗口 `windowSizeChange` 之外另补触发器，批报告记。**
- **区域划分（产品定义稿 L140）**：上半屏高度＝折痕 top（vp），下半屏＝剩余高度减折痕 height，折痕区留空当铰链避让带。纸面区＝`[0, creaseTopVp)`，键盘区＝`(creaseBottomVp, winH_vp]`；折痕带内不放任何内容（纸、键盘、按钮、图片、文字均不得横跨铰链）。
- **50% 回退（带高 0）**：折痕 API 无回值时分界取窗口高 50%（px 帧，不硬编码 1292）；**回退时 `creaseTopVp ＝ creaseBottomVp ＝ winH_vp / 2`（winH_vp 已是 vp 量，直接取半），折痕带高为 0，SpacerH＝0**。理由：折痕 API 无回值时带的位置与高度均未知，v5 的 196px 带是以探针实测值冒充未知值；分界线取窗口高 50%，纸与键盘在 50% 线处相接；并在批报告里记"折痕 API 无回值，用 50% 线分界、带高 0"。
- **字车／打击行落点**：半开时 `recalcPaperHeight` 的 H 取**上半区高（creaseTopVp − topInset）**，kTop 沿用平板 0.56（即 `carriageTopVp = 0.56 × 上半区高`），`strikeLineVp`、paperBandBase 等公式不变，只是 H 变了。滚筒、字车条随纸走（纸筒一体）。**现行公式若 H 仍取整窗高，按 px 帧折算，`0.56 × 2584 ≈ 1447 px > 折痕顶 1194 px`（密度因子约掉），打击行落在折痕带之下——本轮必须按上半区高重算，不得沿用整窗 H。** 执行机制见 D0b（`layoutMode`＋frozenHVp 绕过）。
- **下半区容量**：见 D0b 第 2 点（容量校验＋Spacer 机制）。
- **纸与键盘的归属**：纸（PaperStage）进上半区，键盘（PhotoKeybed＋功能行）进下半区；顶栏留在上半区顶部；候选栏跟键盘走（在下半区顶部，紧贴键盘上方）。
- **不重建**：半开切换只改布局参数（区域划分＋纸高／键区高重算），不重建页面、不重建文档模型、不丢光标与文档位置（见 D4）。

## D2：FoldService（新建，单一状态源）

- **API 清单来源：产品定义稿 §6 L135**（华为官方 API 实锤）：`display.on('foldStatusChange')`（FoldStatus：1 展开／2 折叠／3 半折叠）、`display.on('foldAngleChange')`（0–180°，API 12+）、`display.getCurrentFoldCreaseRegion()`（折痕区域）、`display.isFoldable()`／`getFoldStatus()`／`getFoldDisplayMode()`。
- 新建 `entry/src/main/ets/services/FoldService.ets`（单例，仿 `StatsService`／`AppPreferences` 形态）：
  - 订阅 `display.on('foldStatusChange')` 与 `display.on('foldAngleChange')`；读 `display.isFoldable()`、`display.getFoldStatus()`、`display.getCurrentFoldCreaseRegion()`。
  - 对外状态：`foldState: 'EXPAND' | 'HALF_FOLD' | 'FOLDED'`、`foldAngle: number | null`、`creaseRect: { x, y, w, h } | null`（vp 单位，D1 口径换算后）、**`creaseHorizontal: boolean`（由 `creaseRect` 派生：`w > h` 即横向折痕＝桌台姿态；`creaseRect` 为 null 时（50% 回退）默认为 true——回退分界为水平分界）**。
  - **角度回调取数组首元**：`foldAngleChange` 回调传角度数组（单铰链 1 元，双轴／三折叠 2 元），取 `angles[0]`（主铰链角）；第二元语义待真机确认（产品定义稿 §6 L143："三折叠设备的双角度数组处理方式也需确认"），本轮不用。
  - **非折叠设备初值**：`isFoldable() == false` 时 FoldService 恒报 EXPAND，`foldAngle = null`、`creaseRect = null`、`creaseHorizontal = true`（默认值，无实际意义——非折叠设备恒走 EXPAND 分支，不读该值），不订阅角度事件，App 行为零变化（直板设备零回归，兼容总纲 L274）。
  - 角度事件节流防抖（60–120° 判定只在状态切换时算一次，不逐帧重算布局）——**唯一例外是边沿触发进入（见下）**。
  - `foldStatusChange` 与 `foldDisplayModeChange` 时序不同，不要混用（产品定义稿 L140 原文；物理折叠态变化在前、屏幕显示模式变化在后，布局切换要抢先的信号是 foldStatusChange）。`getFoldDisplayMode()` 读值做二次确认是允许的（读值不是订阅，不算"混用"）。
  - **回调注册（D0b 第 4 点）**：`onFoldChange(cb)`；Index 在 aboutToAppear 注册一次。
- **冷启动初始化**：**问题**：v5 只定义了非折叠设备的初值，可折叠设备的 `foldState` 初始值全文无一处写明，订阅时是否跑一次入场门也未写。App 在设备已半开 90° 时冷启动——无状态事件、无角度事件（铰链静止）→ 桌台布局不触发，直到用户动一下铰链。入场门现有两个求值点（状态切换＋角度进入边沿）在此场景下均不触发，这是第三个缺失的求值点。**修复难点须诚实写明**：初始化时角度不可读（API 清单无 `getFoldAngle`，只有 `foldAngleChange` 订阅），故入场门在订阅时只能按"状态＋折痕朝向"跑，角度记未知。**机制（写死）**：订阅时（`EntryAbility.onCreate`，FoldService 订阅处）同步读 `display.getFoldStatus()`＋`display.getCurrentFoldCreaseRegion()`＋`display.isFoldable()`，跑一次入场门：
  - `isFoldable() == false` → EXPAND（同非折叠初值）。
  - 原始态 EXPANDED → EXPAND；FOLDED → FOLDED。
  - 原始态 HALF_FOLDED ＋ 折痕横向 → **暂定 `foldState = HALF_FOLD`，记 `angleKnown = false`（角度未知），hilog 记 "cold-start HALF_FOLD (angle unknown, provisional)"**。
  - 原始态 HALF_FOLDED ＋ 折痕纵向 → `foldState = HALF_FOLD`（状态如实报），布局回退展开态（同真值表竖向折痕行）。
  - **首个角度回调的纠正**：`angleKnown == false` 时的首个 `foldAngleChange` 回调视为初始角度读数——若角度在 [60,120] 外且 foldState 为暂定的 HALF_FOLD，纠正为 EXPAND 布局（hilog 记 "cold-start angle corrected"）；若在区间内，确认暂定值（无变化）。然后置 `angleKnown = true`，此后边沿规则适用。铰链始终静止（无角度回调）时暂定值一直有效——风险已明示：设备半开在区间外角度且用户从不动铰链时，桌台布局会误现；该近似可接受（半开在用姿态以 90° 为主，且用户稍动铰链即纠正），批报告记。
- **半开判定真值表（v4："方向"改为"折痕朝向"）**：

  | FoldStatus | 折痕朝向 | 角度 | foldState | 布局 |
  |---|---|---|---|---|
  | EXPANDED（1） | 任意 | 任意 | EXPAND | 按 isTablet |
  | FOLDED（2） | 任意 | 任意 | FOLDED | 手机分支 |
  | HALF_FOLDED（3） | 横向（`w > h`） | 60°～120° | HALF_FOLD | 桌台（D1） |
  | HALF_FOLDED（3） | 横向（`w > h`） | ＜60° 或 ＞120° | **保持上一 foldState（不跳变）**，记 hilog | 同上一状态 |
  | HALF_FOLDED（3） | 纵向（`w ≤ h`） | 任意 | HALF_FOLD（状态如实报） | **回退展开态**（竖向折痕无桌台意义；帐篷模式探针未覆盖，批报告记"竖向折痕半开布局＝展开态"） |

  角度阈值 60–120° 为社区实践值（产品定义稿 L140），探针实测半开角 90°；Mate X 真机校准后定，模拟器上先用此区间。**入场后角度漂移不改变 `layoutMode`**（角度只在入场判定用一次；状态仍为 HALF_FOLDED 即保持桌台）。
- **边沿触发进入**：**问题**：角度入场门只在状态切换时算一次。真机连续合拢时，若物理态翻为 HALF_FOLDED 的瞬间角度仍在 120° 之外，`foldState` 保持 EXPAND；此后角度变到 90° 只有角度事件、无状态事件，桌台布局永不触发，直到重新展开再合拢。探针证据不能排除该场景（watcher 2 秒采样，只记录了 settled 态角 90°；系统 HALF_FOLDED 接通角度在 draft 全文无出处）。**机制**：FoldService 内部记 `prevAngleInRange: boolean`（上一次角度是否在 [60,120] 内，初值 false）。每次 `foldAngleChange` 回调：更新 `foldAngle`；若 `!prevAngleInRange && angle ∈ [60,120] && 物理态 == HALF_FOLDED && creaseHorizontal` → 重估一次入场门（置 `foldState = HALF_FOLD`，走与 `foldStatusChange` 回调相同的重算路径）；然后置 `prevAngleInRange = angle ∈ [60,120]`。角度漂出 [60,120] 时不动（保留"漂移不退出"决定）。**每折叠一次最多多一次重算**，仍满足"不逐度重算"。**物理态来源写死**：物理态取最近一次 `foldStatusChange` 事件值；若从未收到事件（冷启动），取 `display.getFoldStatus()` 的同步返回值。
- **订阅点写死：`EntryAbility.onCreate` 订阅一次。** 理由：FoldService 是应用级单例，与页面无关。
- **teardown 口径（对产品定义稿 L140 的显式偏离，附理由）**：L140 写"页面退出时 `display.off` 取消监听防泄漏"，针对的是订阅挂在页面上的旧假设；本轮订阅挂在 Ability 上，页面切换不重复订阅、**不取消**，**Ability onDestroy 时 `display.off` 全量取消**，以此替代 L140 的页面退出口径。若评审／用户不同意这个替代，就按 L140 执行并重写 D2。
- **foldStatusChange 订阅未探针验证**：探针实际验证过的只有 `foldAngleChange` 订阅成功、`isFoldable()=true`、`getFoldStatus()=1`（自检记录 §2）；`foldStatusChange` 订阅是探针用 hidumper 读状态绕过去的，从未实际订阅过。**实施轮首跑须以 hilog 确认 foldStatusChange 订阅回调到达，见 D7。**

- **裁剪机制（写死）**：半开时纸容器在 creaseTop 处裁剪，机制为 `recalcPaperHeight` 里 `paperContainerTargetVp = min(算出值, creaseTopVp − paperTopTargetVp)`（HALF_FOLD 时），**容器本身即裁剪区，不另加 `.clip()` 修饰**；与状态表 `paperContainerVp` "重算"行互相引用。（安全网：D1 公式下容器本已在折痕之上，cap 仅防折痕值误读。）
- **打击行错位的补救**：D1 公式下 `strikeLineVp = carriageTopVp − marginB() − lineHeightVp/2 − strikeShift`，`carriageTopVp = 0.56 × (creaseTopVp − topInset)`，故打击行恒在折痕之上，错位触发条件在正确实施的前提下不可能发生。**若打击行落在折痕带内或带下（只可能因折痕值误读导致 H 算错），不动 `paperTopVp`，改为重算 H／`carriageTopVp` 并记 hilog＋批报告；重算时改用 50% 回退分界（D1）或重读折痕值；若重读仍错，记 hilog＋批报告并保持上一正确 H，不静默用错值。`paperTopVp` 始终由 `carriageTopVp` 与光标行派生（`paperTopTargetVp = carriageTopVp − paperBandBase − 光标行 × 行高`），不单独调整。**
- **验收句**：paperTopVp 数值比对只在 EXPAND↔FOLDED 间成立，半开允许按新 H 重算（语义保留为准）。
