## Overview

回车是一款鸿蒙拟物打字机 App（全离线、零遥测、无内购、无在线功能、无 App 内 AI）。四台虚构时代机（1920s／1930s／1950s／1960s）已全部落地蓝图并通过验收，中文输入（内置拼音＋系统通道）、换纸、拨杆换行等核心链路已通。

本轮要做的是下一阶段：**引导、自定义、文件与分享三大新系统，外加 12 项此前排队的功能与修复**，全部以自动化测试—优化—回归流程交付，桌面端连续自主运行数小时、按批提交、每批留档可追溯。目标是新用户能自己摸会、老用户能按自己喜好改、写好的东西能方便地存下来分享出去。

## The Problem

现状（2026-11-09 沙箱实测＋读码核实，非推测）：

- **引导不存在**：`AppPreferences.ONBOARDING_SEEN` 键已定义，但全仓没有任何读它的地方；没有任何引导／教程组件；主页只有一句静态引导语。
- **自定义只有预设**：`CustomizePage` 是 4 台机／4 种纸／3 条色带／17 款字体，全是点选预设。没有字体导入、没有纸张自定义（颜色／横线／边距／导入纹理）、没有字号调节、没有每机字体搭配。`FilePicker` 全仓零处。
- **导出只有分享入口**：`ExportPage` 有预览＋图片／PDF／纯文本三行＋分享按钮；三种格式实际已先落盘到应用 `filesDir`（`Index.ets:3736–3808`），再经 `systemShare`（`@kit.ShareKit`）分享。缺的是"用户自选位置保存"与"只存不分享"的入口；没有碰一碰分享；分享进度与成功态反馈缺失。导出动画本身已存在（D4 按压 0.97／120ms、D6 入场 200ms＋三行间隔 60ms）。
- **图标已收敛**：`AppIcon.ets` 是唯一的系统 SymbolGlyph 入口（13 种 kind，`sys.symbol.*`）；代码里没有 emoji、没有文字形图标。工作是全仓审计各页是否都走 AppIcon、补齐缺失的 kind、堵住旁路——不是重写图标系统。
- **设置页开关未接线**：`SOUND_ENABLED`／`VOLUME`／`VIBRATION_ENABLED` 键存在，但 `SettingsPage.ets` 无 `AppPreferences` import，音量／叮声／震动／删除方式全是页面内部 @State；`AudioService` 音量私有默认 0.8，`setVolume` 只在接口声明、无调用方；音效致谢行显示 '—'；"默认机器／默认纸张"行是纯展示（2026-11-08 审计结论，第 6 批第一步先复核）。
- **成就系统不存在**：临时全解锁顶着（`CollectionPage.unlocked()` 与 `CustomizePage.unlockedMachine()` 直接回 true，成就落地时改回按条件判定）；`docs/成就体系设计.md` 的阈值仍是"提案待用户点头"。
- **折叠屏 API 零处**：折叠屏 API（`FoldStatus`／`foldAngleChange`／`windowSizeChange` 监听）全仓零处；现有的 fold 字样只是键带 fold 图命名（`foldBand`／`keybandFoldRawfile`），与折叠屏无关。
- **每台独立音效包没做**（四台共用一套音）。**旋钮已撤下**：但 `knobAngle`／`knobD()` 仍在（后者决定底座宽 `baseW()`），`detectLayers` need 列表仍含 `knob.png`——缺失则全部分层件静默退回 carriage-strip。**换纸约 8–11 秒时长之谜未定位**（换纸代码本身是 600ms）。**拨杆视觉不跟手**：全仓有 5 份 LeverLayer（`components/LeverLayer.ets`＋4 份蓝图复制件），每份 `onDragRatio` 都有 `if (this.dragging)` 门控；Index 的 `leverDragRatio` 接线已存在（总成层 PanGesture 已算出 `dy/h`，四处实例化都传了 `dragRatio`），缺的是去掉门控、让传进来的 dragRatio 直接驱动角度。注意：1920s 实际渲染件是 `components/LeverLayer.ets`（Index:62 import、:3108 实例化），蓝图目录里的 `machines/1920s/LeverLayer.ets` 是死代码路径（`LeverOnlyAssembly1920` 全仓无引用）。另：Index 里有三份近乎相同的 PanGesture 拖拽处理（约 3206／3319／3380 行），后两份 overlay 版无条件置 `leverDragActive=true`——"同一条处理函数"今天不存在，第 0 批须先去重成一份。
- **回归门现状**：1920s 冻结基准 `docs/shots/332_metal3.jpeg`；第 7 批门图 540 vs 332 的"0.00%"沙箱未复现（键盘 0.03%、车架左 0.41%、车架右 1.89%），原因是拨杆静止角不同、其余零件全一致；500（CRLF 刚转完）vs 332 是 0.00%。教训：门图拍摄前必须确认拨杆已回静止位，且门必须有可复现的测量口径（见"验证计划"）。

## Goals

* **G1 引导**：新用户首次启动能自己完成"这是什么—怎么打字—东西存在哪"，每页首次进入有 2–4 条短提示且可重看；引导不挡路、不重复打扰。
* **G2 自定义**：字体可导入、可管理、可按机搭配、字号可调；纸张颜色／横线／边距可调、可导入图片作纸纹、可存为自定义预设。
* **G3 文件与分享**：内容可存为图片／PDF 到用户可见位置，可只存不分享；可经 ShareKit 分享；碰一碰分享先探针、有则实现、无则 ShareKit＋指引兜底；分享有进度与成功反馈。
* **G4 成就与统计**：成就系统正式落地替代临时全解锁（阈值用户点头后）；打字统计在既有统计行上加每日目标及进度。
* **G5 机械与形态**：拨杆拖拽跟手、换纸耗时之谜定位并修复、旋钮恢复、折叠屏三态。
* **G6 声音与管理**：每台独立音效包；设置页全部开关接线；卷宗内搜索、回收站、重命名。
* **G7 统一与易用**：全部图标走 `AppIcon`；页面／弹窗／动画／引导四套规范统一且有据可查；系统组件优先；每页有提示说明与空状态。
* **G8 过程**：8 批全部按 EGM 走（总纲一次批准，每批增量设计＋fresh Goldfish review＋resolve，自主运行、批准按当时有效的决策权）；**自动化为主、边界写明**：每批"测试—优化／修复—回归验证"走自动化，动画／手势／声音／折叠／碰一碰／时间条件六类按验证计划的豁免表执行（逐项列明替代证据与缺口，不许假装自动化），豁免项集中到第 7 批一次**计划内**真机冒烟检查；测试全程静音；文档与截图落到实处可追溯；每批重过 1920s 回归门。

## Non-Goals

* 不碰在线／服务器功能；不碰 App 内 AI 功能；不做元服务；不做内容生成 lane。
* 不新增机型（只做现有四台）；不改 1920s 的静止姿态与几何常量（冻结定义升级见 Open Questions Q1）；不改已批的成就阈值；其余数值口径的改动须在增量设计里列出并经 Goldfish 评审。
* 不做 iOS／非鸿蒙端；不引入第三方 SDK／在线字体库（字体只从用户本地文件导入）。
* 不重写已有且已验收的核心链路（打字、换行、换纸、中文输入），只在上面加功能；第 0 批只做两类工作：无争议基建与探针（0a），以及验证架构与拨杆隔离（0b）——拨杆隔离是唯一的行为变更例外（见分批），其余基建不改产品行为。
* 不把 zoom-out 评审提议的三项砍／降级擅自执行（F11 砍、F13 砍、F5 降级为只显示收藏进度），留给用户在批准本稿时定（见 Q4）。

## Open Questions

* **Q1 冻结定义的升级（必须用户本人定，批准本稿时确认）**：1920s 的冻结从"文件不许动"升级为"静止姿态与几何常量不许动"，动态响应（拨杆跟手角度）不在冻结范围内；并补状态维度——"拨杆角状态须按机隔离、切机或测试后须回静止位"。理由：拨杆跟手修的是动态响应，静止像素不受影响；5 份 LeverLayer 里 1920s 实际渲染件是 `components/LeverLayer.ets`，不修它就修不了跟手。**对称 fallback**：若用户否决升级，则第 0 批隔离跳过 `components/LeverLayer.ets`（只隔离 4 份蓝图件），第 1 批只去掉 4 份蓝图件的门控，1920s 跟手保持未修、记为已知限制。
* **Q2 成就阈值＋迁移口径（必须用户本人定；无缺省动作）**：阈值以 `docs/成就体系设计.md` 为准，须用户点头；临时全解锁期间用户已能用全部四台机，正式系统落地时已解锁状态是保留还是按阈值重锁？二选一。未决时 F5 批不开工，第 6 批先做 F6＋F10，批报告记录跳过项。
* **Q3 折叠屏硬件（必须用户本人定；缺省＝模拟器验证＋真机延期）**：现有机队无折叠设备。选项：① 买／借折叠真机；② 用模拟器验证布局＋真机验证标记为延期；③ F7 移出本轮。缺定论，第 5 批不许开工 F7；若到第 5 批仍未决，按缺省 ② 执行（F7 只做模拟器验证，真机部分标记未验证）。
* **Q4 三项砍／降级（必须用户本人定，批准本稿时定）**：zoom-out 评审提议：砍 F11 每日目标、砍 F13 旋钮、F5 降级为只显示收藏进度（理由：无用户原话支撑、投入产出比低、阈值未批）。Elephant 未擅自采纳。若用户同意其中某项，本稿对应章节作废、以用户决定为准；**重排程序**：任一裁决落地后，由 Elephant 在第 0 批开工前出一份分批调整说明（批号不变、内容重排），随第 0 批增量设计提交。
* **Q5 碰一碰双机条件（可由父 agent 代决；缺省＝ShareKit＋指引、碰一碰标记未验证）**：MLR-AL10 的 NFC 能力待核实（很可能没有）；单机探针验不了端到端。选项：① 借第二台 NFC 设备对碰验证；② F4 只做 ShareKit＋指引，碰一碰部分标记为未验证（功能代码可留待有设备时再验）。若到第 3 批仍未决，按缺省 ② 执行。
* **Q6 F8 音效来源（可由父 agent 代决；缺省＝Freesound 采制）**：四套音效从哪来——Freesound 采制（按本仓既有做法：入库时记录协议、日期、SHA-256，设置→关于→音效致谢必须做）还是复用现有 23 个 OGG 重组？第 4 批增量设计里定，采制须在批内完成。

## Critical User Journeys (CUJs)

### CUJ 1：首次启动

* **Given**：全新安装，`ONBOARDING_SEEN` 未置位。
* **When**：打开 App。
* **Then**：启动引导出现（这是什么、怎么打字、四台机在哪、东西存在哪），可跳过；走完置位 seen；设置页可重播；引导不挡住后续自动化测试（测试 harness 分两种模式，见验证计划）。

### CUJ 2：导入一款字体并用到 1950s 上

* **Given**：用户本地有一个 .ttf／.otf 文件；1950s 当前字体为默认。
* **When**：换装页 → 字体管理 → 导入 → 选文件 → 设为 1950s 字体。
* **Then**：字体出现在管理列表（可删）；1950s 打字立即用新字体；重启后仍有效（注册点走 Index 同款路径，UIContext 就绪后注册）；坏文件有明确报错、不崩溃、不污染已有字体。

### CUJ 3：把一页纸存为 PDF 并分享

* **Given**：一篇已写好的文档；设备已静音（测试）或正常（用户）。
* **When**：导出页 → 选 PDF → 保存到用户自选位置（只存不分享）→ 再选分享 → 碰一碰／ShareKit。
* **Then**：PDF 落在用户选的位置、可打开；分享有进度与反馈（反馈文案为"已保存＋已调起分享"，不宣称"已分享成功"——系统面板调起后应用无法观测是否完成分享）；碰一碰无 API 时走 ShareKit＋指引兜底，分享组件、动画与指引与碰一碰链路完全相同（探针只决定传输，不降级体验）。

### CUJ 4：成就解锁

* **Given**：阈值已批；用户达成某台机的解锁条件。
* **When**：达成瞬间。
* **Then**：解锁提示出现；收藏页状态更新；临时全解锁的迁移口径按 Q2 的决定执行（保留或重锁）。（提案值：1950s＝累计 5000 字＋用过 2 种纸；一切以批复的阈值为准。）

### CUJ 5：折叠屏半开打字

* **Given**：折叠设备（或模拟器，见 Q3）；文档打开中。
* **When**：折叠到约 90° 半开。
* **Then**：上半屏纸、下半屏键盘、不跨铰链；文档、光标、纸张位置全保留；中文输入不 detach／re-attach；引导锚点仍对得上三态。展开态＝平板布局；外屏态＝手机分支布局。

### CUJ 6：拨杆拖拽跟手

* **Given**：任意一台机；纸上有文字。
* **When**：手指按住拨杆向下拖到一半以上、松手。
* **Then**：拖拽过程中拨杆角度跟手指走（不跳变）；松手后换行（纸上滑一行、字车回位、叮声）；拖不到一半松手则拨杆弹回原位、不换行。

### CUJ 7：删纸进回收站并恢复

* **Given**：卷宗里有一张纸；删除方式设为"进回收站"（见第 6 批）。
* **When**：删纸 → 回收站 → 恢复。
* **Then**：删纸后原位置消失、回收站里出现；恢复后回到原卷宗；彻底删后不再出现；保留 30 天、过期自动彻底删（缺省值，第 6 批增量设计可改，须写清）。

### CUJ 8：换纸

* **Given**：纸上有文字；换纸计时打点已开（第 0 批起）。
* **When**：点换纸。
* **Then**：换纸全程 ≤1 秒（600ms 代码路径＋余量）；旧纸上卷、新纸从滚筒里往上长出；换纸后哥特拱在行首（带动画）；文档已清空。

## Technical Plan (Architecture)

### 共享契约（第 0 批定，后面各批只消费、不自造）

```text
Index（@Entry，唯一入口，显式导航栈）
 ├─ PageShell（页面壳：顶栏＋insets＋沉浸式，引用 AGENTS.md 定论）
 ├─ AppDialog（弹窗：遮罩与卡片兄弟节点，引用 AGENTS.md 定论；成就达成提示走 AppDialog）
 ├─ GuideOverlay（新增：只做渲染器；提示文案与功能同处一源，各组件声明自己的提示）
 ├─ HintBar（既有：瞬时操作反馈，顶部下滑、3 秒自消失）
 ├─ AppIcon（图标唯一入口；kind 注册表，第 0 批定方法，各批补 kind）
 ├─ DocStore（文档状态模型：active／trashed；save／load／remove／list＋trash／restore／rename／search）
 ├─ StatsService（新增：单一派生层；totalWords()／consecutiveDays() 各一个实现）
 ├─ AppPreferences（prefs 键命名空间＋登记规则；新键一律登记；新功能开关默认 off）
 ├─ FileHelper（新增：FilePicker 选择／保存共享 helper，统一权限与错误处理）
 ├─ ShareService（新增：分享唯一入口；Index 现有 systemShare 调用迁入）
 ├─ FontService（新增：薄封装，复用启动注册循环的同一函数，不许另写注册逻辑）
 ├─ AudioService（每机音效包选择层；空输出 PCM 捕获验音效）
 └─ 拖拽偏移状态（新增：单一事实源；PanGesture／点按／测试钩子同走一条处理函数）
```

* **提示机制分工**：HintBar＝瞬时操作反馈；GuideOverlay＝首次引导浮层；常驻说明行＝静态说明；成就达成提示走 AppDialog。不合并（生命周期不同：HintBar 3 秒自消失，GuideOverlay 常驻至关闭）。引导锚点用语义锚（按组件 id／role 解析落点），不写死布局坐标。

### 验证架构（根本矛盾 1 的解法，第 0 批探针先行）

* **状态驱动手势（条件式）**：拨杆角度、纸张偏移等交互状态由单一拖拽偏移状态驱动；PanGesture、点按、自动化测试钩子都只是往同一个状态写值的生产者，走同一条处理函数。**前置条件**：第 0 批先把 Index 里三份复制粘贴的拖拽处理去重成一份，再谈注入。探针"hdc 输入能否驱动 PanGesture"前置为条件分支——能驱动则真实输入重放为主证据（走完整识别链），注入只作补充；不能则注入＋豁免，但豁免必须写明"识别层未验证"，并安排每批一次真人手指抽查。注入面只在测试构建开启，发布构建关掉；注入必须经过与手势完全相同的处理函数，写进设计稿当铁律。
* **确定性测试时钟（探针先行，不许写成已成立）**：ArkUI 的 `animateTo` 由系统 vsync 驱动，没有公开的手动步进时钟 API；"观测 @State 不能证明渲染插值（animateTo 立即赋终值）"是仓内实测定论。本稿**不**把"动画系统支持测试时钟驱动"写成第 0 批必建项，改为第 0 批探针（"测试时钟可行性探针"：能否帧步进、动画曲线能否抽成纯函数单测）。探针通过才建；探针失败则 G8 改写、动画类验证退回 AGENTS.md 既有口径（hilog 打点＋用户录屏），并进豁免表。"或等价地输出关键帧状态快照"与实测定论矛盾，已删除——@State 快照证明的只是方向与终值，与逐帧截图不等价。
* **空输出验音效**：验证声音信号，不验证扬声器。AudioService 的输出接到空输出（null sink），测试捕获解码后的 PCM 缓冲并断言：包间频谱指纹可区分性（抓 F8 最可能的失败——包接错、两包实为同一文件）＋哈希一致性检查＋时长与包络合理＋该静音的角色确实静音；同时在选择层断言（某台机、某个动作选了哪一个音效文件）。"对不对"（选型、时长）与"响不响"（扬声器）分开验证；后者留给第 7 批计划内真机冒烟检查，不计入自动化批次。必须在设计稿里写清这条管线证明什么、不证明什么。
* **换纸计时打点**：第 0 批就把换纸全链路的计时打点加上（各阶段起止时间戳，hilog 可查），数据从第 0 批开始积累；第 5 批修的时候面对已有数据，而不是现抓的几条日志。打点零成本关闭，不许影响换纸动画时序。假说清单（打点数据裁决）：① 换纸动画链被某步同步 IO 堵住；② DocStore 保存同步写盘；③ 纹理滚动重算；④ 动画时长常量被误读。
* **hilog 埋点口径**：每批验收加一条"关键操作 hilog 打点清单"（引导展示／关闭、自定义项变更、导出成功／失败、成就达成、折叠切换、拨杆拖拽事件），与识屏验收并列。

### 批间规则

* 每批独立提交到 main（只对 main 提交）；批内多功能分开提交，revert 按提交不按批（后批已依赖前批时改为 fix-forward，须在批报告里写明）。

## Alternatives Considered

### Alternative A：引导只做启动引导，不做每页提示

* **Pros**：工作量最小；一次写完不返工。
* **Cons**：用户进新页还是迷路；自定义项越多，新用户越迷路；与用户要求直接冲突。
* **Reason for Rejection**：Rejected by author（用户 2026-11-09 指令原文："启动引导，每个页面的引导和指引、说明"）；且 Goldfish 评审指出引导文案若集中写、后批改页必返工——本稿的解法是 F2 拆分（各功能批自带本页引导），不是砍掉每页提示。

### Alternative B：字体导入拷进 rawfile

* **Pros**：与现有 17 款字体同一套加载路径。
* **Cons**：rawfile 运行时只读，不可写；行不通。
* **Reason for Rejection**：技术上不可行。改走 FilePicker → 应用私有目录 → `registerFont` 动态注册（注册点走 Index 同款路径，UIContext 就绪后注册）。

### Alternative C：碰一碰分享只做 ShareKit，不探针

* **Pros**：零风险、立刻能做。
* **Cons**：用户明确要求"正确支持碰一碰分享"；不探针就等于默认放弃，连 API 是否存在都不知道。
* **Reason for Rejection**：Rejected by author（用户 2026-11-09 指令原文："正确支持碰一碰分享并且还有动画和指引"）。改走先探针、有则实现、无则 ShareKit＋指引兜底，且分享体验与传输解耦（同一套分享组件、同一套动画与指引，探针只决定传输）。

### Alternative D：每批一批准（用户逐批批）

* **Pros**：控制最严。
* **Cons**：与"连续自主运行数小时"互斥；7 次批准关卡会让自主循环每批停下等用户。
* **Reason for Rejection**：与用户"全自动运行"的要求冲突，且 2026-11-09 用户扩展立规已定：自主运行时评审照做，批准按当时有效的决策权。本稿改为总纲一次批准＋每批增量设计＋fresh Goldfish review＋resolve，批准按当时有效的决策权。

### Alternative E：动画／手势验证缺口"如实记录"即可

* **Pros**：不用改架构。
* **Cons**：每一批的验证报告里都会留一个"缺口"栏，"数小时自主运行、每批可追溯"的承诺在手势与动画这两类功能上打折兑现；且用 hilog 证明音效违反识屏铁律（hilog 只作辅助）。
* **Reason for Rejection**：Goldfish inventive-catalyst 指出这是被当成前提接受下来的妥协（`egm-work/zoom_out_report.md`，inventive-catalyst 一节）。改走架构消除：状态驱动手势＋测试时钟探针＋空输出 PCM 捕获验音效；探针失败的才进豁免表，且豁免须写明替代证据与缺口。

### Alternative F：拨杆"只改共享接线、不动冻结件"

* **Pros**：听起来最安全。
* **Cons**：与代码现状不符——全仓 5 份 LeverLayer 各有 `if (this.dragging)` 门控，Index 的接线已存在；"不动冻结件、只改接线"的边界画不出来（加 prop 算不算动、改哪一层的文件）。
* **Reason for Rejection**：Goldfish codebase-details 核实后推翻（`egm-work/implementation_readiness_report.md`，codebase-details 一节）。改走"冻结契约而非文件"：先隔离（状态分割＋纯函数驱动器抽取），后修复（去门控）；冻结升级为静止姿态与几何常量不许动（见 Q1，须用户确认）。

### Alternative G：成就／统计／收藏进度各自在 prefs 里维护计数

* **Pros**：各功能独立、最快。
* **Cons**：同一个"总字数"迟早在两处算出两个数；本仓已有"同一事实两处口径"的教训。
* **Reason for Rejection**：本轮 resolve 决定（`egm-work/consolidated_review_report.md`，R-B7）：不建追加式事件账本——总字数／连续天数今天已由 DocStore 派生，无消费者需要事件历史（YAGNI）。改走 DocStore 派生＋prefs 计数器（非文档事件），外加单一派生层 `StatsService`（`totalWords()`、`consecutiveDays()` 各一个实现），F5／F11／F14 只消费派生结果。

## Risks & Mitigations

| 风险 | 影响 | 缓解 | 残留风险 |
|---|---|---|---|
| 不可信字体／图片文件的二进制解析面（用户导入的 .ttf／.otf／图片可能损坏或恶意构造） | 崩溃、解析异常、注册污染 | 导入时校验文件头与大小上限；注册失败有明确报错、不污染已有字体；坏文件不入库 | 校验只能覆盖已知损坏模式；极端构造文件仍可能触发解析器未知行为 |
| 三处无界存储（prefs 计数器、导入的字体／纸纹文件、回收站） | 磁盘占用持续增长 | 回收站缺省保留 30 天、过期自动彻底删；导入文件计入配额（上限由第 2 批增量设计定，超限提示用户清理）；计数器是标量、无增长问题 | 用户长期不清理导入文件仍会占空间；配额上限本身是待定值 |
| 测试构建与发布构建分叉（验证的 artifact 不是交付的 artifact） | 注入面、空输出捕获、测试时钟钩子只在测试构建存在，发布构建的行为未经同等验证 | 测试钩子只在测试构建开启、发布构建关掉；每批回归门与关键 CUJ 在发布构建上重跑一次（不带测试钩子） | 发布构建的回归覆盖面小于测试构建；分叉本身无法完全消除 |
| 折叠设备缺失（Q3） | F7 无法真机验证 | 缺省＝模拟器验证＋真机延期；真机部分标记未验证，不许写成已验证 | 半开角度与铰链避让的真实手感未知 |
| 确定性测试时钟不可行（R-B1） | G8"全程自动化"承重墙倒塌 | 第 0 批先探针；失败则 G8 改写、动画类验证退回 AGENTS.md 既有口径并进豁免表 | 动画类验证回到"hilog＋用户录屏"，自动化覆盖率下降 |
| 父 agent 代决风险（Q3／Q5／Q6 由父 agent 代决） | 代决与用户真实意愿不一致 | 代决只限有缺省动作的项；代决记录在批报告里，用户可复核与回滚；Q1／Q2／Q4 必须用户本人定 | 用户醒来才发现代决已执行，须回滚 |
| 拨杆隔离改 1920s 实际渲染件（Q1） | 冻结件被动，1920s 静止像素漂移 | 冻结常量断言测试＋驱动器纯函数单测（`f(0) = 各自静止角`）＋每批回归门；Q1 被否时有对称 fallback | 断言测试只能覆盖已知常量；未知耦合仍可能漏网 |

## Non-Functional Requirements

* **离线与隐私**：全程无服务器、无联网；字体与纸纹只从用户本地文件导入；统计派生只读本地文档与 prefs；不引入第三方 SDK。
* **性能**：运行时绝不 sort（词库键序由管线预排，F15 增删用户词不许触发索引重建或排序——这是 2026-11-08 卡死的同款根因）；引导浮层与自定义项不许拖慢打字主链路（打字 90ms 摆杆、字 1:1 永不丢的口径不变）；计数在保存／导出事件时更新，不走打字热路径；测试时钟与注入面只在测试构建开启，发布构建关掉。
* **兼容**：API 12+；手机／平板分支互不影响（改手机分支时平板零像素回归，反之亦然）；折叠三态只在折叠设备上生效，直板设备行为不变。
* **回滚**：每批独立提交；批内多功能分开提交，revert 按提交不按批（后批已依赖时 fix-forward，须在批报告里写明）；新功能 prefs 开关默认 off，回滚时开关回 off 即可；DocStore 数据回滚＝revert 提交＋trash 状态保留（数据不丢）。
* **可追溯**：每批增量设计＋Goldfish 评审报告＋批报告（落点 `docs/自检记录.md`）＋验证截图（`docs/shots/`，6xx 号段）＋commit 可查；关键操作 hilog 打点清单与识屏验收并列。
