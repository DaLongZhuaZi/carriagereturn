# 26-增补-33-批68-纸向上延展＋滑动回位＋换纸动画重做

## 0. 背景与判定

- 批 67 桌面端推回 `aebdc11`（2026-11-21 21:38）：字篮井高度同源、扇盒井高减 10vp、纸视口加 clip。批 67 自检称纸底 882px 在拱顶 938px 之上、重叠已修。
- 用户 2026-11-21 21:43 在最新提交上指出一个更深的纸问题（平板实测）：**纸并没有自然伸展，而是不停向下伸展**——向下伸展会被中央区（字篮井）和键盘区挡住，**下半张纸完全无法正常看到**。用户同时定方向：纸只能向上延展、允许超出上边界、纸可上下滑动、下一次落字时动画自动回到落字位置；换纸动画也是错的，旧纸应向上飞出、新纸从下方出现。**全部设计遵循自适应原则**（尺寸/位置/距离一律由 stageLayout 与纸内容高推导，不写死 vp/px）。

## 1. 根因（读码，`aebdc11`）

### 1.1 纸底没有被真正钉住——纸是“顶锚定”，所以向下长

- 纸视口（`Carriage26.ets`）里，内层 Column 用 `.height('100%')`＋`justifyContent(FlexAlign.End)` 想把纸底贴住视口底。但该 Column 是 Stack 的孩子，`'100%'` 在 Stack 里没有落到一个确定的高度——Column 实际按内容定高，`justifyContent(End)` 没有多余空间可分，等于没生效。**纸的顶被钉在视口顶，纸高一长、纸底就往下走**：纸高＝`paperGrowVp`（`paperVisibleTargetVp()`，31＋lh×行数＋6，平板封顶 567.9vp），视口只有 `paperAreaH()＝zoneHVp−18＝319.9vp`，纸比视口高 248vp，多出来的部分只能向下伸进字篮井（393.9–539.6vp）和键盘区（678.6vp 起），被后画的井/键盘盖住——下半张纸看不见。
- 批 67 加的视口 `clip(true)` 只裁住了“画出视口”的像素，没修“纸底往下走”这个锚定问题；纸底该在的位置（视口底，约 371vp）没有被任何一个确定值钉死。
- 佐证（批 67 自检回归日志）：回车时 `paperTop 311.0→282.4`、`paperBox 94.2→122.8`——纸顶上移、纸盒长高，但这两个量仍是“纸顶派生”，纸底没有一个以视口底为基准的独立量。

### 1.2 纸没有用户可用的滚动——长纸的上半截够不着

- 现行唯一的纸滚动是 `paperScroll26()`（`Index.ets`）：光标行超出纸高时整卷上移 `scrollYVp`，只保证光标可见。用户自己不能拖纸：纸一长、上半截（早先的行）顶出视口顶（被 TopBar 遮挡）就再也看不到了，只能靠继续打字把它“顶”回来。这是纸“只能向下长、不能翻回去看”的另一面。

### 1.3 换纸动画是“死”的——`paperTopVp` 不再定位纸

- `onPaperChange`（`Index.ets`）第①步把 `paperTopVp` 上移一个纸高并淡出、第②步把 `paperTopVp` 藏到滚筒处再 `recalcPaperHeight()` 推回。批 64 flex 化之后，纸的位置由 `stagePaper()` 传的 `paperHVp＝paperGrowVp`＋视口 flex 决定，**`paperTopVp` 不再参与纸定位**（`stagePaper()` 根本不传它，`Carriage26` 也没有这个 prop）。所以第①步的“旧纸向上卷出”没有真的让渲染出的纸动，第②步的“新纸从滚筒卷出”也只是纸高在原地长出来——用户看到的换纸就是纸在原地一缩一长，没有“旧纸向上飞出、新纸从下方出现”的运动。

## 2. 设计（用户定方向，本稿落成可实现口径）

### 2.1 纸只能向上延展——纸底是硬锚点，纸顶允许超出上边界

- **硬不变量**：纸底 Y 恒等于视口底（`paperAreaH()`，由 `zoneHVp−18` 推导，平板 319.9vp）。纸高 `paperH()＝paperGrowVp` 再长，纸底不动，纸顶＝`paperAreaH() − paperH()` 向上走。**纸永不向下伸出视口底**。
- **实现**：`Carriage26.ets` 里纸视口的内层 Column 把 `.height('100%')` 改成确定的 **`.height(this.paperAreaH())`**（一个数，不再是百分比），`justifyContent(FlexAlign.End)` 才有确定的容器可锚；纸底由它贴住视口底。若桌面端实测该写法仍锚不住，改走显式定位：纸用 `.position({ y: this.paperAreaH() - this.paperH() })` 按底定位（纸顶由纸高推导），二选一，以验收为准。
- **纸顶允许超出上边界**：纸高封顶仍是 `paperVisibleTargetVp()`（平板 567.9vp），可以比视口（319.9vp）高，超出的部分从视口顶出去（视口 `clip(true)` 裁住、顶部被 TopBar 遮挡，28 号稿 Q4 口径不变）。超出的内容不丢失——用 2.2 的滑动把它翻回来。

### 2.2 纸可上下滑动（用户拖动）

- 新 `@State paperUserOffsetVp: number = 0`（`Index.ets`）。0＝落字位（纸底贴视口底）；＞0＝纸被用户向下拉，露出上半截（早先的行）。
- **手势**：纸视口上加 `PanGesture`（拖动）。手指下移 → 纸跟着下移、`paperUserOffsetVp` 增大；手指上移 → 减小。位移量就是手指的位移量（vp），不另设速率。
- **钳制（自适应）**：`paperUserOffsetVp ∈ [0, max(0, paperH() − paperAreaH())]`。上界是“纸顶正好拉到视口顶”（再拉上面就是空的）；下界 0 是落字位（纸底不许拉到视口底之上，那会藏住当前行）。纸比视口短时上界为 0，不可滑动。
- **作用点**：`paperUserOffsetVp` 作为 translate 加在纸的渲染位置上（纸视口内容整体 `.translate({ y: paperUserOffsetVp })`，与 2.1 的锚定叠加），不改纸高、不改 `scrollYVp`。视口 `clip(true)` 保证滑动时纸不会画进字篮井/键盘区（滑下去的部分被视口底裁掉）。

### 2.3 下一次落字时，动画自动回到落字位

- 触发：下一次内容变化的落字（`commitChar` 落字、`onNewline` 回车、`backspace` 退格——任一改变文档/光标的键）。
- 动作：若 `paperUserOffsetVp ＞ 0`，用 `animateTo({ duration: 250, curve: Curve.EaseOut })` 把它动画回 0，同时正常落字。纸向上滑回落字位，当前行回到落字位（视口底上方一个行高处），用户不用手动拉回去。
- 不触发的情形：单纯点按/移动光标（不改变文档）不回位——用户可能正在翻看旧行，别打断他。

### 2.4 换纸动画重做——旧纸向上飞出，新纸从下方出现

- 现行 `paperTopVp` 动画作废（死值，不再动它）；改在**渲染出的纸**上做 translate＋淡入淡出。
- 新 `@State paperFlyVp: number = 0`（`Index.ets`，传给 `Carriage26` 作 prop，加在纸视口内容的 translate 上，与 `paperUserOffsetVp` 叠加）与现行 `paperContentOpacity` 复用。
- **第①步（旧纸出，300ms）**：`animateTo({ duration: 300, curve: Curve.EaseIn })`，`paperFlyVp: 0 → −(paperH() + paperAreaH())`，`paperContentOpacity: 1 → 0`。旧纸整体向上飞出视口顶（飞出距离＝纸高＋视口高，保证整张纸完全出顶），同时淡出。滚筒同转（`knobAngle ＋180`，现行不变）。
- **第②步（新纸入，300ms）**：清空文档后，先把新纸藏到视口下方——`paperFlyVp ＝ ＋paperAreaH()`（纸整体在视口底之下，被视口 `clip(true)` 藏住）、`paperContentOpacity ＝ 0`；再 `animateTo({ duration: 300, curve: Curve.EaseOut })`，`paperFlyVp → 0`，`paperContentOpacity → 1`。新纸从视口下方滑上来、落到落字位，同时淡入。滚筒再转半圈（现行不变）。
- 总时长 600ms（300＋300，现行时序不变）。动画结束 `paperFlyVp ＝ 0`、`paperContentOpacity ＝ 1`、`paperChanging ＝ false`。
- **自适应**：飞出/藏入距离一律由 `paperH()` 与 `paperAreaH()` 推导（`−(paperH＋paperAreaH)`、`＋paperAreaH()`），不写死 vp。

### 2.5 自适应总则（本批硬要求）

- 本批所有尺寸/位置/距离：纸底锚点 `paperAreaH()`、滑动上界 `paperH()−paperAreaH()`、换纸飞距 `paperH()＋paperAreaH()`，一律由 `stageLayout26()`（`zoneHVp`／`paperH`）与纸内容高 `paperGrowVp` 推导；**不引入任何写死的 y 值或 vp 常数**。时间量（250ms 回位、300ms＋300ms 换纸）是时长不是尺寸，沿用现行值。
- 手机暂缓，只验收平板；不改纸高封顶公式（`paperVisibleTargetVp()`）、不改行高/字号、不改 `paperScroll26()` 的光标跟随（它仍负责长纸时光标可见）。
