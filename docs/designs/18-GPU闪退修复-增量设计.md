## §1 目标与范围

### 1.1 目标

连续快速打字不再闪退，同时**帧率不降、动画不降级**：

1. 100 字快速连打（含 6 次换行）在手机上跑完，不闪退、无 `RENDER_MEMORY_OVER_WARNING`。
2. 帧率保持 120Hz（帧间隔 p50 8–9ms，与批 20 实测同口径），无持续掉帧。
3. 动画主观仍顺滑：拱无回拉、换行纸仍可见滑动、拨杆跟手（17 号稿 §8 预算表全数保留）。
4. 时序容差仍 ±20ms（第 18 批 hilog 口径不变）。

### 1.2 范围

- 只动 `CanvasTypewriter.ets` 的绘制结构（`draw()`、图层创建／重建点、帧时钟每帧的落点）与 Index 侧为配合分层所需的最小传参（如有）。不改动画时序表、不改触发通道、不改逻辑层（换行／换纸／退行的判定）、不改声音、不改键盘命中。
- 回滚开关 `canvas.enabled`（缺省 true）保留；ArkUI 旧主屏保留作最终回滚（16 号稿 §2.2／§6）。
- 测试设备缺省手机 ADA-AL00U（USB），与现行口径一致；平板只在分层几何涉及时补验。

### 1.3 非目标

- 不降帧率、不降 draw 次数、不缩短动画时长（用户已否决，见 §3.4）。
- 不重做 16 号稿的静态像素基线（1083／1087 候选基线口径不变；分层后静态像素须与基线一致，见 §5 回归项）。
- 不动字杆（17 号稿 Q3 已定不画）。

## §2 根因调查：每 draw 约 10.7MB 到底来自哪里

### 2.1 现行 draw() 每帧到底做了什么（已读码，721acaa 版）

`draw()`（`CanvasTypewriter.ets` L914–945）每帧全量：

| 步骤 | 内容 | 尺寸 |
|---|---|---|
| `clearRect(0,0,widthVp,heightVp)` | 清全屏 | 362.7×822.5vp |
| `backgroundLayer` blit | 背景渐变＋已烘焙机身（`buildBackgroundLayer` L820–831） | 全屏 |
| `drawRollerLayer` | 滚筒图＋已缓存明暗渐变（`rollerShade`，L172–173、L872–901）＋底边亮条 | 滚筒区 |
| `paperLayer` 裁剪 blit | 纸纹（`buildPaperLayer` L836–856）＋clip 矩形 | 纸区 |
| `drawArchLayer` | 中央件（哥特拱） | 拱区 |
| `machineFrontLayer` blit | 压纸卷＋拨杆支架（`buildMachineLayer` L715–782） | 全屏 |
| `drawLever`／`drawTypebar` | 拨杆、字杆（55° 静止） | 小区 |
| `drawTexts` | 行文字＋光标三角＋**键帽叠字（1920s 43 帽，每帧重填）** | 纸区＋键带区 |

图层位图（`machineLayer`／`machineFrontLayer`／`backgroundLayer`／`paperLayer`，L152–155）只在 `buildStaticLayers()`（L707）里创建一次，切机／切纸才重建（`machineBuildCount`／`paperBuildCount` 打点，L781／L855）。`redrawPaper()`（L865）只置 `paperDirty`，不重建位图。渐变已缓存（批 2 修法）。所以**图层位图重建不是每 draw 的成本**——除非有代码在逐帧调重建（见 E0）。

帧时钟（`ensureFrameClock` L957–1130）：单一常驻 Animator，`onFrame` 每帧插值（拱追踪器／纸段／换行 O／O 弹簧／拨杆），帧末 `needDraw = 任一活动 || (leverActive && leverDirty)` 时调一次 `draw()`。**但"每帧最多一次 `draw()`"（17 号稿 §2.7）有两处例外须注意**：`onCandidatesChanged`（L503–505）与 `onPaperReset`（L489–493）是无守卫的直接 `draw()`，动画期间可与 onFrame 的 `draw()` 同帧 double-draw（见 §2.4 预算表的"直接 draw 附加"行；修法时给这两处加与 onFrame 同源的守卫，见 §4.3）。**CPU 侧每帧只画一次、绘制 1ms 量级，但 GPU 侧每 draw 涨约 10.7MB。**

### 2.2 数量级验算：10.7MB 就是"一张全屏"的量级

手机 ADA-AL00U：1224×2776 物理像素（362.7×822.5vp × 3.375）。像素格式（RGB vs RGBA）尚未确认，E2／E3 顺带钉死。

| 候选 | 字节数 | 与 10.7MB 的关系 |
|---|---|---|
| 全屏 RGBA8888（4B/px） | 1224×2776×4 = 13,591,296 ≈ **13.6MB** | 10.7MB 是它的 79% |
| 全屏 RGB888（3B/px） | 1224×2776×3 = 10,193,472 ≈ **10.2MB** | 10.7MB 是它的 105% |
| 纸层（891×1259px，RGBA） | ≈ 4.5MB | 不到一半 |
| 单个拱／拨杆／字杆贴图 | < 1MB | 一个量级以下 |
| 一行 fillText 光栅化 | KB 量级 | 可忽略 |

**最可能的来源（待 E0–E6 证实或证伪）：主 Canvas 的全屏渲染目标（帧缓冲／呈现面）每 draw 被重新分配或重新上传一次，且旧面在动画期间不释放。** 10.7MB 与"一张全屏 3B/px 表面"几乎相等，与任何一层位图、任何一次渐变、任何一次 fillText 都对不上量级。`drawImage` 拼的是已存在的位图（blit，不新建表面），`clearRect` 也不新建表面——所以成本不在 `draw()` 的某一次调用本身，而在**每 draw 触发一次全屏表面的呈现／合成**（Canvas 内容上屏时，合成器为该帧取一份全屏纹理；若管线保留已呈现帧或每帧新建后端缓冲，显存就按"每帧一张全屏"的速度涨）。

另外两种次可能机制，实验须区分（见 §2.3）：

- **机制 B（队列积压）**：每帧 GPU 工作量大，合成器跟不上 120Hz，待呈现帧在队列里积压，显存随队列长度涨；空闲时队列排空、显存回落。若属实，降单帧工作量（小面积）即可让队列排空，显存有界。
- **机制 C（某层逐帧重建）**：某处代码在逐帧重建位图／渐变／PixelMap（如 `buildStaticLayers` 被逐帧触发、或 `drawTexts` 的字体／`createLinearGradient` 漏网）。读码未见（渐变已缓存、位图只建一次），但须由 E0 的计数打点排除，不许凭读码定案。

### 2.3 判定实验（桌面端真机跑，顺序即优先级）

测量手段（现成，无需新 API）：批 20 已加的 `draw frame` hilog 打点（`draw()` 入口，含时钟时间戳）用于数 draw 次数；系统日志的 `RENDER_MEMORY_OVER_WARNING`（批 2 实测在 gpu 1.52GB 时报——**一次观测值，非已知阈值**）与 `RENDER_MEMORY_OVER_ERROR`（kill 行含 `gpu[...]` 绝对值）用于读 GPU 数。单次成本 =（kill／warning 时 gpu 值 − 起始 gpu 值）÷ 该段 draw 数。起始 gpu 值取测试段开始前最近一次 WARNING／kill 行的 gpu 值，或以冷启动后静止态为基线（须在批报告里写明基线来源）。

**阈值穿越协议**（E1–E4 共用）：仅有的读数是 WARNING（约 1.5GB）与 ERROR（约 2.157GB）两条阈值线，小 draw 数从冷基线起未必触及任一阈值。协议：先预加载（打字或空 draw）至接近 WARNING 线，再记"到 WARNING 的 draw 数"作为可比指标；基线 GPU 值以冷启动后首次 WARNING 行反推（或以 kill 行的 gpu 绝对值减去当段 draw 数的估算）。

**测试钩子**：实验操作改用**运行时调试开关**（`canvasDebugGPU` 之类的临时开关，Phase 0 分支专用，修法分支删除），不用逐层注释代码多次"改代码→重建→安装→测"循环。`draw()` 是 private，Phase 0 分支内补一个测试钩子（`debugDrawOnce()`，或把 `draw()` 的调用点收敛到一处可注入的函数）。"跑 N draw"的节奏写死：**120Hz 帧时钟驱动**（与真实动画一致），不用紧循环（紧循环的 GPU 队列行为与帧时钟不可比）。抗锯齿设置（`RenderingContextSettings(true)`）列为 Phase 0 变量（零成本诊断对照：开关抗锯齿各跑一次 E1，看单次成本是否变化）。

| 编号 | 实验 | 做法 | 判定 |
|---|---|---|---|
| **E0** | 重建计数排除 | 打字测试段内读 `machineBuildCount`／`paperBuildCount`（已有打点）与 `static layer rebuilt` 日志。计数在测试段内必须不变。 | 若任一计数随 draw 涨 → 机制 C 成立，先修重建触发点（这是独立 bug，不在本稿修法内，另记）；若不变 → 排除 C。 |
| **E1** | 静止 draw 对照 | 无动画、无输入：直接调 `draw()` 200 次（值全部不变），数 GPU 涨量。 | 若仍涨约 10.7MB/draw → 成本与动画内容无关，是表面／呈现本身；若几乎不涨 → 成本与"值在变"有关（如每帧新纹理上传），修法重心转向"值不变时不呈现"。 |
| **E2** | 逐层消融 | 逐项关掉 `draw()` 里的一层 blit（background／machineFront／paper／roller／arch／texts／lever／typebar，运行时调试开关控制），每项各跑 100 draw，记单次成本变化；消融须包含"文字重填"这一项的单次成本（供 Q3 定夺用，见 §8）。 | 某层去掉后单次成本断崖跌 → 该层上传是主因；全部去掉只剩 `clearRect` 仍约 10MB/draw → 帧缓冲本身是主因，局部重绘**不能**修（见 §3.1 的 go/no-go）。 |
| **E3** | 空 Canvas 对照 | 同尺寸空白 Canvas，只 `clearRect`，200 draw；顺带钉死像素格式（RGB vs RGBA）。 | 与 E2 的"只剩 clearRect"互相印证：若空 Canvas 也约 10MB/draw → 全屏表面是主因无疑。 |

### 2.4 预算再算（为什么"降单次成本"必须降到很低才够）

100 字验收段的 draw 数：打击 100×11 ≈ 1100；换行 6×84 ≈ 504；直接 draw 附加（`onCandidatesChanged`／`onPaperReset` 等无守卫的直接 `draw()`，中文打字时几乎每键一次，与帧时钟 draw 同帧叠加）约 100；合计 **≈1700 draw**。300 字长会话 ≈ 5100 draw。

| 单次 retained | 100 字段（1700 draw） | 300 字（5100 draw） |
|---|---|---|
| 10.7MB（现状） | ≈18GB（必死 8 次） | — |
| 1.0MB | ≈1.7GB（仍近硬顶） | ≈5.1GB（死） |
| 0.5MB | ≈850MB（过，见 §5） | ≈2.6GB（死） |
| 0.1MB | ≈170MB | ≈510MB（过） |
| ≈0（transform 路线） | 仅基线 | 仅基线 |

transform 路线的纸内容重画成本（另计，不在上表内）：内容 Canvas 每字重画一次，若沿用 `transferToImageBitmap` 模式每次新建纸大小位图（约 4.5MB），300 字 ≈ 1.35GB——所以 §4.3 写死实现模式为**持久 Canvas、复用 backing store**（内容 Canvas 只建一次，内容变时在原 Canvas 上重画，不新建位图），此项成本不计入上表。

结论：**只要每 draw 还 retained 一张全屏面的零头，100 字段勉强过、300 字长会话仍死。** 局部重绘若只能把单次从 10.7MB 降到 1MB 量级，是不够的；只有把"每 draw 新表面"这个机制本身去掉（transform 路线，单次 retained ≈ 0），长会话才安全。这就是 §4 把 transform 定为主修法、局部重绘定为辅助的算术依据。

## §3 修法方案比较（帧率 120Hz 不动，只降单次成本）

比较维度统一为：**降的是 CPU 还是 GPU、是否触及 10.7MB/draw 的根因（§2.2 的全屏表面机制）、风险与回退。** 所有方案都保留帧时钟、tick 触发通道、时序表（±20ms）与 `canvas.enabled` 回滚开关。

### 3.1 (a) 局部重绘：只重画变化区域

**做法**：`draw()` 入口先算本帧脏区（各活动动画的并集：拱矩形／纸矩形／拨杆矩形／新字行矩形／光标三角），`ctx.save()`＋`clip(脏区)`＋只 `clearRect` 脏区，只重画与脏区相交的层；其余区域不动。脏区按动画种类分档：打击帧只含拱区＋新字行区（约 4% 屏：拱约 1.3%＋新字行区约 2.6%，单次成本约 0.43MB）；纸上滑帧含纸区（约 33% 屏）；换行 O 复位帧含字车带区（约 30% 屏）。腾空区必须用背景层重盖，只 `clearRect` 不重 blit 背景层会透出页面底色。同时把 `drawTexts` 里的键帽叠字（1920s 43 帽，每帧重填、内容永不变）移出逐帧绘制，进静态层（见 §3.2）。

**降什么**：CPU 光栅化量（本已 1ms，省得不多）；**GPU 上传量——仅当平台按脏区上传时才省**（待 E4 验证）。

**是否触及根因**：**不一定。** 若 E4 证实成本∝面积，则触及（单次从 10.7MB 降到"脏区面积占比×10.7MB"：打击帧约 0.43MB，纸滑帧约 3.5MB）；若 E4 证实成本与面积无关（每 draw 恒约 10MB），则**完全不触及**——全屏表面照样每帧新建，局部重绘白做。这是本稿要求 E4 先行的原因。即使面积成正比，纸滑帧 3.5MB×35 draw ≈ 123MB／次换行，6 次换行 ≈ 740MB，100 字段仍吃紧（见 §2.4）；局部重绘**单独不能**过 300 字长会话验收。

**风险**：脏区算错 → 残影／撕裂（旧内容残留）；clip 与现有纸容器 clip（`draw()` L928–935、`drawTexts` L1192 起）叠加，须小心 save/restore 配对；每帧算脏区并集本身是新逻辑，须单测钉住（脏区必须覆盖上一帧与本帧的并集，否则移动件拖影）。

**回退**：脏区计算加开关（缺省开；出问题时关回全屏重绘——但全屏重绘即回崩溃态，所以此回退只用于定位，不用于交付；真正的回退是 §3.3）。

### 3.2 (b) 图层合成优化：静态一次画好，动件分层，让合成器搬纹理

**做法**（结构性重组，分两步）：

- **B1 拆全屏透明大位图（可选子项，不占关键路径）**：`machineFrontLayer` 是全屏位图（362.7×822.5vp），但实际内容只有压纸卷（纸宽条带）＋拨杆支架（60vp 小框），其余全透明——每帧全屏 blit 一张基本透明的大纹理。拆成两个小位图（bail 条带、bracket 小框），按位置单独 blit。精确矩形以代码 L730／L757／L766 的几何为准（bail 条带与 bracket 小框的精确矩形写进实施记录）。该纹理只分配一次（约 13MB 基线，占硬顶 0.6%），不影响每 draw 成本，所以 B1 移出 Phase 1 关键路径（有空再做，不阻塞验收）。`backgroundLayer`（全屏渐变＋已烘焙机身）保留全屏 blit（它是底，动不了），但机身静态部分（键带、功能行、底座）本就静止，**只画一次**的现状已对，不用再动。
  - **baked-renderO 不变量**：`buildMachineLayer` 把当前 `renderO` 烘焙进静态层（L730／L765），只在初始化（`prepare()` L674，`renderO=0`）与换机／换纸后重建；拆出的 bail／bracket 仍须带 live `renderO` 偏移 blit（现行 L939 口径），否则卷与支架不再随 O 动。静态层重建时若 `renderO≠0`，须先把 O 归零再烘焙，或把烘焙值记为"烘焙时 O"并在 blit 时补差值（二选一写死）。
- **B2 分层 Canvas**：把现在一个全屏 Canvas 拆成上下叠放的两个（或三个）Canvas 组件，由 ArkUI 合成：
  - **静态 Canvas**（全屏）：背景渐变＋机身＋键带＋功能行＋**键帽叠字（1920s 43 帽）＋功能行 6 个文字标签（EN／删除／换行／换纸／退行／字符）**＋字体条，**只画一次**（切机／切纸／换字体时重建，其余时间不画），动画期间零 draw。触发点写死：初始化、`prepare()`、换机、换纸、换字体、换色带时重建。
  - **字车 Canvas**（只盖字车带：y 从纸顶到木底座底，带高＝max（四机拨杆包围盒高，拱高＋纸滑行程），先算四机拨杆包围盒再定精确值，不再写"约 250vp"）：纸＋滚筒＋拱＋压纸卷＋拨杆＋字杆＋行文字，每帧只重画这一个 Canvas。单次表面成本随 Canvas 面积同比降（带高／822.5，约 30% → 约 3.2MB/draw，仍高，见 §2.4）。
  - （可选）**纸文字独立小 Canvas**：行文字＋光标只在文档内容变时重画（落字／删除／换行时各 1 次），动画期间由 ArkUI 按 transform 平移，不重画。见 §3.3 的"内容光栅与动画变换分离"。是否在本批由 Q3 定夺（已移到 Phase 0 之后，见 §8）。
  - **L0–L3 重映射表**（16 号稿 §3.1 的分层如何落到新结构）：L0（底色）＋L1（静态）进静态 Canvas；L2（纸层）进纸内容 Canvas（Phase 2 含 Q3 时）或字车 Canvas；L3 动件按 §3.3 接线表拆原生组件；层叠顺序由 ArkUI 组件树顺序保证（静态 Canvas 在下、字车 Canvas／原生动件在上）；clip 与层叠顺序由组件树保证，不再由单一 `draw()` 内的 save/restore 保证。

**降什么**：CPU（静态层零重复绘制）＋ GPU（每 draw 的表面从全屏降到字车带面积；静态纹理常驻、不重复上传）。

**是否触及根因**：**部分触及。** 它把"每 draw 一张全屏表面"降成"每 draw 一张字车带表面"（约 1/3），100 字段约 1700×3.2MB ≈ 5GB——**仍不够**。所以 B2 单独不能过验收，必须与 §3.3 组合（B2 是 §3.3 的结构前提：动件先从全屏 Canvas 里拆出来，才能交给 transform）。

**风险**：多 Canvas 叠放的层叠顺序与 clip（纸须在滚筒处 clip、压纸卷须在纸之上、拱须在纸之上）要在 ArkUI 层重建，错一层即视觉错；两 Canvas 的几何必须用同一份几何常量（`paperX()`／`paperY()`／`stackTop()`）对齐，否则错位（注意：`computeTransform` 只在 `aboutToAppear` 打日志（L535），绘制路径无任何 `setTransform`／`scale`，Canvas 按窗口 vp 直接绘制——**两 Canvas 不共用 computeTransform 的变换**，只共用几何常量）；TopBar／无障碍覆盖层／IME 锚点的位置同步逻辑（现行读同一几何）须复核；折叠／尺寸变化时双 Canvas 在同一 `onAreaChange` 回调里重建（不许两 Canvas 分两次回调重建，中间态会错位一帧）。

**回退**：分层前后各留一个提交；静态像素门图（§5 回归项）任一区超阈即回退该步。

### 3.3 (c) 动件改走原生 ArkUI transform：合成器搬纹理，不重画

> **本节是待验证的修法细节，不是已定结论。** 接线细节仅当 E4／E6 证实相应前提时生效（E4 证实面积无关 → transform 为必选项；E6 证实桥接存在 → 接线表生效）。

**绑定机制（R-S1，核心缺口，v2 新增）**：`renderO`／`renderArchX`／`renderPaperTop`／`renderLeverRatio` 全是 Canvas 内部普通 private 字段（非 `@State`），ArkUI 不会因此重渲染。绑定机制二选一写死：
- (a) 渲染值改 `@State`＋`.translate()`／`.rotate()`，并把"每帧 @State 更新的成本"列为 R-c1 的首要验证项（验证动画期间帧间隔仍 8–9ms、且 ArkUI 不触发布局）；或
- (b) 存在不经过 @State 的命令式更新路径（须写明具体 API，如 RenderNode／NodeController，否则不成立）。
在绑定机制未定前，§3.5 表格里 (c) 方案"CPU：大（动画帧零光栅化）"的断言加注"待 E6 证实"，不许当已定结论。E6（§2.3）是绑定机制的前置验证。

**动件接线表（R-S5，每件写死四列：原生组件类型、布局位置、transform 属性与值、值的语义）**：

| 动件 | 原生组件 | 布局位置（锚点） | transform 属性与值 | 值的语义 |
|---|---|---|---|---|
| 纸（含行文字） | 纸容器（纸纹 Image＋纸内容 Canvas＋滚筒＋压纸卷＋支架） | `(paperX(), stackTop())`（未含动画值的基线） | `.translate({x: renderO, y: renderPaperTop})` | 动画值（增量，布局与 transform 不重叠） |
| 滚筒 | 滚筒 Image＋明暗罩（渐变一次画好或原生渐变） | 随纸容器（与纸同一容器，天然同步） | 随纸容器平移 | — |
| 哥特拱 | 拱 Image 组件 | `(0, strikeYVp)`（x 锚点为 0） | `.translate({x: renderArchX})` | 绝对 x（布局 x 必须为 0，否则右偏） |
| 拨杆 | 拨杆 Image 组件 | 组件中心落在销钉处 | `.rotate({angle, centerX, centerY})`（显式指定销钉，以 ArkUI 实际支持的旋转中心参数为准） | 角度（绕销钉，与 Canvas 的 `drawLever` 同数学） |
| 字车底座／支架 | 底座静止留静态层；支架随 O 动进字车容器 | — | 随纸容器 | — |
| 字杆 | 55° 静止，不画（17 号稿 Q3） | 不动 | — | — |

**默认 transform 种类**：`.translate()`／`.rotate()`（纯渲染变换），不默认 `.offset()`（布局侧属性）。R-c1 以实测为准，实测项里加"`.offset()` 与 `.translate()` 的重布局对比"。

**素材来源**：拱／拨杆贴图复用已有 `imgCentral`／`imgLever` 字段（CanvasTypewriter 内已有），不新增 prop、不改 `machines/*`（蓝图零引用铁律不变）。若某机型的贴图只在蓝图内、CanvasTypewriter 拿不到，改法写"由 Index 经现有 prop 传入"，不许 CanvasTypewriter 直接 import 蓝图。

**核心原则——内容光栅与动画变换分离**：纸上的文字（行文字＋光标＋页码）只在**内容变时**光栅化一次（落字／删除／换行／换纸时各 1 次 draw，进纸内容 Canvas）；动画期间（拱滑／纸滑／O 复位／拨杆摆）**只改 transform**（translate／rotate），不调任何 `draw()`。这样每字打击的 11 次动画帧里，Canvas draw 次数为 **0**，GPU 新表面分配为 **0**，只有合成器按矩阵搬已有纹理（GPU 纹理变换，近乎零成本）。纸内容 Canvas 的实现模式写死：**持久 Canvas、复用 backing store**（内容 Canvas 只建一次，内容变时在原 Canvas 上重画，不新建位图；若沿用 `transferToImageBitmap` 模式每次新建纸大小位图（约 4.5MB），300 字 ≈ 1.35GB，见 §2.4）。

**降什么**：**GPU（根因本身）**——每 draw 的全屏表面分配被消除；CPU（每帧的光栅化也被消除，只剩每帧一次 transform 属性写）。

**是否触及根因**：**是，唯一触及根因的方案（待 E6 证实桥接存在）。** 10.7MB/draw 的来源是"每 draw 一张全屏表面"；transform 路线让动画帧不再产生 draw、不再产生新表面，单次 retained ≈ 0，1700 draw 的 100 字段与 5100 draw 的 300 字长会话都只剩基线显存（见 §2.4 表）。

**风险与待验证点**：

- **R-c1（最大）**：帧时钟每帧写 ArkUI 属性（@State 或组件属性）是否会触发重布局／重渲染？若实现里每帧改的是**布局属性**（如 `position` 的 x/y 走布局），等于把旧 @State 驱动问题换个地方重演。**须用 transform 类属性**（`.translate()`／`.rotate()` 中不触发布局的那一路，以实测为准），且须验证：动画期间 `draw()` 调用次数为 0（hilog `draw frame` 计数）、帧间隔仍 8–9ms。验证不过 → 退回 §3.2 的分层 Canvas 方案（B2＋§3.1）。
- **R-c2**：clip 与层叠要在 ArkUI 层重建（纸在滚筒处 clip、压纸卷在纸之上、拱在纸之上、拨杆支架与底座的相对关系）。错一层即视觉错，须以静态像素门图逐项验收（§5）。
- **R-c3**：纸内容 Canvas 的重画时机（内容变时 1 次）与动画帧的时序配合：落字那帧既要内容更新（新字上屏）又要拱动画——内容 Canvas 的 1 次 draw 与 transform 更新须在同一帧内完成，否则新字晚 1 帧出现（验收：落字反馈启动仍 ≤1 帧，17 号稿 §8 口径）。
- **R-c3 补充**：候选栏／功能行／字体条是静态的，不进 transform，留静态层；IME 锚点（`cn_anchor`）与无障碍覆盖层的位置同步逻辑须随新几何复核（现行读同一 `paperX()`／`paperY()`，分层后须确认锚点仍对）。

**回退**：`canvas.enabled` 开关保留（关 → ArkUI 旧主屏）；分层与 transform 各自独立提交，transform 回退时保留分层（B2）＋局部重绘（§3.1）作为降级组合（100 字段可过、长会话受限，须在批报告里如实写清降级后的预算）。

### 3.4 (d) 已否决：降帧率／降 draw 次数（不采用）

以下方案**用户已明确否决（2026-11-16 14:35），本稿不采用、不推荐、不作为止血带**，列出仅为防后人重提：

- 帧时钟节流到 60Hz（120Hz→60Hz）：draw 数减半，预算从约 200 draw（1.7 秒）延到约 400 draw（约 3.4 秒）。**治标不治本**：单次 10.7MB 不变，正常打字几秒后仍崩；且与用户投诉（"帧率特别低、跟瞬移没区别"）反向——用户要的是帧率上去，不是下来。
- 值变化小于阈值时跳过 draw／动画合并以减少 draw：同理，只延缓崩溃，不消除崩溃；且阈值跳过会引入"小步不动"的顿挫感，与"顺滑"目标冲突。
- 缩短动画时长以减少 draw（如打击 90ms→50ms）：改手感、不修根因，17 号稿 §5 已否决过一次。

**止血带说明**：本稿不设"先降频止血、再慢慢修"的两段走——降频止血本身就是用户否决的方向。P0 的止血只能是"修法本身先行"：§4 的 Phase 0（E0–E6 判定）＋ Phase 1（分层）是最快能落地的降成本动作；若判定指向 transform 为必选项，则 Phase 1 与 Phase 2 不拆两批，串行一次做完。

## §4 选定方案与实施步骤

### 4.1 选定：先判定，再按判定走两条路（测量门控）

**Phase 0——判定先行（不写修法代码，先跑 E0–E6）**。E4 是分水岭，E6 是 transform 路线的前置验证：

- **若 E4 证实成本∝面积**：主修法 = (b) 分层 Canvas ＋ (a) 局部重绘（分层后在字车 Canvas 内再做脏区裁剪）；(c) transform 作为下一批优化（长会话仍吃紧时再上）。验收按 §5，但 300 字长会话项记为"有条件"（须实测过才算）。
- **若 E4 证实成本与面积无关（恒约 10MB）**：主修法 = **(b)＋(c)**（分层是结构前提，transform 是根治手段）；(a) 局部重绘**不做**（已证无效，不浪费工作量）。验收按 §5 全项。
- **若 E6 证实桥接不存在**：(c) 路线不可行，回退到 (b)＋(a) 的降级组合（见 §6 R2）。
- **若 E0 发现逐帧重建（机制 C）**：先修重建触发点（独立小修，另记提交），再重跑 E1–E6。

Phase 0 的结论写进批报告（附 hilog 原文与 gpu 数值），修法代码按结论走，不许先写代码再补实验。诊断代码在独立测试分支（`exp/gpu-probe-<日期>`）上跑，可与评审并行（见 §6 R7）。

### 4.2 Phase 1——分层（结构前提，两条路共用）

1. 拆 `machineFrontLayer` 全屏位图为 bail 条带＋bracket 小框两个小位图（B1，**可选子项，不占关键路径**，精确矩形以代码 L730／L757／L766 的几何为准）。
2. 把键帽叠字从 `drawTexts` 的逐帧绘制移入静态层（内容永不变，不许每帧重填），落静态 Canvas 的 L1（静态层），与键帽底图同层；功能行 6 个文字标签（EN／删除／换行／换纸／退行／字符）一并点名进静态层。
3. 拆单 Canvas 为静态 Canvas（全屏，只画一次）＋字车 Canvas（字车带，带高＝max（四机拨杆包围盒高，拱高＋纸滑行程），先算四机拨杆包围盒再定精确值）。两 Canvas 的几何用同一份几何常量（`paperX()`／`paperY()`／`stackTop()`）对齐，不共用 `computeTransform` 的变换（`computeTransform` 只打日志，绘制路径不用它）。L0–L3 重映射见 §3.2 的映射表。静态像素门图逐项验收（§5 回归项）。折叠／尺寸变化时双 Canvas 在同一 `onAreaChange` 回调里重建。
4. 帧时钟、tick 通道、时序表不动；`canvas.enabled` 开关不动。

### 4.3 Phase 2——动件 transform（根治，E4 指向面积无关时必做；E4 指向面积成正比时可与 Phase 1 同批做，不另立项）

1. 纸容器（含纸纹 Image＋纸内容 Canvas＋滚筒＋压纸卷＋支架）改为原生组件，按 §3.3 接线表：布局 `(paperX(), stackTop())`＋`.translate({x: renderO, y: renderPaperTop})`；拱 Image 布局 `(0, strikeYVp)`＋`.translate({x: renderArchX})`；拨杆 Image 布局中心落在销钉处＋`.rotate({angle, centerX, centerY})`。绑定机制按 §3.3 二选一写死（@State＋translate／rotate，或命令式更新路径），并过 E6 验证。
2. 纸内容 Canvas（纸大小）只在文档内容变时重画 1 次（落字／删除／换行／换纸）；动画帧内零 `draw()`（以 hilog `draw frame` 计数为证）。实现模式写死：**持久 Canvas、复用 backing store**（内容 Canvas 只建一次，内容变时在原 Canvas 上重画，不新建位图）。
3. clip 与层叠在 ArkUI 层重建：纸容器 `.clip()`（滚筒处）、压纸卷在纸之上、拱在纸之上；TopBar／无障碍覆盖层／IME 锚点位置同步复核。
4. transform 须走不触发布局的属性（R-c1）；实现后验证动画期间 `draw()` 计数为 0、帧间隔仍 8–9ms。
5. `onCandidatesChanged`（L503–505）与 `onPaperReset`（L489–493）的无守卫直接 `draw()` 加与 onFrame 同源的守卫（帧时钟活动时只置 dirty、不直接 draw），恢复"每帧最多一次 draw()"。

### 4.4 Phase 3——局部重绘（仅当 E4 证实面积成正比时，在剩余逐帧 Canvas 内做）

在字车 Canvas（若 Phase 2 后仍有逐帧 Canvas）内加脏区裁剪：打击帧只含拱区＋新字行区；纸滑帧含纸区；换行 O 复位帧含字车带区。脏区 = 上一帧与本帧的并集（防拖影），单测钉住。腾空区必须用背景层重盖（只 `clearRect` 不重 blit 背景层会透出页面底色）。E4 若证实面积无关，本 Phase **跳过**。

### 5.2 GPU 峰值"1.0GB 目标"的说明（诚实口径）

App 内无直接读 GPU 显存的 API，可观测的只有两条系统线：`RENDER_MEMORY_OVER_WARNING`（批 2 实测在 gpu 1.52GB 时报——**一次观测值，非已知阈值**）与 `RENDER_MEMORY_OVER_ERROR`（kill 行含 gpu 绝对值，硬顶 2.157GB）。所以验收分两层写：

- **硬线（算过）**：全程无 WARNING、无 kill。无 WARNING 意味着峰值低于约 1.5GB 的 warning 线，离 2.157GB 硬顶至少有约 0.6GB 余量。
- **目标线（争取，按路径分档）**：transform 路线单次 retained ≈0／≤0.1MB；降级路径 ≤0.5MB（§2.4 算术：1700 draw×0.5MB ≈ 850MB），由 E1–E6 同法复测。达不到目标线但无 WARNING 时，记"硬线过、目标线未达"＋不符点，不判 FAIL，下一批继续降。
- **应力测量程序**（单次 retained 在成功时无法直接测量，故加此程序）：验收段跑完后，若全程无 WARNING（即无读数），故意追加一次应力段（连续快打至触发一次 WARNING，读 WARNING 行的 gpu 绝对值），反推单次 retained。应力段只用于测量，不计入验收段。

- 16 号稿 §3.3 时序表全部项＋第 17 批已 PASS 项（字车步进、跟手）＋第 18 批已 PASS 项（拱移动、删除弹簧、菜单／页面／换装、候选栏滚动）的动画相关项。

### 5.4 验收不靠什么

- 不靠"draw 次数少了"（降 draw 不在本稿修法内，次数只作分母用于算单次 retained；transform 路线下动画帧 draw 计数为 0 是硬断言，不是"次数少了"）。
- 不靠视频计时（VFR，不能作毫秒计时；视频只作"纸在滑／拱无回拉"的视觉确认）。
- 不靠 CPU 绘制耗时（P2 的 1ms 结论已被 GPU 轴证伪，不再作为"不瓶颈"的证据）。
- 逐帧 hilog：`draw frame` 与 `frame tick` 两条打点并列（`frame tick` 在 onFrame 末段，`if (activeNow && value > this.frameLastValue)`），按路线选用。

| 风险 | 判定／应对 |

| **R1：E4 证实成本与面积无关，局部重绘无效** | 这是预期内的可能结果，不是失败。应对：Phase 1 分层照做（结构前提），Phase 2 transform 为必做；§3.1 不做。批报告写明 E4 数据，不许硬上局部重绘凑数。 |

| **R4：纸内容 Canvas 重画时机与动画帧错位（新字晚 1 帧）** | 应对：落字反馈启动仍 ≤1 帧（17 号稿 §8 口径）；内容重画与 transform 更新同帧完成，hilog 记 `trigger strike` 与内容 Canvas draw 帧。 |
| **R5：测量本身扰动（hilog 每 draw 一条）** | 批 20 已加 `draw frame` 打点并沿用至今，扰动已在既往数据内；Phase 0 与验收用同一打点，数据可比。另有 `frame tick` 打点并列（见 §5.4）。不另加逐帧打点。 |
| **R6：分层改动波及 TopBar／无障碍覆盖层／IME 锚点位置同步** | 应对：分层后复核三处位置（现行读同一 `paperX()`／`paperY()`／几何常量）；无障碍覆盖层（2C-2）与 IME 锚点（`cn_anchor`）逐项点按复验。 |
