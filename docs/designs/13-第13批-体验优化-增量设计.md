## §0 本批新证据改了上一批哪条结论、为什么改

1. **第 12 批 ⑤「主假设不成立、K 未改」存疑，结论本身待重验。** 批报告的机制解释（「PaperStage offsetXVp 写死 0、纸不消费 O」）不成立——只看了内层 prop，漏了纸容器 `.offset()` 带 O（Index 挂载 PaperStage 的外层容器 x 含 `carriageOffsetVp`）与滚筒 `rollX()` 吃 `rollerOffsetVp = carriageOffsetVp × ROLLER_K`。代码上纸与滚筒都应随 O 移动，与像素表「四机位移均为 0」互相矛盾，原因未查明；且复现截图未入仓，像素表无法独立复核。所以「K 不用改」不是已证实的结论，只是「在一次未留档的复现里没看到位移」。本批 A 项先按 §2 重新复现并带截图入仓，解开矛盾再定修法，不预设修法。
2. **第 12 批 ⑤ 的验收对象本身错了：用户投诉的是相对联动，不是绝对位移。** 按代码，平板 O=−64 时纸应左移 64vp、滚筒应左移 51.2vp（K=0.8），两者相对滑移 12.8vp——纸相对滚筒表面滑了 12.8vp，这正是用户说的「纸张与纸筒存在错位，没有正确联动」。第 12 批的判定只验绝对位移，会在错位以设计值存在时宣布「机制正常」。本批 §2 的验收标准改为相对滑移（阈值 2vp），并加 K=1.0 对照试验，追问 K=0.8 为何存在（物理上纸面与滚筒表面速度应为 1:1，手机 K=1.0 正是这个口径）。
3. **导出比上一批以为的更严重：旧纸内容在数据层根本不存在。** 第 12 批时只知道导出页没有多选 UI；本次查码证实，换纸时 `onPaperChange` 调 `DocModel.clear()` 把行清空，全仓无任何旧纸存档（`archive`／`saveSheet`／`sheetHistory`／`sheets` 零命中），`flushSave()` 随后把清空后的文档写盘，旧纸连磁盘上都不剩。所以 ⑥「导出整篇多张纸」不是仅改导出页 UI 就能解决的，必须先改保存模型（换纸时归档旧纸），否则无内容可导。
4. **退行确认全程静音（无音效、无震动），换纸同样全程静音。** 退行在批内；换纸静音只作观察记录，不在本批范围（用户只点了退行）。
5. **1950s／1960s 的 hero 整机图已由沙箱亲看确认；四机 front 图也在 resolve 时亲看。** 查码时 1950s／1960s hero 图未亲看；本稿撰写前已补看：1950s 奶油流线机整机全貌（纸已装）、1960s 灰色电动整机全貌（纸已装、带电源线），均为真整机图。resolve 时又亲看了四机 front 图（见附录补看记录）：四图均为正面整机全貌。⑤ 改选 front 图（见 §7）。

## §2 A： 第 12 批遗留——⑤ 纸筒错位重新复现＋第 12 批 ② 项验收 ⑦ 补验

### 2.1 问题陈述

第 12 批复现结论「四机纸左缘与滚筒带位移均为 0」与代码矛盾：纸容器 `.offset()` 的 x 含 `carriageOffsetVp`（Index 挂载 PaperStage 的外层容器），滚筒 `rollX()` 吃 `rollerOffsetVp = carriageOffsetVp × ROLLER_K`（平板 K=0.8、手机 K=1.0）。O=−64 时纸应左移 64vp、滚筒应左移 51.2vp（平板），像素却量到 0。候选排查点：截图时 O 是否真为 −64（是否拍在换行回位之后，O 已归 0）；容器 offset 是否被其他布局覆盖；量测对象是否选错（纸左缘 vs 纸内文字左缘；滚筒带 vs 滚筒罩）。

术语：滚筒带＝随纸同速纵向滚动的筒面纹理层（`CarriageLayers.ets` 纹理 Stack）；滚筒罩＝固定不动的柱面明暗罩；端帽＝滚筒两端金属帽。

钳制定义（`machines/1920s/CarriageLayers.ets` L63–66、L114–121）：`baseLeft() = paperLeftFixedVp − knobD()`，是木底座左缘，不是滚筒静止位。平板数值：静止位 rollX≈103.5vp、baseLeft≈45.0vp；O=−64 时 rollX≈52.3vp > 45.0vp，钳制不触发——§2.2 分支 1 的期望值（纸 −64、滚筒 −51.2）成立。K=1.0 时 rollX≈39.5vp < 45.0vp，钳制会触发，滚筒位移上限 58.5vp（103.5−45.0）——K=1.0 对照试验须以此上限为准，实测停在 −58.5vp 附近即钳制生效，不是异常。满行程 O=−64 时 K=1.0 滑移仍为 5.5vp＞2vp（滚筒行程上限 58.5vp＜纸行程 64vp），钳制是绑定约束，不是 K 能解决的；13 字协议不测满行态，满行程残留 5.5vp 是已知项，批报告记录，不进 ⑤ 的验收。rollX 的钳制无 hilog 行（静默钳制），须从实测位移推断是否触发。

验收标准是相对滑移：`|纸 Δ − 滚筒 Δ|`，阈值 **2vp**（2vp 远高于量测噪声、远低于 12.8vp 设计滑移）。滑移 > 2vp 即算错位。阈值是工程约定，可见性以批报告实测为准。

## §3 ① 键帽按下效果逐帽对应

### 3.1 现状（查码证实）

- 唯一渲染点 `components/PhotoKeybed.ets`：全部字母／数字／符号键共用一个正圆（直径 `2×hitRadius`、黑 0.30、叠字下沉 2vp）；空格条另有一套写死圆角 8 的矩形。`hitRadius` 是命中半径（`KeymapModel.ets` L143：最小行距 × 0.42），不是键帽尺寸，却同时管命中阈值、圆直径、叠字容器宽。叠字＝键帽照片上叠加的字母（PhotoKeybed 渲染的 label 层）。
- 四机键帽真实几何（照片目视＋连通域量测，平板 vp）：1920s 43 帽全是同一正圆 40.4×39.9，圆 43.7 只大 8%——效果是按这机校准的，唯一「对」的机型；1930s 横椭圆约 31×27，圆 34.5 高出 26%、上下各溢出约 3.6vp；1950s 圆角方帽（顶面约 31×20，推测，见下），圆 35.1，方帽四角伸出圆外（量待核实）；1960s 方帽约 32×32，四角伸出圆外约 4.6vp；1960s 宽键 Backspace 66.8vp、Return／Shift 58.6vp、底行 Shift 66–72vp，圆只盖住宽键中央约 50–60%。
- 已证实的命中缺陷：宽键半宽（29–33vp）≫ hitRadius（18vp），点按宽键两端命中不到该键。
- `CapDef` 只有中心点＋行号＋label，无宽／高／形状／圆角；keymap JSON 每帽只有 x＋label。1960s 的 3 个 Shift 有三种宽度（58.6／66–72／同字母键），按 label 分类区分不开。
- 推测待核实（量测时核对）：1950s 帽顶面高约 20vp、全帽高约 28–30vp；1930s 底行两角 Shift 与字母键同大；四机空格条真实圆角（目视估计 1920s ~4、1930s ~5、1950s ~7、1960s ~3vp）；1930s／1950s 透视致同行帽尺寸渐变；1960s 底行行首 Shift 宽 66–72vp。

### 3.2 设计（缺省 D1：逐帽字段，比例存储）

1. **keymap 每帽加可选字段**（比例存储，与现有 `xRatio/yRatio` 同制；量测仍按母版 px 做，入库时换算：`wRatio = w/带宽、hRatio = h/phone 带高（975）、rRatio = r/带宽`——`hRatio` 一律按 phone 带高换算，parse 时 fold 带按 `975/853` 重算；两带宽同为 2048、高为 975 vs 853，一套字段对 h 不成立，须定分母带；母版＝keyband 母版图，phone 带 2048×975、fold 带 2048×853）：`wRatio`（宽）、`hRatio`（高）、`rRatio`（圆角半径）、`shape`（`circle`／`rounded-rect`）。空格的 `rRatio` 存在 JSON 的 `space` 对象里（`KeymapModel` 的 `RawSpace`），解析后进 `KeymapLayout` 新增字段 `spaceR`（vp；缺失 → 8）。按字段回落（缺失组合）：shape 缺失 → 正圆（现有行为）；wRatio 缺失 → w＝2×hitRadius；hRatio 缺失 → h＝w；rRatio 缺失 → r＝h/2（rounded-rect）／空格 r＝8vp。老 keymap 不强制全量补齐也能跑，单测断言回落行为。fold 重算分支的调用点：全仓唯一 parse 调用点（Index L1826）写死 fold=false，本批不新增 fold 解析调用点，重算分支先落代码不跑，待折叠布局重构时再接；1930s fold 带 h=975（reuses_phone），套用 975/853 会算错，同样除外。
2. **量测方法（分层，不逐帽手工量）**：(i) shape 每机一个值写死（1920s `circle`，其余三机 `rounded-rect`），不用量测；(ii) w／h 从现有 x／y 网格推导（w：同行邻帽中心距 − 横向间隙；h：同列邻帽中心距 − 纵向间隙；两向间隙每机取字母键实测尺寸与中心距之差各标定一次），推导值每机抽样与照片比对（每机每行抽 1 帽，行首帽；另抽全部宽键），偏差 >2vp 改用照片量测值；(iii) 只对手工量测三处：宽键、空格条圆角 r、1950s 帽高。量测方法要点：亮度阈值＋以 keymap 帽心为种子取单帽包围盒＋x 间距交叉核对。量测取**顶面**（可视顶面，1950s 侧壁不计；理由：侧壁是另一平面，黑层只应落在顶面）。phone／fold 两带分别量测（1930s 除外，恒用 phone 带）。
3. **渲染按 shape 分支**（`PhotoKeybed.ets`，与现有圆叠加层同位置、同黑 0.30、同叠字下沉 2vp）：
   - `circle`：正圆，直径＝宽（1920s 40.4vp，比现有 43.7vp 小约 8%——这是修正的一部分，burst 帧按下前后对比即验收，见 §3.4）。
   - `rounded-rect`：圆角矩形，w×h，圆角 r（宽键与方帽走此分支；1930s 椭圆走此分支，r=h/2，验收以截图贴合为准，边缘偏差 ≤2vp，全分辨率量测）。
   - 空格条：矩形 w×h，圆角取空格的 `rRatio`（不再写死 8）。
   - 叠字容器尺寸随逐帽 w／h 走，不再写死 `hitRadius × 2`／`× 1.7`；定位改为 `cx − w/2`／`cy − h/2`。
4. **命中判定同步改**（`PhotoKeybed.hitAt` 与 `KeymapModel.hitTest`）：有 w／h 的帽按逐帽矩形判定（`|dx| ≤ w/2，|dy| ≤ h/2`，显示 vp）；重叠区取帽心最近者（与现行 `hitAt` 语义衔接）；无 w／h 的帽回落现有圆阈值。空格条命中矩形不变。
5. **不改项**：不改任何 label 文案与字号（长标签三选一仍待用户定夺）；`extra` 空白帽保持出反馈（空白帽也是物理帽）；叠字下沉保持 2vp，只改注释（现注释写 3vp，与代码不一致）；`hitRadius` 保留作回落默认值与行距派生，不删。
6. **双副本同步**：四机 keymap 两副本（`rawfile/keymap/`＋`assets/images/machines/`）同步改；新增 Node 单测校验四机 JSON 字段（有 wRatio／hRatio／rRatio／shape 或明确回落）与命中矩形逻辑（含重叠触点用例）。

### 3.3 备选（不采用，记档）

- B 按 label／行分类：不够——1960s Shift 三种宽度 label 区分不开；1950s Shift 与字母键同宽会误判。
- C 只改圆直径（调 `hitRadius` 系数）：圆永远套不上方帽和宽键；且 `hitRadius` 还管命中，改它牵连命中。
- D 进仓管线自动量测：可作量测手段，但本次量测有窗口截断／邻帽粘连／阈值噪声，全自动不可信，须人工核对。推导法（§3.2.2 (ii)）已纳入缺省，不属备选。

### 3.4 验收

- 四机各拍按下前后对比：字母键、宽键（1960s Backspace／Return／Shift）、空格条各至少一张（号段内）；叠加层边缘与帽缘贴合，目视无「四角露白、边缘溢黑」，叠加层覆盖宽键两端；1950s 单列一条：顶面贴合且侧壁不溢黑。

## §4 ② 退行音效

### 4.1 现状（查码证实）

- 退行唯一入口：功能行「退行」按钮（`FunctionRow.ets` L120）→ `Index.ets` L4399–4401 → `onBackLine()`（L3016–3080）。发声／震动类 21 处 `audioService.*` 调用点核查中（play* 14＋vibrate 7；另有生命周期／配置类 10 处），`onBackLine()` 区间内为 0 处；全仓 `onBackLine` 只有这一处定义、一处调用。退行全程静音，也无震动。
- 对照：删除在 `onDelete()` 动作开始即播 `playBackspace()`＋震动；换行在 `onNewline()` t=700 字车回位同帧播 `playCarriageReset()`＋震动。
- 退行时序：t=0 纸下移一行（300ms EaseInOut）＋字车滑到上一行末（250ms FastOutSlowIn）；t=270ms 清 `backBusy`、`animateArch(200)`、排队字回流（排队字＝落字队列里等待落字的字，打字速度超过落字动画时入队）；可见动作约 470ms。
- 包内没有专为退行切的声音。候选：`carriage-reset-01.ogg`（语义最贴——退行是换行的逆动作，同一套滑架机械反向运动；代价：与换行同音无法区分、音长 1.14–2.68s 超动作窗口、占受保护的复位 1 路）；`key-alt-01.ogg`（时长最合 0.09–0.46s，但它是删除键的声音，共用易与删字混淆，且 1950s 包长达 0.464s 手感不一致）。

### 4.2 设计（缺省 D2：复用 carriage-reset，t=0 播，t≈470ms 停流）

1. `onBackLine()` 在守旗与首行判断之后（无动作的两条返回路径不播音）、动作开始处（t=0）调 `playCarriageReset()`＋`vibrate()`（20ms），播音后记一条 hilog 行，字面格式 `'backline sound at O=%{public}s paperTop=%{public}s'`（O＝退行前当前 carriageOffsetVp，paperTop＝paperTopVp；与换行 t=700 的 `newline choreo bell` 同格式族，不同字段），供验收取证。四包走现有 `packForMachine()` 映射，无需新增音频文件、无需改 `SoundRole`／`capFor()`／`buildBanks()`／切包脚本。
2. 挂音时刻选 t=0（删除先例：反馈与按键同步；退行的可闻事件——滑架滑动声——从 t=0 开始）。换行的 t=700「落位播」为备选，不采用（退行无 700ms 编排，落位时播会与 t=270 的回流落字音撞在一起）。
3. 拖尾处理：`carriage-reset-01` 音长 1.14–2.68s，超过退行动作窗口（约 470ms）。播出后在拱动画结束时（t≈470ms，可见动作结束）停掉该流——`AudioService` 新增公开方法 `stopRole(role: SoundRole): void`（内部用现有 private `stopAndForget`＋`streamRole` 停该角色最新流；`playCarriageReset` 仍返回 void，不改签名；`AudioEngine` 暴露接口不动，不列 `ui/AudioEngine.ets`），补单测；调用点：270ms 回调内链 `setTimeout(() => this.audioService.stopRole(SoundRole.CARRIAGE_RESET), 200)`，继承代际守卫（§18.6「本轮 setTimeout 只负责自己那一代」）；独立 470ms 定时器不采用（不受代际守卫保护，快速连续退行会停掉后一轮刚播出的流）；若实现发现定向停流超出 AudioService 单文件改动，退回接受拖尾，批报告写明。注意：`backBusy` 在 t=270ms 清除，与停流锚点 t≈470ms 是两回事（§4.1 已正确）。同音缺口升级为下批专属音的触发条件：若用户耳听确认退行与换行无法区分，即立项新切（见 §4.3）。
4. 另：`onBackLine()` 注释称「纸下移一行高 200ms」，实际 `recalcPaperHeight()` 是 300ms——顺手改注释以代码为准。另 `Index.ets` L189「换行 600ms 编排进行中」改为 700ms（换行编排实为 700ms，t0=450＋250）。

### 4.3 备选（不采用，记档）

- 新切专属退行音：须用户从 Freesound（免费音效库）下载实录素材（`assets/sounds/freesound/`）→ `tools/cut-sound-packs.py` 切包 → `SoundRole` 加 `BACKLINE`＋`playBackline()`＋`buildBanks()` 加分池分支 → 断言每包 19 改 20（19＝每包 19 个 ogg 文件） → 基线包 `pack/` 另走 v1 流程（基线包手工切包流程）。工作量大且须用户供素材；若用户日后要求退行与换行可区分，再立项，不在本批。

### 4.4 验收

## §8 ⑥ 导出重做

### 8.1 现状（查码证实）

- 导出页全仓只有一个挂载点（`Index.ets:4708`），只接当前 live 文档的 `docId`；两个入口（主页菜单、打字机汉堡菜单）都是同一篇。文档视图页、卷宗详情页、文档库列表都没有导出入口。
- **只导刚写过的纸**：一篇文档的落盘数据里只有当前这张纸的行；换纸即 `clear()`，旧纸内容连磁盘上都不剩；`DocMeta` 只剩 `sheetNo`／`sheetCount` 两个计数器。
- **只能导出一张**：PNG 只取前 12 行（与模板同源：`buildPngTemplate` 直渲同一模板，随 `EXPORT_BODY_LINES` 走，无独立上限；模板 12→13 后 PNG 自动跟随）；图文版 PDF 只 `getPage(0)`，全仓无加页调用；文字版 PDF 写到页底即停，超出的行丢弃并记 warn；连预览也只有 16 行。

6. 不改项：卷宗与文档的索引分离结构不动；回收站文档不进导出范围（语义未定，不在本批）。

### 8.3 导出页重做（缺省 D6）

1. **范围选择**（缺省**整篇**）：当前纸／整篇文档／整卷宗三档。整卷宗＝该卷宗内全部文档（按 `updatedAt` 倒序，与 `DocStore.list()` 一致）；整卷宗时格式限定 PDF／纯文本（PNG 置灰并注明「多页请用 PDF」）。范围缺省整篇 ⇒ 格式缺省 PDF（联动）；格式缺省恒为 PDF（范围切回当前纸时仍为 PDF，PNG 仍可选）。
2. **格式**（缺省 **PDF**）：图片／PDF／纯文本三档不变。PNG 仅「当前纸」可用；选整篇／整卷宗时 PNG 置灰。PDF 格式文案过期修正：「文本路径，可打印、可存档」→「图文版，可打印、可存档」。格式缺省改 PDF 的机制：`picked` 初值改为 1（`FORMATS[1]`，顺序 image/pdf/text）；`FORMATS` 顺序不动（格式行 UI 顺序不变）。范围切离「当前纸」时，若 `picked` 为 image（0）则强制回 PDF（picked＝1）；置灰＝禁用态（仍显示、不可点，点按无反应），不是隐藏。既有入口（主页菜单、打字机汉堡菜单）不置 exportTarget（保持缺省 ''），按优先级走当前 live 文档整篇；范围选择器初值取 `exportTarget.scope`，'' → 'doc'（整篇）。
3. **自定义区**（页面下方，格式行之下、双按钮之上，分两组）：
   - 内容组（缺省全开，与现行强制显示一致）：是否显示页码／标题／日期／机器框图／卷宗名。页码开时显示真实页码（§8.3 item 6）；日期开时显示**文档创建日期**（`createdAt`，不再用当天日期；**行为变更**：现行模板写当天日期，改后写 createdAt——createdAt 稳定，不受 `updatedAt` 影响（`updatedAt` 由 `DocModelCore` 在每次编辑时刷新，导出前 `prepareExport()` 调 `flushSave()` 落盘，故导出时 `updatedAt` 确为当天；`Index.ets` L3688 的 `updatedAt: Date.now()` 在 `newPaper` 里，不在 `flushSave()` 里））；卷宗名开时追加到日期行（"2026-11-12 · 卷宗名"，maxLines(1)，不新增版块）。关掉后的版式：关＝隐藏该块＋`templateLayout()` 按可见块重算 Y（上移重排，不留空洞）；卷宗名附在日期行——日期关＋卷宗名开 → 该行只显示「· 卷宗名」；日期开＋卷宗名关 → 只显示日期；两关 → 该行隐藏并重排。
   - 外观组（缺省全开＝跟随文档）：纸张／字体／墨色按文档出（纸张：`findPaper(meta.paper)`＋Index 的 `customPaperColor`／`customPaperTexture` 覆盖；字体：`CustomizeStore.fontFamily(machine)`；墨色：`findRibbon(ribbon).inkColor`，逐行）；关时按导出默认（现行写死的底色 `#f4ecd8`／纸面 `#eee4ce`、系统默认字体、墨色 `#2a231d`，`ExportTemplate.ets` 现行值）。

4. **预览**：预览跟随范围：当前纸 → 当前纸前 16 行（现行）；整篇 → 首纸前 16 行＋「共 n 纸」；整卷宗 → 文档清单（标题＋纸数）＋总页数。预览不跟随开关（开关效果在导出物上验收，批报告写明）。纸数公式：纸数 `＝ sheets.length + 1`（`sheets` 缺失时为 1，与 `sheetCount` 计数器无关）；整卷宗预览纸数取导出计划口径，不取计数器；总页数 `＝ Σ（每篇纸数）`。预览数据源：整篇首纸取 `sheets[0]`（`sheets` 缺失或空时回落当前纸 `d.lines`）；整卷宗清单取 `listByDossier(dossierId)` 的摘要 → 逐篇 `load(id)` 计纸数（`sheets.length + 1`），每篇一行「标题 · n 纸」，按 updatedAt 倒序拼接进同一预览 Text（不另起列表组件）；超 16 行时只取前 16 行，第 16 行改为「……共 m 篇」（m 为篇数）。刷新触发：`aboutToAppear` 入场算一次＋范围 @State（`range`，见 item 5）变化时重算 previewText；`previewOf` 保留读单纸，新增按范围分支的预览计算（内部复用 previewOf）。空态判定落点：`onBeforeExport` 改签名为 `(scope: string, dossierId: string) => boolean`，`prepareExport(scope, dossierId)` 内部分支（整篇判 sheets＋当前纸、整卷宗判卷宗内文档有无内容；归档纸沿用现行「去空白后有非空字符」口径）；`docId` 为空的 early return 只保留在 paper／doc 分支，dossier 分支先调 `listByDossier` 查卷宗内文档，不依赖 live `docId`（paper／doc 分支仍先 flushSave 再判）；当前纸空但卷宗有内容时不进 PHASE_EMPTY。
5. **入口**：卷宗详情页与文档视图页加导出入口——`DossierDetailPage` 新增 `onExport: (dossierId: string) => void`，`DocumentViewPage` 新增 `onExport: (docId: string) => void`；按钮落点：`DossierDetailPage.hdrRow()` 标题行右侧加「导出」按钮（文案「导出」，图标 AppIcon EXPORT（share），与「新建纸张」并列）；`DocumentViewPage` 底部操作行加「导出」按钮（与「加页」并列，文案「导出」，图标同款）。Index 新增 `@State exportTarget: { docId: string, dossierId: string, scope: string }`（scope 取值 `'paper' | 'doc' | 'dossier'`，缺省 `''`），新增 `onExportDoc(docId: string)`（置 exportTarget `{ docId, dossierId: '', scope: 'doc' }` 后 `pushPage('export')`）与 `onExportDossier(dossierId: string)`（置 `{ docId: '', dossierId, scope: 'dossier' }` 后 push；显式置 scope，不留空）；挂载点 `ExportPage` 改读 `this.exportTarget`。ExportPage 新增 `@Prop dossierId: string = ''` 与 `@Prop scope: string = ''`，挂载点传参写法：`ExportPage({ docId: this.exportTarget.docId, dossierId: this.exportTarget.dossierId, scope: this.exportTarget.scope, machineKind: this.machineKind, onBeforeExport: (scope, dossierId) => this.prepareExport(scope, dossierId), ... })`；ExportPage 新增 `@State range: string`（取值 'paper'|'doc'|'dossier'，初值取 this.scope，'' → 'doc'），范围选择器读写 this.range。优先级：docId 非空 → 该文档（scope＝target.scope 或缺省整篇）；仅 dossierId 非空 → 整卷宗；两者皆空 → 当前 live 文档整篇。
6. **页码**：全部导出物页码一律为导出内相对编号「第 n 页／共 m 页」（n＝该页在导出物内的位置；当前纸 1/1；整篇每纸一页；整卷宗跨文档连续页码）。纸头 `sheetNo / sheetCount` 是另一套口径，导出物不采用；旧文档升级后的不一致是已知取舍（见 §8.2.3），导出物自洽为准。文字版抬头同理，字面格式为 `dateText + '  ·  n / m'`（与图文版「第 n 页／共 m 页」同口径、不同字面）。
7. **TXT**：整篇／整卷宗＝一份 txt，纸间以 `--- 第 n / m 纸 ---` 分隔行，篇间以 `=== <标题> ===` 分隔。数据源为 `.txt`（§8.2.2 已含归档纸），`buildTxt` 不动。
8. **分层不动**：`ExportService` 只做「文档 → 字节」；选位置写盘归 `FileHelper`，分享归 `ShareService`，进度／结果态／临时文件清理归 `ExportPage`。回退链不变（模板失败 → 文字版；图片失败 → 抓预览快照）。文字版跟随页码／标题／日期／卷宗名（抬头同理）；外观组（纸张／字体／墨色）不进文字版（系统字体写死、墨色黑色，现行限制）。

### 8.4 多页 PDF 管线

1. 实施前先在 SDK 里确认 `PdfDocument` 加页方法，**并在批报告写明方法名**（现行代码只用过 `getPage(0)`，多页能力未验；方法名以 SDK 为准，稿内不现编）。
2. 图文版：按纸循环——每纸调一次 `createFromBuilder` 渲染 1080×1440 模板 PNG → 逐页 `addImageObject`（现行 API 名，`ExportService` L89）；每页重画抬头（机名＋标题＋日期＋页码）。数据流接口写死：`ExportPage.templateBuilder(sheet: SheetRenderInput)`，`SheetRenderInput = { lines: DocLine[], pageNo: number, pageTotal: number, machine: MachineKind, paper: PaperKind, font: PaperFont, ribbon: RibbonKind, title: string, dateText: string }`；`ExportTemplate` 新增 `@Prop sheetLines: DocLine[]`＋`@Prop pageNo/pageTotal`＋`@Prop paperBg/fontFamily/inkColor`＋内容组 `@Prop showPageNo/showTitle/showDate/showMachine/showDossier: boolean`（缺省 true）＋`@Prop dossierName: string`（缺省 ''），`bodyText()` 改读 `this.sheetLines`（有值时不再 `load(docId)`；单纸路径保留 docId 回落）；`buildPngTemplate` 签名不动，调用方以闭包把 sheet 绑进 builder（`() => this.templateBuilder(sheet)`，逐纸调一次）。`ExportPage` 新增 5 个 @State 开关（与模板 props 同名，缺省全 true）＋`@State dossierName`（入场时按生效 dossierId 经 DossierStore 读 `dossiers-index.json`、取 `Dossier.name`；查不到取 ''，该行只显示日期）。`templateLayout()` 改签名 `templateLayout(visible: TemplateVisibility)`，`TemplateVisibility = { showTitle: boolean; showMachine: boolean; showDate: boolean; showDossier: boolean; showPageNo: boolean }`；规则：隐藏的块不占高度，后续块依次上移（上移重排，不留空洞）；日期行当 showDate 与 showDossier 全关时隐藏；pageNoY 固定（页码只影响自身显示，不移动其它块）。每纸 `dateText` 取该纸所属文档 `meta.createdAt` 的格式化值（`todayText()` 泛化为按时间戳格式化，入参 timestamp、缺省当天）；整卷宗导出时各纸按所属文档分别取。模板正文行数 12→13（与平板 maxRows=13 对齐；`templateLayout()` 纯函数重算，`export-pixels` 单测版式断言同步 12→13）。临时文件随页数线性增长，`aboutToDisappear` 统一清理（现有机制）。大文档口径：超过 10 页时进度浮层常驻（<300ms 不显示的规则只覆盖小文档）；不设硬上限，批报告写明实测页数与耗时。
3. 文字版：按页高分页、每页重画抬头；写到页底即换页，不再丢弃超出的行。
4. **回退阶梯（两级，不设硬门槛）**：若 SDK 的 `PdfDocument` 支持加页，走多页 PDF；若不支持，整篇／整卷宗导出仅提供 TXT（当前纸 PDF／图片仍可用）。回退粒度：**整单**（与现行一致）——任一纸模板渲染失败 → 整个导出回退文字版（多页文字版，页码仍相对编号）；「图片失败 → 抓预览快照」只适用于单张当前纸 PNG，多纸时不适用（预览只含当前纸前 16 行，无第 k 纸快照可抓）。不设「每纸一个单页 PDF、连续保存」中间级：`FileHelper.saveBytes`（L131–136）走系统 picker 按文件弹，无目录级连续写盘能力，未证实的能力不写进阶梯。实施时在批报告写明走了哪一级、为什么，不以「API 不支持」为由停工。

## §12 风险与回滚

- **DocData 落盘变更**：`sheets` 为可选字段；旧版只读不丢、一存即丢；回滚期不得用旧版编辑含归档的文档，否则归档灭失（已知取舍）；不新增回滚开关，字段缺失即回落当前纸口径。
- **PDF 多页 API 未验**：`PdfDocument` 加页方法须实施前在 SDK 确认；不支持时回退两级（多页 PDF／仅 TXT），当前纸 PDF／图片仍可用，不以 API 不支持为由停工。
- **keymap 双副本漂移**：四机两副本同步改，Node 单测校验字段与命中逻辑（字段校验单测同时加载两副本，断言同一机型的逐帽字段一致）；漂移时单测先报。
- **七项并行回归面**：门图重拍覆盖 ①③ 的打字机页改动；④⑤⑥ 逐项截图＋文件核对；⑥ 模型验证先于 UI（§1.4）。
- **K=1.0 对照可能触发钳制**：§2.1 已述上限（滚筒位移上限 58.5vp）；实测停在上限附近即钳制生效，不是异常，修法按 §2.2 分支 1 走。
